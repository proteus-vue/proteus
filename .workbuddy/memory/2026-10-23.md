## 15:40 B1 完成：原生点击通路（提交 `a4f2ac1b`）· 判据 16 → 17 条

链路：`ObjC mouseDown` →（y 翻转成左上原点）→ `Rust extern "C"` 回调 → `app.emit("canvas-click")` → 前端 `listen`。

**三个技术要点**：
1. **坐标必须翻转**：AppKit 原点在**左下**，前端习惯**左上** ⇒ `g_click_cb(p.x, h - p.y, w, h)`。
   前端只按 `x/w` 百分比定位，不需要知道 AppKit 的坐标系。
2. **C 回调里拿 AppHandle 只能走静态**：`static APP: OnceLock<tauri::AppHandle>`，在 `setup` 里 `set`。
3. **不引 serde_json**：Cargo.toml 里只有 `serde`，Tauri 的 `emit` 只要 `Serialize` 就够
   ⇒ 定义 `struct CanvasClick {x,y,w,h}` + `#[derive(Clone, Serialize)]`。
   （第一版用了 `serde_json::json!` ⇒ `E0433: cannot find crate serde_json`，改 struct 后通过。）

**判据 ⑬**：从事件入口模拟 `(498,374,996,748)` ⇒ 标记落在 50%,50%、状态栏 `498,374`。
画布是原生视图 Playwright 点不到，只能从事件入口验 —— 但验的是**前端那半段真接线**（不是假通过）。

## 16:0x 设备画面等比适配 + 缩放（判据 20 条）

**修的是一个从 B2 就存在、一直没被发现的真 bug：画面被拉伸。**

- 原生视图 = 「`main` 减 20px」，而 blit 是**全屏三角形铺满视口** ⇒ 画面被拉成视口比例：
  Android 1280x720(1.78) 进 1.30 区域 ⇒ **纵向拉伸 37%**；iPhone 888x1920(0.46) ⇒ **横向 2.7 倍**。
- **为什么一直没发现**：`poc_dump` 读的是 **FBO（g_canvas 纹理）**，不是屏幕。dump 永远正确，
  而我之前所有"看图"的验证都是 dump ⇒ **只有人眼看窗口才看得出变形**。
  ⇒ 教训：**dump 证明的是"解码+合成对"，不能证明"上屏对"**，两者要分开取证。

**修法两层**：① HTML 让原生视图只占设备矩形（`.screen` = `stats.width/height` 比例）；
② 原生 `uFit` 做 contain 兜底（宁可黑边，绝不变形）+ `uFit<0` 直接 exit(2)（否则除零 ⇒ 全黑且不报错）。

**真机（假源）验证链**：日志从
`blit 等比兜底：视口 1.600 与画面 0.463 …占视口 29%x100%` →
`blit 等比：视口 0.462 == 画面 0.463 ⇒ 无黑边，像素 1:1`
⇒ 证明 HTML 确实把视图收成了设备比例。**打印改成"状态迁移时打"**（不是"前 N 次"）——
后者会在启动阶段用光额度，恰好看不到这个转折。

**判据 ⑮ 第一次跑就红，抓到真 bug**：`.stage` 是 flex，**flex item 默认 `flex-shrink:1`**
⇒ 放大时宽度被压回舞台宽、高度不压 ⇒ 横向压扁（误差 20%）。修法 `.screen{flex:0 0 auto}`。
肉眼 125% "好像没问题"，量一下才知道错了 —— 这就是这条判据存在的理由。

**已知边界**：缩放锚点在中心、**无拖拽平移**；屏幕保持直角（原生 NSView 不受 CSS `border-radius` 裁剪）。

## 16:1x 纠正 B1 的死路：输入改由 HTML pointer 提供 + 拖拽平移（判据 22 条）

**★这是今天第二个"判据绿但功能不可用"的坑，比代码 bug 更值得记。**

- B1 的前提是「画布叠在 HTML **之上**」⇒ HTML 收不到点击 ⇒ 做了原生 mouseDown 回调。
- 事实：`embed_view.m` 是 `addSubview:g_view positioned:NSWindowBelow relativeTo:nil`
  —— **在最下面**，WKWebView 铺满 contentView ⇒ `hitTest:` 先命中 webview ⇒
  **`mouseDown:` 一次都不触发**。
- 而判据 ⑬ 当时用 `window.__EMIT__` 从 **JS 事件入口** 注入 ⇒ **一直绿**。
- **自查问句（以后每次写判据都问）**：**「这个判据注入/伪造的那个东西，在真实运行时由谁产生？」**
  答不上来 ⇒ 判据在证明一段没人调用的代码能跑，**假绿**。
  （同一天两次：dump 证明了"合成对"不是"上屏对"；⑬ 证明了"接线对"不是"点得到"。）

**新增拖拽平移**：`transform:translate` + `rAF` 合并 IPC（pointermove 可达 120Hz，不合并就每帧发 IPC），
上限 = 屏幕比舞台大出的那一半；`⌘0` 归零。**pan 不持久化、zoom 持久化**（一次性手势 vs "看多大"的偏好）。

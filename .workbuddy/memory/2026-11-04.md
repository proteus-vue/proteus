## 决策 #1420 · 内存级诊断改用 tsserver（不再用 Volar server）
- ★★Volar 路线失败原因：`vue-language-server` **对 .ts 恒返回空**（实测 publishDiagnostics 推 []），
  对 .vue 只给模板/CSS 提示（一条 line-clamp）。因为 **script 块与 .ts 的类型检查在 tsserver 侧**
  （Volar 的 TS 特性靠 tsserver 插件，单独跑 server 拿不到）。
- 正确路线：**直接驱动 tsserver**（typescript 自带，零新增依赖）
  · `updateOpen.openFiles[].fileContent` = 内存文本（不落盘）
  · `syntacticDiagnosticsSync` + `semanticDiagnosticsSync` 主动拉取（不依赖 push）
  · ★`updateOpen.changedFiles` 只接受**文件名**、不能带内容 ⇒ 变更用 **close+open**
  · 实测：首次 ~3s（项目加载），之后毫秒级；改回正确代码立刻 0 条
  · 诊断期间文本又变 ⇒ 丢弃旧结果用最新文本重跑（否则错位）
- ★★关键前置：根 tsconfig 的 include **完全不含 packages/studio/ui**（24 项里 0 个 studio）
  ⇒ 任何"按项目"的检查都会返回空。新增 `packages/studio/ui/tsconfig.json`（给常驻服务），
  `tsconfig.diag.json` 留给 `tsc --watch`。
- 协议（Rust `diag_lsp_*` + `diag:update-file`、前端 `diagSync.ts`）**一行未改**，只换脚本内部数据源。
- .vue 边界：tsserver 不认 SFC ⇒ 实时需 `@vue/typescript-plugin` + tsconfig plugins；当前由保存后 <1s 的 watch 覆盖。
- 状态：门禁 68/68、类型 0；进程 diag-lsp + tsserver + vue-tsc --watch 各 1。未推送。

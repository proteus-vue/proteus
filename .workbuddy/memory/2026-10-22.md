   第一版只看 build.mjs ⇒ 差点把"证据在第二个入口"判成错标。改为扫**全部**入口。

## 决策 #1168：Studio PoC B1（窗口上屏）—— 顺手打回 A 的一个结论

**做了什么**：同一条解码→合成管线放进真实窗口（`NSWindow + NSOpenGLView`），把
**compose（上传+画进 FBO）/ blit（贴到 backbuffer）/ present（flushBuffer，含 vsync）** 三段分开记账。

**实测（三轮 30s，M1）**：30.03 fps · 间隔 p99 34.8/40.8/37.9ms · **合计 p50 1.39/1.15/2.00ms**
（33.3ms 预算的 **4%**）· 迟到 **0/903** · CPU **7–8.2%** ⇒ 四条判据全过，检查器叠加有 ~32ms 余量。

**★打回 A 的 P2**：A 报「渲染 3–9ms、判不了」，其实是 `glFinish` 的**墙钟同步等待** + 并发负载；
窗口路径靠双缓冲自然节流，compose 只有 **0.8–1.6ms**。已在 A 的 README 加「★更正」段
（**阈值口径不改，只更正解读**——推翻旧结论先改旧结论）。

**★测量坑（写进决策，防后人误读）**：**compose 与 present 的分界会漂移**（run1 present 0.40ms、
run2 5.55ms）——vsync 等待落在哪段取决于"这帧是否早于 vsync 就绪"。**只有合计跨轮可比**。

**边界**：这不是 Tauri——原生 NSView 承载；挂进 WKWebView 窗口是 B2 的独立风险（性能同源、挂载不同源）。

## 决策 #1170：Studio PoC B2（Tauri 2 承载）—— 核心形态成立

**做了什么**：最小 Tauri 2 应用（2.12.5）——窗口里 WKWebView 做 UI（透明 + HTML 十字线/面板），
原生 `NSOpenGLView`（复用 B1 管线）垫在 contentView 最底层，30fps 主线程调度。

**实测（三轮 22s）**：`attach rc=0` · `webview found=1 transparent=1` · **30.34 fps** · 迟到 **0%** ·
间隔 p99 **44.5/49.6/45.2ms** · **合计 p50 1.36–1.44ms** · CPU **8.1–8.8%** ⇒ R1–R4 全过。

**与 B1 对账**：单帧成本持平（都 ~1.4ms）；但**间隔 p99 +8ms**（vsync 对齐变松），余量从 13ms 缩到 4ms。

**★六条踩坑（都实测过，写进 README 了）**：
1. `setup()` 里配置窗口**还没建**（`get_webview_window` 返 None），此时遍历 labels 直接在 tao 的
   `did_finish_launching` 里 panic ⇒ abort，**`catch_unwind` 抓不到**；
2. `setup` 里直接 `run_on_main_thread` 同样 abort（事件循环没起）；
3. **后台线程碰窗口对象** ⇒ WKWebView 跨线程 ObjC 异常 ⇒ `Rust cannot catch foreign exceptions`；
4. **`ns_window()` 给的是 `NSWindow`（TaoWindow），不是 NSView** ⇒ `-[TaoWindow bounds]: unrecognized selector`；
5. ObjC 异常必须在 ObjC 侧 `@try/@catch` 兜住 —— **这是定位根因的关键**：先兜住拿到 NSException 文本，
   否则只看到无栈 abort；
6. `generate_context!` 要求图标存在且是 **RGBA** PNG。

**用户提到 github 现在挂了代理可通** —— 记录：本轮已改 ffmpeg 路线，不再需要 libmpv；
若将来要回到 mpv，`brew install mpv` 现在应该可行（此前三重阻碍里的网络一条已消除）。

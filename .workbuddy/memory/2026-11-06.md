## 决策 #1445 · F2 卡住/超时误报（首次项目加载 4.7s）
- 现象：`computed` 上按 F2 → 转圈一阵 → 「语言服务未返回结果」。
- ★取证：真 tsserver 同进程内 **第一个 rename 4722ms**，之后本地符号 8ms、依赖符号 `computed` **3ms**
  ⇒ 慢的是**首次项目加载**，不是"依赖扫描"；15s 超时把"正常但慢"误报成失败。
- 修：① `diag_rename` 超时 15s→**30s**，超时文案写清"首次需加载项目，请再按一次"；
  ② `hint.ts` 的 `showHint/hintAt` 加时长参数（`ms=0` = 常驻），F2 第一句就
  `hint('正在分析符号…', true)`（0.12s 可见）；完成/弹框/取消时 `hideHint()`；
  ③ tsserver 英文原因中文化（node_modules → 「不能重命名依赖（node_modules）里的符号」）。
- 验证：0.12s 显示分析中、1.5s 显示中文原因、可重命名时输入框出现且提示已收、Esc 清干净。
- eslint 0 / 类型 0 / 门禁 68 / tauri 30。已推送 e7df64c7。
- ★通用教训：**"操作后无反馈的等待"必须给常驻提示**——异步请求再快也可能有首次加载，
  用户看到的是"卡死"；提示文案要说**为什么慢**，不能只说"失败"。

## 决策 #1446 · F2 卡顿真根因：同步 command 在 UI 主线程（★重要）
- ★★**Tauri 2 的同步 `#[tauri::command]` 在 UI 主线程执行**；`lsp_call` 用 `recv_timeout` 阻塞
  ⇒ 首次 rename 4.7s 期间**整个窗口无响应、鼠标转圈，连 hint 都渲染不出来**。
  这解释了 #1445「加了提示还是卡」：提示要等主线程空闲才画。
- 项目内既有对照：`diag_tsc` / `diag_eslint` 一直是 `async fn` + `spawn_blocking`，从不卡；
  新加的 5 个命令（complete/definition/quickinfo/references/rename）沿用同步写法才引入问题。
- 修：宏 `define_blocking_cmd!` = `async fn` 包 `spawn_blocking`，**对外名字不变**；
  原实现改名 `*_blocking` 去属性。`git_status`（跑外部进程）一并改 async。
- 另加**后台预热**：打开文件 1.2s 后静默发一次 definition，把首次 4.7s 挪到用户没按键时。
- `check-tauri-handlers.mjs` 增加识别：`async fn` + `define_blocking_cmd!(name, …)`（覆盖 42 个）。
- ★**以后新增任何"会等回包/跑外部进程"的 command，必须 async + spawn_blocking**，
  否则 UI 冻结。判断口径：函数体里有 `recv_timeout` / `Command::output` / 大 IO 就要包。
- 自证判据：提示能否**立刻**出现（不阻塞才会即时渲染）。

## 决策 #1491 · 符号面板过滤 + 键盘导航（IDE 主线）
- 问题：真实 `bridge.ts` 有 **95 个符号**，面板只能滚 = 能看不能用。
- 做法：`q` → `matched`（name/kind 子串）→ 分组与扁平都基于它；
  `cursor` 在**扁平顺序**上走（与屏幕分组一致）；`Enter` 复用点击的 `go()`；
  过滤时副标题变 `匹配 M/N`。
- ★**打字即过滤，但绝不自动聚焦输入框**：面板可能是**悬停 380ms 自动开**的，
  那一刻用户手还在编辑器里打字，抢焦点会把输入打进面板。改成"按下可见字符才聚焦 + 写入"。
- ★★**判据抓到真 bug**：输入框 `@keydown` 与 `window` keydown **都处理 ↑↓**
  ⇒ 一次按键走两格（两下 ↓ 选中 `sym14` 而不是 `sym12`）。
  修法：`onKey` 里 `if (e.target === inputEl.value) return`（Esc 仍全局）。
  **这类"同一事件两处处理"不报错，只表现为手感发飘** —— 没有精确到行的判据，
  人只会觉得"有点怪"却说不出哪里不对。
- ㊿t 四条：条目 < 80 且全含该串 / 副标题「匹配 M/80」/ 两次 ↓ 后是 sym12 / 回车收起。
  **全部走真实键盘**（给 input 赋值只证明 v-model 通，证明不了快捷键）。
- 破坏性验证：`needle` 固定 `''` ⇒ 仅 ㊿t 红（`80 条 allMatch=false`、选中 `hasBridge`）。
- 判据：**89 绿 0 红**（基线 `--update-ids` 同步 89 条）。`SymbolPanel.vue` 401 行。
- 诚实边界：只做子串（`useAutoSave` 搜 `uas` 不命中）；无多选；过滤状态不记忆。

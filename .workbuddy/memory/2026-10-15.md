### ② 坐标修好后仍有四个结构性差距（本报告增量）

**G1 · 形变方向反了（最重要）**
- 当前实现（工作区版 `GlassMaterial.inflatedPillPath` + `sd_glass`）：轮廓点**向内**偏移（`q − n·inf`，内陷凹口）。
  依据是 #969 对 18:53 单帧的判读「iOS 按下表面凹进去」。
- **双帧差分（最强证据，10-14 17:49 取证）否定内陷**：按下后联合剪影**向外**鼓——条底缘 +30px（1874→1904）、
  顶缘 −8px（1728→1720），以触点 ±120px 平滑衰减；本论 iOS 图复测同样单调外鼓、翼部无下凹。
- #969 把「**内容内流**」误读成「**轮廓内陷**」：凹进去的是**背景采样**（内容被吸向透镜 −12px），
  鼓出来的是**玻璃轮廓**。两者方向相反、同时存在，这正是"液态"感的配方。
- ⇒ 建议：剪影 = 透镜充气 + 外凸并集；内容 = 内流。当前"每盒各打一个高斯凹口"会得到条上两个坑——
  与所有测量相反， rebuild 后大概率"还是不对"。

**G2 · 两 pass 独立裁剪表达不了并集（"还是原来的边"的连续性出不来）**
- 条与胶囊是两个独立绘制 pass、各自 `clipPath`。iOS 的"边被挤压但仍连续"来自 **smooth-min 并集的颈部**
  （metaball 融合带）：条的边在透镜旁**连续地**离开原位、流入透镜弧。
- 独立裁剪只能得到两条各自变形的轮廓，交界处必然交叉/留缝，做不出颈部。
- ⇒ 方向：宿主几何层把「条路径 + 充气透镜路径」做**一次 union**（Android `Path.op(UNION)` 只是硬并，
  无颈部；要颈部需按 SDF smooth-min 采样生成联合路径，或接受硬并 + 透镜弧盖住交界），**一次裁剪**。

**G3 · 光学不随剪影形变（形变"读"不出来）**
- shader 里 `d`/`e`/法线/位移一律用**未形变轮廓**（#968 有意冻结），`press_rim` 又只给胶囊（overlay 门控）
  ⇒ 条被宿主裁剪撑出的形变区**没有任何贴着新轮廓的亮环/镜面** ⇒ 形变在多数背景上看不见。
- iOS 的挤压边之所以"明显还是原来的边"，靠的是**连续亮边跟着形变走**。
- ⇒ 方向：亮环（及色散）要沿**联合形变轮廓**生成，且条也需要（不是只给胶囊）。

**G4 · #968「内容零位移」与 #966「面纱不随 press」与双帧证据不符（事实订正）**
- 双帧实测：按下时背景内容**整体向透镜内流 −12px**（不是挤压式非均匀位移）、
  整条面纱变薄（透出结构 σ +46%）。
- 用户否定的是旧 `push` 的**挤压**（内容被非均匀压缩），不是**平滑低频内流**；完全冻结会丢"液态流动"感。
- ⇒ 方向：内容采样做**低幅度、低频、朝触点**的平移式位移（函数空间光滑，不产生压缩感）。

### ③ 建议的按压模型（四件套，对齐 iOS）
1. **形状**：触点透镜充气（垂直 ~1.6x）+ 与条 smooth-min 并集（宿主生成联合路径，一次裁剪）——得"边被挤压"的连续颈部。
2. **亮环/色散**：沿**联合轮廓**一圈镜面亮环 + RGB 分裂（±1-2px），条与透镜同待遇。
3. **内容**：朝触点的低频内流（峰 ~10-15px，展布 ~±120px），无挤压项；面纱 α 随 press 适度降（透出 +46% 量级）。
4. **动效**：弹簧驱动（过冲），前景内容 1.2x（x>y squash 已知项）。

## ★按压结构订正（09:05 边缘分离取证，推翻昨天"smooth-min 并集+颈部"结论）

**用户提问**：「外凸的是胶囊玻璃还是下面的玻璃条？我视觉上看下面的玻璃条的两边是向内走的」

### 真实结构（双场景确认：17:45 浅底 + 18:53 深底）

1. **外凸的是胶囊玻璃（透镜）**：充气膨胀，向上鼓出 ~35px（18:53 图顶边 1692 vs 翼部 1727）、
   向下 ~20px，上下端带 RGB 色散环；左右两端在条内部收窄（椭圆端部）。
2. **玻璃条的上下两条边：保持原位、平直贯穿** —— 增强对比图实证：边线（镜面高光）
   在透镜覆盖区**依然连续可见**（透镜半透明，边线透见）。双帧翼部仅 ±2-4px 整体外扩。
3. **两者是叠加/穿越关系，不是 metaball 融合**：透镜椭圆轮廓完整（穿越条边），
   条边线完整（穿过透镜）。**无颈部、无 smooth-min**。
4. **"挤压感"的真实来源**：透镜鼓出 + 条边不动的**对比**——参照物鼓出去，原位条边
   相对显得"凹"；配合透镜左右端收窄，整体读作"玻璃被从中间挤出"。
   用户「还是原来的边 + 被挤压了」两个观察同时成立，机制即此。

- 昨天日志「条底缘在按压点下凸 ~30px（1874→1904）」—— 测的是**透镜鼓包的底端**，
  不是条的边。条的底边只整体外扩 2-3px。

  保持连续，是**两个独立渲染层的叠加**，无融合颈部。
- ⇒ **#969「轮廓向内凹口（内陷）」方向错误**：iOS 条边无任何内陷（平直贯穿实证）。
  内陷实现会在条上凹出两个坑，与 iOS 完全相反。

### 对我们实现的映射（★移交并发会话裁决，本会话不落代码）

1. **条的几何按压时不动**（既不外凸也不内陷，最多 ±2-3px 整体外扩）——

## 「是不是没做离屏硬件管线才做不出通透玻璃」——13:49 取证答复

**素材**：#973/#975 构建的真机截图（绿底，`ours-1349/`）。存证：src.jpg、crop-2x.png、crop-stretched.png、
compare.png、a1-a4.py。

### 结论：不是管线单点原因。**透镜的光学签名做反了。**

**① 内容采样已通，但「条边穿过胶囊」是★手画的，不是光学透射（★14:03 用户当庭更正，原结论作废）**
- 实测：胶囊内 x450 顶缘 y2169-2170 亮线 222（邻域 166）、底缘 y2337-2338 亮线 231-235（邻域 ~195）。
- **该亮线来自 `#973` 宿主手画描边**（`ProteusHostView.java:3551-3557`：把外层玻璃盒轮廓以
  `argb(150,255,255,255)` 描边画进 `glassLayer`，胶囊再采样它）——是"画上去的近似"，
  **不是透过玻璃看到下面那层玻璃**。⇒ 我们**至今没有任何"玻璃看玻璃"的光学透射能力**。
- 真正的部分：透镜内部**内容**可见度大涨（std 6.44→12.59、行梯度 249→398，面纱退场 #972 生效）
  ——内容是真采样，边线是假描边。
- ⇒ 这一项**正是缺离屏/硬件管线的直接后果**：iOS 每层 CABackdropLayer 由**合成器**采样"它下方
  已合成的画面"（含其它玻璃层的真实光学结果：镜面边、霜、折射）；我们只能在 CPU 侧把"应该看到的
  元素"手画进采样图，静态像、一动就露馅（线宽/位置/粗细固定，不随透镜光学变形，也不会被二次折射）。

**② 真正反了的：iOS 透镜比条更"柔"，我们比条更"锐"**
- iOS 参照（press3-ios-2x，同口径 y260-610）：透镜内 std 13.55 / 条内 31.76 ⇒ **0.43×（更柔）**；
  行梯度 0.70 vs 2.79。
- 我们（ours-1349）：透镜内 std 12.59 / 条内 6.44 ⇒ **1.95×（更锐）**。
- ⇒ iOS 的"通透" = 内容被**放大 + 轻模糊 + 位移**（高频压掉、低频保留、位置移动）；
  我们的"通透" = **面纱一关、原始高频直透** ⇒ 读作"挖了个洞/贴了张清晰底图"，不是凸透镜。

**③ 待办（不需要等管线）**
1. 透镜内部**放大折射采样**（iOS 凸模式 ref_length/ref_height>1）：现位移只在极边缘 (1-e)³，内部零位移零放大。
2. 透镜内部**自身轻度低通**（不是面纱、也不是全局降采样位图）。
3. 亮环收窄：实测竖边亮脊 **~14px 全分辨率软带**（峰值 253 vs 外 150，+103 但对比较散）；iOS 是 1-2px 锐脊。

**④ 管线的真实限制（诚实边界，属进阶项）**
- Android AGSL RuntimeShader **无 backdrop 语义** + 本设备**忽略 shader 返回 alpha** ⇒ 玻璃层不能真半透明
  叠加，只能"重画替换"⇒ 多层叠加只能靠宿主软件 layer 模拟（#973 已做，代价=每帧 CPU 重画+位图）。
- 采样源是**一次性全局降采样位图**（DIV=2 + 4× 降采样近似高斯）⇒ 所有玻璃层共享同一份已模糊的图；
  第二层（胶囊）采的是第一层模糊后的结果，**高频已不可逆丢一次**——iOS 是每层 CABackdropLayer
  独立实时采样 + 独立模糊/色散 + 真 alpha 叠加。**这一条确实只有离屏/硬件管线（每层独立 FBO 或
  合成器采样）才能彻底解决**。
- ⇒ 一句话：**"通透"的观感本体（放大折射+轻模糊+锐亮环）现在就能做；离屏管线解决的是"多层独立实时
  采样+真 alpha 叠加+每层独立模糊/色散"，是第二层的事。先把透镜做成凸透镜，再谈管线。**

## 「安卓能做离屏管线吗」——14:08 API 查证结论（可行，有官方路径）

**★系统不给 backdrop-filter（AGSL 是 Canvas/RenderNode 绘制管线的一部分，无"采样背后"语义），
但我们可以自己做——宿主是自绘层树（drawCmds），等价于 Flutter 拥有整棵层树，不需要系统施舍。**

**官方离屏路径（纯 GPU，零 CPU 回读）**（developer.android.com「从 RenderScript 迁移」官方示例）：
```
ImageReader.newInstance(w,h,PixelFormat.RGBA_8888, 2,
    HardwareBuffer.USAGE_GPU_SAMPLED_IMAGE | USAGE_GPU_COLOR_OUTPUT)   // API 29+
HardwareRenderer() (API29) .setSurface(imageReader.surface) .setContentRoot(renderNode)
renderNode.beginRecording() → 录内容(+玻璃 pass) → endRecording()
hardwareRenderer.createRenderRequest().setWaitForPresent(true).syncAndDraw()
image = imageReader.acquireNextImage() → hardwareBuffer → Bitmap.wrapHardwareBuffer(hb)  // API 29+
→ new BitmapShader(hwBitmap) → RuntimeShader.setInputBuffer("backdrop_tex", bs)          // API 33+
```
- `setInputBuffer` 与 `setInputShader`（API 33）区别：**前者直接从位图缓冲采样，不做色彩空间转换/
  alpha 预乘** ⇒ 正是玻璃采样要的 raw 语义。
- 现状对照：`GlassMaterial.java:158-160` 已是 `BitmapShader(glassBackdrop)` + `setInputShader`
  （`glassBackdrop` = **软件** drawCmds 重画 + 4× 降采样近似高斯）。

**多层玻璃 = 每层一个离屏 pass**（第 N 层采样第 N-1 层输出）⇒ 真"玻璃看玻璃"，可替掉 #973 手画描边。
**每层可挂 `RenderEffect.createBlurEffect`（API 31）做真 GPU 高斯模糊** ⇒ 替掉"降采样近似"，且每层
模糊半径独立（对齐 iOS 每层独立）。
**alpha**：逐像素 alpha 被设备忽略，但**整层合成**（`drawBitmap(layer, alphaPaint)`）可行 ⇒ 离屏顺带
解决真半透明叠加。

**门槛与风险**（真机前必读）
- 硬门槛 API 33（`RuntimeShader`/`setInputBuffer`/`setInputShader`）；`GlassMaterial:33` 当前门是
  API 31（S），偏低——真跑 `setInputShader` 需 33。
- 官方警告：ImageReader 等自定义 consumer **必须及时消费**，否则**卡死共享 render thread**（波及所有
  HardwareRenderer 实例）。maxImages≥2 轮转。
- hardware bitmap **不可变**（不能用 Canvas 画它）⇒ 一切合成必须在 RenderNode 录制内完成（我们能做到）。
- 成本：每帧 N 次 offscreen pass + N 次 acquire；须按层缓存（层内容未变不重画，对标 iOS lumaUpdateRate）。
- 必须保留现有软件路径作 API<33 / 离屏失败回退（玻璃方案铁律 3：绝不白屏黑块）。
- iOS 侧更简单：已有 Metal 自绘（`VaporRenderHost`），离屏 MTLTexture 采样无障碍；鸿蒙同 Android 软件路径。

**优先级**：① 先修 shader 配方（放大折射+轻模糊+锐亮环，不依赖管线，收益最大）
② 再上离屏管线（替掉手画描边 + 真 alpha + 每层独立模糊）。

## 「拖动时水滴流动」安卓宿主实现方案（14:30，只读调研，未落码）

**iOS 机制**：形变不是补间动画，而是**速度 → SDF 场变换**（各向异性缩放 + 位移 + 与邻域 smooth-union），
CASDFLayer 存的是 SDF 纹理（R=距离、G/B=法线）⇒ **形状变了法线自动跟着变，光学天然一致**；
位置由欠阻尼弹簧驱动（滞后 + 轻过冲）。

**我们现状的三处硬缺口（代码实证）**
1. **形状只有缩放**：`ProteusHostView:3665` clip = `addRoundRect(RectF(bx,by,bx+bw,by+bh), radius)`；
   按压只能改 `bx/by/bw/bh`（#963/#971 的 sx/sy），**没有任何非对称/各向异性形变能力**。
2. **无速度、无弹簧**：`onDraw:3157-3166` 只做 `glassPress += (target-press)*0.28` 的一阶 lerp
   ⇒ 无滞后、无过冲、无味。
3. **拖出即丢**：`onTouchEvent:2543` MOVE 重做 `glassInteractHit`（命中要求落在盒内）
   ⇒ 手指移出条范围后触点冻结，没有拖尾的余地。

**实现规格（四层，L0→L4 递进）**
- **L0 状态量**：DOWN 锁定节点（手势期不再重命中，同 `gestureTarget` 语义）；MOVE 记 (x,y,t)
  ⇒ VelocityTracker 或自算 v；弹簧：二阶 ODE `x'' = -k(x-target) - c·x'`
  （或 AndroidX `SpringForce`，dampingRatio ≈ 0.6~0.75 欠阻尼）。
- **L1 形状**：clip 从 `addRoundRect` 换成 **N=16~24 采样点的闭合贝塞尔 blob**，
  半径按方向调制 `r(θ) = r0·(1 + s·cos²(θ−φ) − q·sin²(θ−φ))`（φ=速度方向、s=stretch、q=squash），
  保面积约束 `s ≈ q`；Catmull-Rom → `cubicTo` 闭合。
- **L2 水滴感**：① 位置弹簧滞后（不是刚性跟随）；② **拖尾 = 主 blob + 1~2 个衰减小 blob，
  分离距离 ∝ |v|**，渲染时用 metaball `smin`（Path 侧用 Union + 颈部二次贝塞尔近似即可，
  不必真 SDF）；③ 松手：弹簧回归 + 轻过冲。
- **L3 光学同源（★关键，否则形状动了里面没动 = 假）**：`glass.wgsl` 的 `sd_round_rect(p,hs,r)`
  是**写死的圆角矩形**，位移场与亮环全基于它的 `sd` ⇒ 必须把形变参数
  （中心偏移 Δc、φ、stretch、squash、tail）作为 uniform 传进去，让 shader 用**与 Path 同一套公式**
  算距离/法线。这是本仓 SSOT 纪律的硬要求：形状与光学必须同源，否则必然脱节。
  另加 `vel` uniform ⇒ 折射/色散强度随速度增强（iOS 快拖时内容被拉扯更明显）。
- **L4 帧驱动与成本**：沿用现有 `onDraw` 自持模式（拖动期 `postInvalidateOnAnimation`，
  照抄 `flingActive` 分支）；新增成本仅几十次 `cubicTo`（微秒级）⇒ **不需要离屏管线**。
  拖动期建议临时提高采样源更新频率 / 降采样倍率降到 1（见下）。

**诚实边界（安卓做不到的部分）**
- 采样源是**上一帧捕获的降采样位图**（`captureGlassBackdrop`）⇒ 快拖时**形状已变、内容位移慢半拍**
  （iOS 是同帧合成器采样）。缓解：拖动中 div→1、跳过降采样。
- AGSL 无 backdrop 语义、逐像素 alpha 被设备忽略（既有结论）⇒ 拖尾与条的重叠区仍是"重画替换"。

**顺序建议**：L0+L1（形状动起来，零依赖）→ L2（水滴感）→ L3（光学同源，最难但决定真假）
→ 再谈离屏管线。

4. **★包围盒未含"按下放大后的胶囊"**：`captureGlassBackdrop` 的并集盒用的是**未放大**的 `c.x/c.w`，

   ⇒ 要真透，必须走"整层 alpha 合成"（离屏层 + `drawBitmap(layer, paint.setAlpha(...))`），

## ★面纱机制订正（15:15，用户洞察 + 4 点数值验证）：**α 恒定、霜色两档**，不是「α 随 bg 变」

**用户洞察**：iOS 液态玻璃可能没那么复杂——只有**白色霜 / 暗色霜**的差异，采样只判断深底/浅底；
深底=通透、浅底=白霜。之前（#943/#949/#977）我们把「α 随 bg_lum 变 + 霜色恒白」做复杂了。

**数值验证（用 #926 数据集 4 个实测点：bg→glass = 46→90 · 53→92 · 91→114 · 240→238）**

| 模型 | 结果 |
|---|---|
| A 旧模型（`V=255` 恒白，α 随 bg 反解） | α = 0.211 / 0.193 / 0.140 / **−0.133（浅底负数=不可能）** ⇒ **自相矛盾** |
| B 新模型（α 恒定，V 分档） | 联立 bg46/bg91 ⇒ **α=0.467 · V_dark=140.3**；残差 **0.0 / −1.7 / 0.0**（bg53 为留出点，预测 93.7 vs 实测 92）；亮区反解 **V_light=235.7** |
| 线性模型 #926（0.777·bg+49.7） | 残差 +4.5 / +1.1 / **−6.4** / +1.8 ⇒ 明显更差 |

⇒ **新模型 `glass = 0.533·bg + 0.467·V`，V = 140（暗霜·中灰）/ 236（亮霜·近白）**，4 点几乎零残差。

**为什么用户会读作「深底通透 / 浅底白霜」**：对比保留**两者相同（53%）**，变的是**面本身的明暗**——
暗底上面是 90（暗面）⇒ 读作"透明玻璃"；浅底上面是 238（白面）⇒ 读作"白霜"。**是面明暗的观感，不是通透度差异。**

**机制层证据（独立吻合）**：`CABackdropLayer` 的 `tracksLuma / lumaSubrect / allowsFilteredLuma /
lumaUpdateRate` = **区域级 luma 统计 + 限速更新** ⇒ 本就是"低频、区域、二态决策"，不是逐像素连续函数；
HIG 原文「flip from light to dark based on the background」。⇒ 用户判断在机制层面成立。

**★冲突（必须重测，别照抄 α=0.467）**：#949 的另一组真值（深底 L80 / 背景 56）与新模型冲突——
新模型预测 bg56 ⇒ 95（残差 +15），而旧模型（α=0.09,V=255）预测 74 ✓。⇒ **两组历史数据互相矛盾，
现有样本不足以唯一确定 (α, V)**。需一次受控重测：同一张 iOS 截图内取 ≥6 个配对点（面内 vs 紧邻面外
同一内容），覆盖 bg 40→250，拟合两段的 (α, V)，判据 = **暗区各点能否共用同一个 V**。

**若验证通过，wgsl 改法（#943/#949/#977 三处合并为两行）**：
```wgsl
let VEIL_A = mix(0.47, 0.47 * 0.06, pr_ov);                 // α 恒定（按下仍退场，守 #981）
let veil_t = smoothstep(0.42, 0.62, u.bg_lum);              // 软阈值（宿主侧补滞后，防滚动闪）
let VEIL_V = mix(0.55, 0.925, veil_t);                      // 暗霜 140/255 · 亮霜 236/255
```
（现行为 `veil_base = mix(0.09,0.55,veil_t)` 驱动 **α**、`VEIL_V=1.0` 恒白 ⇒ 方向反了。）

**边界**：本订正只适用于**面纱/明暗自适应这一层**；折射位移场、SDF 法线、边缘高光/色散、luma 限速与滞后
仍然成立，不因本条推翻。

## 2026-10-15 16:30 白底场景对决：iOS vs 我们（同场景 App Store 底栏）+「内环折射带」证实

### ① 白底下「没有玻璃感」的量化根因（用户问：场景都调一致了为什么还是不行）

### ③ 我们的位移场为什么看不见
`(1-e)³` 把位移压在极边缘且幅度小，采样的又是已 4× 降采样的糊图 ⇒

⇒ 修序：先降模糊/保结构（采样源不降采样或更小半径）→ 再放大位移幅度与带宽 → 亮暗脊对 → 端帽色散。

两者面亮度几乎一样 ⇒ **面亮度不是差距来源，差距全在内容透射质量与边缘光学**。

### ⑤ 「获取按钮灰底没被折射、只有蓝字折射」——机制：全采样+对比度门控（非选择性采样）
用户观察：iOS 条下滚过的获取按钮，灰底无折射感、蓝字明显折射。取证（a7/a8.py）：
- 分离前景后，条内上带 y2283-2304/x956-1169 找到**真·蓝字鬼影**（获取按钮行滚入条下）：
  lum 230 / chroma 58。
- 原件：蓝字 lum163 chroma137；灰底 238-239；白底 255。
- **验证链**：blur 稀释后蓝字≈lum215/chroma~100 → 面纱 0.533 透射 → 预测 lum≈225/chroma≈53，
  实测 230/58 ✓。灰底 Δ15 → 预测残差 8，实测 **9.5** ✓；蓝字 ΔL 对白面 18 + chroma 58 ⇒ 可见。
- **结论**：iOS 全采样全折射，无任何"选择性采样"。折射=位移，位移只在有对比度结构处可见：
  灰底位移前后同色（Δ8 读作平）⇒"没折射"；蓝字高对比+高饱和 ⇒ 位移/挤压/色散全可见。
  副产品：低对比内容自动融霜、高对比自动透出 ⇒ iOS 玻璃永远不显脏（免费的内容管理）。
- **对照我们**：同口径上带蓝像素 = **0**——我们的蓝字透射被 4× 降采样 blur + V=1.0/α0.55 白面纱
  双重抹杀（chroma 残留低于检测阈）。同一个获取按钮，iOS 透出蓝字，我们透出平白。
- 注意区分：此机制 ≠ excludingForeground（前景保护是画在玻璃上的内容）。

### ⑥ 「玻璃条下方区域也有采样处理」——证实，但不是条的绑定机制，是 iOS26 滚动边缘效应
存证：white-bg-1621/ios2-{a,b}.png（App Store 两个滚动位，887×1920）。
- **用户观察成立**：条底到屏底的窄带里内容确实被处理，且明暗随内容变化：
  B 窄带列均值随内容走（图标区 196 / 文字区 221-228 / 白底 251）✓
- **处理签名 = 渐进模糊 + 提亮淡出，且强度随"距屏底边缘"增加**：
  B 窄带上半（近条）gradY=3.92 → 下半（近屏底）gradY=2.05（渐糊）；
  亮度 232 → 243（向底缘渐亮=淡出）；A 窄带行均值 100 → 142 同样向底缘提亮。
  窄带文字 gradY 1.73 vs 列表原件 2.73（≈63%，轻糊但可读）。
- **机制判定**：这是 UIScrollEdgeEffect（iOS26 滚动边缘效应，soft=渐进模糊+淡出），
  作用于 scroll view 内容接近屏幕边缘时，**独立于液态玻璃条**——
  与玻璃条的区别：条是定界 capsule（锐利边缘线 + 三层折射带 + SDF），
  edge effect 是无边界渐进场（无边缘线、无折射位移，只有渐进模糊+淡出）。
  两者视觉同源（都是 backdrop 采样处理）⇒ 看起来像"条带出来的区域"。
- 对我们的启示：底栏场景要完整对标 iOS，除了玻璃条本身，
  还需要一个"屏底缘渐进模糊+淡出"层（无边缘、无折射、随距底缘距离 ramp）。

### 整合：iOS 液态玻璃完整机制清单（截至本次全部实测定稿）
1. **双层独立 backdrop**：条一层 + 选中胶囊一层，各自采样各自模糊，合成器叠加（非 metaball）。
2. **面纱两档明暗**（α≈0.47 恒定，V=140暗霜/236亮霜 随 bg_lum 二档）——决定"深底通透/浅底白霜"。
3. **边缘折射带**（贯通连续场，三层：1px暗缝+亮脊+缘内18-45px挤压带；上下缘对称成闭合内环）。
4. **折射=对比度门控**：全采样全折射，位移只在有对比结构处可见（灰底融霜/蓝字折射）。
5. **内容透射=大半径模糊**（条内对比残留 12-18%）+ 边缘带保细节（85-93%）。
6. **交互形变**：滑动 squash&stretch 1.43× + 临界阻尼弹簧（主体150ms/尾475ms，过冲<1px）+ 前景同形变。
7. **按压透镜**（前期 press3 素材）：按下胶囊膨胀成透镜、面纱退场通透化、放大折射。
8. **luma 自适应**：tracksLuma 区域亮度统计+限速，实时跟随背景明暗。
9. **色散**：端帽/边缘 RGB 通道错位 4-8px 彩虹边。
10. **滚动边缘效应**（UIScrollEdgeEffect，独立于条）：屏缘渐进模糊+淡出。
11. **前景保护**（excludingForeground）：玻璃上的内容不参与背板采样。

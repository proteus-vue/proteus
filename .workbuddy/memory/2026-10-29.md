## ★★真凶（#1376）：处理函数末尾残留的第二处 `term.value.write(d)`
- 症状：整段输出重复、echo 翻倍（p,w→ppw）、命令执行两次。
- 根因：多会话改造时把路由改成 `target.term.write(d)`，**旧的 `term.value.write(d)` 没删**，
  且它在 early-return 之后 ⇒ 每块输出写进网格两次。入口处的 seq/时间窗去重全部无效（两次写都在入口之后）。
- 定位手段（有效）：**网格取样日志** —— 前端每 10 块把 `term.text()` 末几行经 `term_write(src=diag)`
  打到 studio.log（不写 pty）。日志显示网格里已翻倍 ⇒ 排除投递层与渲染层。
- 教训：改事件处理函数要用「整函数替换 + 复核副作用次数」；同类 bug 的判据应是**计数断言**
  （写 N 块后网格文本长度 = 累积长度），而不是肉眼看画面。

## 压缩提交的正确流程（这次一次做对，未再误伤他人）
1. `git fetch` + **`git merge-base --is-ancestor origin/main HEAD`** 先判定：不是祖先 ⇒ **禁止** `reset --soft origin/main`。
2. `git branch -f backup/pre-squash-<HHMM> HEAD` 留后路。
3. **先 `git rebase origin/main`**（把我们的提交挪到最新远端之上），冲突数 0 再继续。
4. `git reset --soft origin/main` → `git diff --cached --name-only` 核对文件清单 +
   **`git diff --cached --diff-filter=D --name-only` 必须为 0**（没有删除他人文件）。
5. 提交（消息写进文件用 `-F`，避免 zsh 把 `**` 当通配）。
6. 重建产物 → 跑门禁 → `git push`（快进 `89901922..329504c4`），再核对他人的鸿蒙文件仍在。
- 结果：14 个提交压成 1 个，只含 7 个文件（studio 终端 + 门禁脚本 + 记忆），他人改动 0 删除。

## 决策 #1379 · 启动出窗口 7.4s → 1.5s
- 方法：先加 `[boot]` 分段打点（保留，仅 4 行），再改。
- 根因：`live_source::default_live_source()`（simctl 枚举 + boot 模拟器 + adb 探测，实测 4.5s）
  跑在 `tauri::Builder::build()` **之前** ⇒ 窗口创建被推后。
- 修：挪到 setup() 的后台线程；自动重连从 `sleep(900ms)` 改为 `wait_src_ready(12s)` 条件等待
  （仓规禁止盲等，也消除"source 未就绪就去连设备"的竞态）。
- 结果：webview 就绪 7438ms → **1479ms**；live source 仍在后台跑完（不影响首屏）。

## 决策 #1380 · 启动不再 auto-boot 模拟器
- 用户："启动模拟器不应该和 Studio 启动捆绑"。
- 旧行为（#1308）：上次设备是模拟器就 `start_simulator()`，Shutdown 也 boot。
- 改：启动路径只**复用已启动**的模拟器（`device::sim_is_booted`），否则跳过并提示"点设备列表"。
  自动重连的"唯一可用模拟器"兜底也要求 Booted；用户点击路径（`device::select`）不变。
- 验证：连 Simulator.app 一起退出 + `simctl shutdown all` ⇒ 启动前后 booted 数都是 0；
  live source 7.9s→4.5s；窗口 2.0s。

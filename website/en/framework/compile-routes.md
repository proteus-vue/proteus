# Route generation

The cross-target routing headache: Web is an SPA route table (history), the Mini Program is a page stack (`app.json` pages + tabBar) — two mental models, two configs. `gen-routes`'s answer is a **compile-time page table**: the page's `<route>` block is the single source of truth; scanning converges it into a single route tree, which then generates both targets' configs separately.

## Pipeline

```
<route> local declarations → scan + validate → nested tree → dual-target codegen
```

- **Scan**: the CLI recursively scans `pagesDir`; `<route>` blocks reuse `@vue/compiler-sfc` parsing (which naturally yields the file and line numbers)
- **Validation**: schema validation, path deduplication, nesting resolution (path prefixes auto-derived + explicit `parent` override)
- **Output** (every record carries a `loc`, traceable back to source):

| Target | Form | Output |
|---|---|---|
| Web | SPA route table | vue-router `RouteRecordRaw` code (lazy → `() => import()` code splitting, nested → recursive `children`) |
| Mini Program | Page stack | `app.json` page configuration (Skyline is an MPA: nested routes degrade to a flat list + `meta.__parent` keeps the parent chain; `meta.transition` → `routeType`) |

## Zero boilerplate

The `<route>` block is entirely optional: `path` / `name` are derived from the file location (`pages/user/profile.vue` → path `pages/user/profile`, name `user-profile`; `index.vue` collapses into the directory path). Pages without a block are still included, and meta is injected centrally from config.

## Skyline fields auto-generated

The fields Skyline needs require no manual configuration: `lazyCodeLoading` in `app.json` and `"renderer": "skyline"` in each page's `page.json` are both auto-generated by gen-routes.

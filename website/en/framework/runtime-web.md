# Web runtime

The Web runtime is simply **standard Vue 3 + standard Vite** — zero transformation, zero abstraction tax:

- `src/main.ts` is a standard entry: `createApp` + router + platform installation (`installWebPlatform` / `installFluidLayout`)
- `ref` is real Vue reactivity — no setData bridge, no batch window
- Vue devtools / HMR / per-route code-splitting all work natively
- The page route table is generated by gen-routes (`src/router/auto-routes.ts`) and carried by vue-router

## Platform installation (installWebPlatform)

`installWebPlatform(app)` from `@proteus-vue/web` does two things (the component layer and the wx API simulation layer are separate; here they are aggregated):

| Installation | What it does |
|---|---|
| `installBuiltInComponents(app)` | registers the framework's built-in components (proteus-*) |
| `installWxApi()` | injects the **wx API Web simulation** globally (the full `WxApi` interface) |

## The wx API Web simulation layer (the WxApi interface)

The compatibility surface for previewing existing Mini Program code (`wx.*` calls) on the Web — routing through PlatformAdapter + browser capabilities to align with Mini Program semantics:

| Category | Coverage | Implementation |
|---|---|---|
| Routing (full) | `navigateTo` / `redirectTo` / `reLaunch` / `switchTab` / `navigateBack` / `getCurrentPages` / `pageScrollTo` | proxies PlatformAdapter — history on the Web drives RouterView transitions; `pageScrollTo` → `window.scrollTo` |
| Storage (full) | `setStorageSync` / `getStorageSync` / `removeStorageSync` / `clearStorageSync` | localStorage + JSON serialization (aligned with Mini Program semantics) |
| System info (full) | `getSystemInfoSync` / `getDeviceInfo` | browser info |
| Interaction (full) | `showToast` / `hideToast` / `showLoading` / `hideLoading` / `showModal` / `showActionSheet` | custom DOM UI matching WeChat's behavior; `showModal` supports WeUI's three dialog variants (two-button / single-button / input-capable), with the return value aligned with the Mini Program's `{ confirm, cancel, errMsg }` |
| Network (partial) | `request` | a fetch wrapper |
| Business capabilities | `requestPayment` and others | no Web equivalent — fires the custom `proteusWebPay` hook or degrades with a warning |

## From the render-backend perspective

The Web render backend is **VueDom** (the `RenderBackend` SPI): nodeOps maps directly onto DOM operations, with event normalization (`onXxx` prop → `addEventListener`); a `documentLike` is injected (tests pass fake/happy-dom, the runtime uses the global document) — which is exactly what makes it the semantic reference for every backend (conformance measures against it).

## Side-by-side with the Mini Program runtime

| | Web runtime | Mini Program runtime |
|---|---|---|
| entry | `main.ts` (createApp) | `main.mp.ts` (app skeleton auto-generated) |
| reactivity | native Vue Proxy | ref → setData (16ms batch + deep diff) |
| routing | vue-router (history) | page stack (app.json pages) |
| styles | standard CSS | WXSS (px→rpx + scoped class-name suffix) |
| events | native event objects | `eventField` normalization (reads detail / target) |
| debugging | Vue devtools + HMR | WeChat DevTools + debug:mp decision chain |

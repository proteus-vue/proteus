# Internationalization (i18n)

Cross-end message catalog + ICU subset + **type-safe `t()`** (`@proteus-vue/i18n`). **Type safety without codegen**: an `as const` catalog + a MessageKey inferred via `keyof` — a mistyped key fails at compile time.

## Creation & the full API table

```ts
import { createI18n } from '@proteus-vue/i18n'

// as const declaration → keyof type safety (mirrors examples/locales — the en-US.json / zh-CN.json catalog files)
const catalogs = {
  'zh-CN': { 'home.title': '首页', 'count': '{n} 次' },
  'en-US': { 'home.title': 'Home', 'count': '{n} times' },
} as const

export const i18n = createI18n({ catalogs, defaultLocale: 'zh-CN' })
```

| API | Signature | Description |
|---|---|---|
| `i18n.locale` | `readonly string` | The current locale |
| `i18n.t(key, params?)` | `<K extends keyof M>(key: K, params?: FormatParams) => string` | **Type-safe translation**: the key must be one of the default catalog's keys; a missing message **falls back to the key itself** (visible in the i18n:check audit) |
| `i18n.setLocale(locale)` | `(locale: string) => void` | Switches locale (**unknown locales are ignored** — the audit can show it) |
| `i18n.dir()` | `() => 'ltr' or 'rtl'` | Language direction (RTL as a first-class citizen: prefix-matched against `rtlLocales`) |
| `i18n.onLocaleChange(cb)` | `(cb) => void` | Locale-change callback (the app persists the locale / applies dir to the root node) |

`CreateI18nOptions`: `catalogs` (locale → message catalog, as const) / `defaultLocale` (defaults to the first key of catalogs) / `rtlLocales` (defaults to `ar/he/fa/ur`).

## Interpolation (ICU subset)

`t('count', { n: 5 })` → `5 次` — the template placeholder `{n}` is rendered through `renderMessage`. Complex formats beyond the full ICU syntax are split into separate keys (honest boundary per i18n-plan).

## Directory conventions & example

`examples/locales/` is the concrete, on-disk form of the cross-end catalog:

```
locales/
├─ index.ts      # createI18n instance (app-side singleton, Pinia pattern)
├─ en-US.json    # English message catalog
└─ zh-CN.json    # Chinese message catalog
```

The example page `examples/pages/i18n-demo.vue`: switching the language → `t()` in the template re-renders immediately.

## Audit: `proteus i18n:check`

| Check surface | Description |
|---|---|
| Hardcoded copy detection | Flags bare strings in business source that don't go through `t()` |
| Catalog key comparison | Each locale's message keys are compared against the default catalog (missing keys / extra keys) |

In CI it joins the `proteus check` aggregate gate; directories without a catalog are skipped without blocking (the standalone command reports the error).

## Cross-end notes

- **MP artifact safety**: the `@proteus-vue/i18n` runtime has zero `??` / `?.` / spread / destructuring — the shared module `_proteus/i18n` compiles into the Mini Program artifact
- Locale persistence is wired up by the app itself (`setLocale` + `onLocaleChange` → platform storage); the framework doesn't bind to a particular storage shape

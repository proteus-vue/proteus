# Startup & update mechanism

The startup carriers and update mechanisms of each target are as follows (each target's rollout status is in the “Terminal rollout” table above).

### Mini Program target (mp-weixin)

```
npm run build:mp
  ├─ gen-routes        scans pages → app.json / page.json / auto-routes
  ├─ vue-tsc           type check
  └─ vite build        compiles each page's SFC → dist/mp-weixin/ four artifacts
                          │
WeChat DevTools import ──► app.js skeleton (auto-generated by the framework) ──► page Page() instantiation
```

- The `app.js` skeleton is assembled automatically at build time: app lifecycle registration + `getApp().__proteusProvides` global registry initialization
- Pages are injected on demand: under Skyline, `lazyCodeLoading` is written by gen-routes, so code for unvisited pages is never injected

### Web target (web)

```
npm run dev:web (Vite dev + HMR)    /    npm run build:web (vue-tsc + vite build)
        │
main.ts: createApp → installWebPlatform (built-in components + wx API simulation) → router → mount
```

A standard Vite SPA — no extra framework layer at startup.

## Update mechanism

- **Development**: `npm run dev:mp` provides Vite watch (gen-routes incremental); for day-to-day iteration prefer a direct `build:mp` + DevTools hot reload
- **Web**: standard Vite HMR (development) and static artifact replacement (deployment)
- **Mini Program review & release**: upload `dist/mp-weixin/` → submit for review → release, following the WeChat platform flow; the page table statically declared at compile time ensures every upload is a complete, auditable artifact

## Debug toolchain

| Tool | Purpose |
|---|---|
| `npm run debug:mp` | full-chain debug build (`PROTEUS_DEBUG=1`: `[proteus][stage]` logs + decision-chain files) |
| `npx proteus explain <file>` | single-file compile decision trace |
| `npx proteus rules` | the compiler rule catalog |

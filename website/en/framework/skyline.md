# Skyline & WebView

On the Mini Program side, Skyline is the next-generation native rendering engine (self-drawn, not WebView). Proteus is Skyline-first: **full-featured Web + Mini Program Skyline-first, with the WebView degradation only guaranteeing runnability**.

> **Target scope**: this page covers the dual rendering engines inside the **mp-weixin** target. Cross-target view: Web = vue-dom (DOM), App = native UIKit/Jetpack/ArkUI, Flutter = Widget — the same semantic model, with each target's own native engine; see [Ends & maturity](/docs/framework/ends-matrix) for the comparison.

## Skyline fields in the project (all auto-generated)

| Field | Location | Generated by |
|---|---|---|
| `lazyCodeLoading: "requiredComponents"` | `app.json` | gen-routes (written when the skyline switch is on) |
| `renderer: "skyline"` | each page's `page.json` (page-level declaration) | gen-routes writePageJsons |
| `rendererOptions.skyline.defaultDisplayBlock` | `app.json` | gen-routes (`skylineLayout` configurable) |
| `requiredComponents` | page.json | Skyline rendering prerequisite (validated by the WeChat platform) — auto-declared by gen-routes |

No hand configuration needed: the skyline switch lives in `proteus.config.ts`; gen-routes generates everything else per page.

## Structural differences between Skyline and WebView

| Dimension | Skyline | WebView |
|---|---|---|
| Route model | MPA (each page renders independently) | close to an SPA mental model |
| Nested pages | degrade to a flat list + `meta.__parent` keeps the parent chain | children nesting |
| Transitions | `meta.transition` → `routeType` (custom route + builder) | CSS transitions |

Proteus's gen-routes absorbs these differences at **compile time**: from the same `<route>` declaration, each target generates its own correct structure.

## Honest boundaries

- Verify Skyline capabilities with a **real AppID + a real device** (base library ≥ 2.29.2)
- The WebView degradation path **only guarantees runnability**, not a Skyline-level experience
- `transition` transitions rely on `wx.navigateTo({ routeType })` + a registered builder; page.json needs no declaration

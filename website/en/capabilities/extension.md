# useExtension

**What it does**: Load host-provided extensions/plugins.

**When to use it**: Host-injected extension points.

**End support & boundaries**: iOS forbids dynamic loading of third-party code (App Store policy); Android/HarmonyOS can implement it via a host-side registry.

> 技术标识：能力原语 C50 · `capability.extension` · 返回 `ExtensionAPI` · **Hook implemented** (per-end support in the table below)

useExtension: extension/plugin (G-21 extension point — host loadPlugin bridge; Err by default)

## Usage

```ts

if (res.ok) {
  console.log('extension returned:', res.data)
} else if (res.error.code.endsWith('.unsupported')) {
  // platform unsupported → degradation path
}
```

## Platform notes

### Mini Program (MP)

- **No plugin-loading API** — Mini Programs cannot load external code at runtime — a host extension shell (same-layer rendering / dynamic components) is required, see docs/proteus-platform-plan

### Web

- **Dynamic import()** — Loads ES modules at runtime (a real implementation); accepts module URLs only (relative/absolute/http(s)) — bare specifiers are rejected

### App (iOS / Android / Harmony)

- **Shell-loaded native modules (same mechanism as G-45)** — Apps can dynamically load native modules (Android DexClassLoader / iOS dynamic libraries) — the same mechanism as dev-host plugin loading · Planned: Available once the shell implements `extension.load`

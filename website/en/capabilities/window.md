# useWindow

**What it does**: Adjust window size or layering (split-screen, floating windows).

**When to use it**: Tablet split view, floating video.

**End support & boundaries**: App ends are full-screen single-window apps: size can be read but not changed programmatically (split view is system-controlled).

> 技术标识：能力原语 C74 · `capability.window` · 返回 `WindowAPI` · **Hook implemented** (per-end support in the table below)

useWindow: window size — setSize for PC (wx.setWindowSize; web has no standard → Err, window.resizeTo is popup-only)

## Usage

```ts
const win = useWindow() // synchronous handle — no await, no res.ok

if (win.ok) {
  await win.data.setSize(1280, 720) // resize on desktop (needs a large enough screen)
} else if (win.error.code === 'window.unsupported') {
  // non-desktop / no Web standard → degradation path
}
```

## Platform notes

### Mini Program (MP)

- **wx.setWindowSize (PC only)** — Only WeChat on PC supports setting the window size; mobile has no such API (honest Err)

### Web

- **Browser window sizing is restricted** — window.resizeTo only works on script-opened popups — regular tabs cannot resize (honest Err, never fake success)

### App (iOS / Android / Harmony)

- **Native window management (split view / foldable / desktop)** — iPad split view, foldable multi-window, desktop free resizing — the shell forwards native window APIs (iOS UIWindowScene / Android WindowManager) · Planned: Available once the shell implements `window.setSize`
- **Size-change notifications** — Size changes arrive via the app:resize event (no polling) — re-layout on split view / rotation · Related capabilities: [`useBackground`](/docs/capability/background)

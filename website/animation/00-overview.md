# Morpheus · 声明式动画引擎

把「会不会掉帧」变成**编译期问题**。

一句话声明演出；曲线求值与物理积分在 Rust 内核；布局动画几乎白送；转场直通系统渲染线程——不自绘，零主线程参与。

## 为什么需要它

主流方案把动画当成**运行时的连续任务**：每帧算、每帧写，掉不掉帧取决于设备与当前负载。Morpheus 换一个问法——**哪些部分可以在编译期就定下来？**

| 问题 | 传统做法 | Morpheus |
|---|---|---|
| 动画参数合法吗 | 运行时才发现（值非法 → 跳变 / 崩溃） | **编译期校验**（封闭集 + 7 类检查，非法即报错） |
| 会不会掉帧 | 靠调参和真机赌 | **合成属性编译期判定**（transform / opacity ⊆ 才走零参与路径） |
| 曲线在哪算 | JS 每帧求值 | **Rust 内核唯一实现**（宿主零曲线数学，三端不会分叉） |
| 布局动画成本 | 变更前后各读一次几何（贵） | 几何本就在内核——**快照与补间都在内核**，零跨边界查询 |
| 转场谁渲染 | 自绘 → 自建渲染线程 | **不自绘 → 直接用系统渲染线程** |

## 三个杀手锏

### ① 布局动画，几乎白送

传统 FLIP 需要在变更前后各读一次几何——在 VDOM 框架里这两次查询很贵。Morpheus 的几何**本来就在 Rust 排版核心里**：变更前后的快照都在内核完成，直接生成 `Δ → 0` 补间，零跨边界查询。

配合 `0.08ms` 全量重排，「列表项增删时其他项平滑让位」这类效果的成本几乎可以忽略。

### ② 转场零主线程参与

Morpheus **不自绘**，所以转场可以直接落在系统的渲染线程上（Android RenderThread / iOS CoreAnimation render server）：内核采样出关键帧，宿主提交**一次**平台动画，此后由系统自主插值。

> Flutter 自绘，所以被迫自建 raster thread。我们不自绘——系统的那套更成熟，而且免费。

### ③ 编译期拦截，零静默降级

合成属性集合（`transform` / `opacity`）在**编译期**判定：只有属性集落在该集合内，才允许走「提交一次、平台自主插值」的零参与路径；在转场里误改布局属性（`width` / `margin` 等）会**编译报错**，宿主侧也会**明确拒绝**——不会静默降级成"每帧重排"。

## 三层分工

```
声明层（@proteus-vue/animation）     ← 一句话写演出 / 编译期拦住错误
     ↓ 引擎指令（跨语言契约）
内核层（layout-core-rust/anim.rs）  ← 曲线/物理/窗口换算唯一实现，每帧零 JS 求值
     ↓ 每帧二进制通道（24B/条）或提交规格
宿主层（平台壳）                     ← 只做「翻译成平台 API」，零曲线数学
```

三层的**职责边界是硬约束**，逐条有机器判据守着：

- **曲线求值与物理积分只在 Rust**（TS 侧只有与内核 golden 对拍的镜像表）——否则就是"第 N 份手写副本"，端间必然静默分叉；
- **宿主只翻译平台 API**（iOS `CAKeyframeAnimation` / Android `ViewPropertyAnimator`），弹簧也用**内核离线采样**而非平台 spring（两套弹簧参数语义不同，混用会让两条路径观感分叉）；
- **动画绑定 Slot 身份**（不是 Node 身份）——长列表复用率 0.997 下，绑错身份 = "错误的项在做动画"。

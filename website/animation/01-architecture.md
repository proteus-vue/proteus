# 架构与边界

Morpheus 的架构只有一件事要做对：**把"连续量"关进一个笼子，让笼子外面的一切都变成可编译、可校验、可对拍的确定问题。**

## 三层分工（硬约束）

```
① 声明层   @proteus-vue/animation        「一句话写演出」+ 编译期校验
      ↓  引擎指令（跨语言契约：kind / curve 编号不得改）
② 内核层   layout-core-rust/src/anim.rs  曲线求值 / 物理积分 / 窗口换算 —— 唯一实现
      ↓  每帧二进制通道（24B/条） 或 提交规格（节点级采样）
③ 宿主层   iOS / Android 平台壳           翻译成平台 API —— 零曲线数学
```

**为什么必须这样分**：动画的连续性（每一帧的值）不可能在编译期算完；但**曲线的形状**、**参数的合法性**、**会不会触发重排**全部可以。分层的意义就是把可收敛的部分收敛掉，只在层与层之间传"最小的事实"——t=0.37s 时的具体数值**永不跨边界**。

## 职责铁律（逐条有判据）

| # | 铁律 | 违反后果 | 守它的判据 |
|---|---|---|---|
| 1 | 曲线求值与物理积分**只在 Rust** | 多份实现 → 端间观感静默分叉 | 跨语言 golden（TS ⇄ Rust 1e-5）+ `tests/anim-curve-golden.test.ts` |
| 2 | 宿主侧**零曲线数学** | "第 N 份手写副本" | 提交规格由内核**采样**下发（17 点/节点），宿主只翻译平台 API |
| 3 | 弹簧**离线采样**，不用平台 spring | 提交路径与 tick 路径观感分叉 | `commit_spec_spring_uses_same_integration_as_tick` |
| 4 | 弹簧采样窗口用**自然静止时间** | 被端点钉死截断（弹簧走不完） | `spring_commit_window_covers_natural_settle` |
| 5 | 动画绑定 **Slot 身份**（非 Node 身份） | 复用率 0.997 下"错误的项在做动画" | `stop_nodes` 解绑 + 宿主 `onRowDematerialized`（真机 D 组） |
| 6 | 不开放任意 JS 动画函数 | 毁掉 conformance 与 AI 可校验 | 封闭集 + 逃生口需登记三要素（做什么/为什么/行为风险） |

## 两条渲染路径（各有适用面）

| | **内核驱动**（逐帧求值） | **平台零参与**（提交一次） |
|---|---|---|
| 机制 | 宿主帧循环（Choreographer / CADisplayLink）→ 内核 `tick` → 写变换 | 内核采样 → 一个平台动画对象交给系统渲染线程 |
| 每帧跨边界 | 1 次（24B/条二进制） | **0 次**（提交后主线程脱手） |
| 覆盖 | 序列编排 / 滚动联动 / 共享元素——**任何**动效 | 仅合成属性（transform / opacity）且非滚动驱动 |
| 真机读数 | 帧循环 57 帧 · 每帧 p50 0.098ms · 稳态零布局 | 主线程 0 绘制 · 600ms 窗口 CPU 1.0ms（对照 tick 17.4ms） |

**判定在编译期**：`isPlatformEligible(batch)` 预判 + 内核 `anim_commit_spec` 双重校验；滚动驱动的批次**禁止**走平台路径（那条路径的语义是"按时间自主插值"，混用会把"跟手"变成"到点自动播放"）。

## 逃生口（显式、可统计）

编译层的封闭集**故意不追求覆盖一切**。表达不了的动效走 `escapes.register({ kind, detail, reason, behaviorRisk })`——三要素必填，缺任一当场抛错；`degraded` 类在报告里**单列高亮**，并对照 5% 目标率（当前装置就绪、业务用量待采数）。

> 设计取向：**宁可显式登记一个逃生口，也不要静默引入第二条实现**——前者可统计可收敛，后者必然分叉。

## 任意缓动曲线（★2026-10-01 转正 —— 从逃生口到契约能力）

封闭集里的 5 条曲线是"常用"的快捷名；设计稿给一条具体缓动（`cubic-bezier(.34,1.56,.64,1)`）
此前只能走**逃生口**（`custom-easing`，登记 + degraded）。现在它是**契约能力**：
`curveBezier: [x1,y1,x2,y2]` 与内置曲线走**同一台求值机器**——
内核把控制点生成一张 65 点采样表（生成一次，按控制点缓存；800 片同曲线共享一份），
之后求值是一次查表插值，**零迭代**；端点钉死、跨端逐位一致，与内置曲线无差别。

> **为什么这是"最强"叙事的一环**：RN 的 Reanimated / Framer / Web Animations 都能吃任意
> cubic-bezier，但它们在**各自运行时**求解；我们把它收敛成**跨语言契约 + 内核唯一实现**——
> 同一个控制点在三个端上求出的值逐位相同，且能进平台零参与路径的采样提交流程。

**边界（如实）**：① `x1/x2 ∈ [0,1]`（时间轴单调；`y` 任意）；② 与 `curve`/`spring`/`keyframes` 互斥；
③ **段级**自定义曲线暂不支持（`keyframes` 的每段仍用封闭集——见声明页）。

## 颜色在封闭集里（★2026-10-01 起；附新的边界）

封闭集由 **5 项扩到 7 项**：`translateX / translateY / scale / rotate / opacity`
**＋ `color`（底色）＋ `textColor`（文字色）**（此后又经 3D / clip / 描边 / v2 五批扩至 **17 项**
——完整清单与编号契约见[声明面](/docs/animation/02-surface)的属性表）。

**用户面一个声明，内核面四条通道**——`{ kind: 'color', from: '#2f6fed', to: '#ff5533' }`
在编译期展开成 `R/G/B/A` 四条标量指令（契约编号 5/6/7/8；文字色同构，编号 9/10/11/12）。

> **为什么这么分解（架构收益，不是权宜）**：引擎的求值机器（曲线查表 / 弹簧积分 / 序列分段 /
> 滚动窗口 / seek / 接管速度移交 / 端点钉死）**全部是标量的**。拆成四条标量通道 ⇒
> 这些机器**零改动复用**，不需要"多通道求值"的第二套实现（纪律 #22）。
> 代价如实：一次颜色动画 = 4 条指令（指令计数 +4）。

| 项 | 说明 |
|---|---|
| 值形态 | `#RGB`（简写，各通道重复一位）/ `#RRGGBB` / `#RRGGBBAA`（**CSS4 序**，低 8 位 = alpha）。解析规则**内核与 TS 同一张钉值表**（`tests/anim-color-golden.test.ts`） |
| `from` | **必填**——内核对颜色**没有**"缺省 = 当前底色"语义（与标量属性同一纪律，见 [声明面](/docs/animation/02-surface) 的约束条目） |
| 底色前提 | 目标节点必须在树里声明 `backgroundColor`（它是**起点基准 + 复位目标**）；否则内核**明确拒绝**（不静默） |
| 复位 | `animStopAll` / 节点回收解绑 / 相位清理都会**回到底色**（不是停在末帧——"解绑必须含清值"的又一次应用） |

**文字色**（2026-10-01）与底色**同构但独立成轨**：`{ kind: 'textColor', … }` → 通道编号
**9/10/11/12**（不复用 5..8 的槽位——两条轨道可同时动一个节点，合并槽位会让后写者覆盖前者）。
前提是节点在树里声明 `color`（文字色基色；同样**必填 `from`、stop 回基色**），落点是
iOS `CATextLayer.foregroundColor` / Android `textPaint`。每帧记录因此从 28B 增至 **32B**
（末两个 u32 = 底色 + 文字色打包色，`u32::MAX` = 无该基色；宽度由
`scripts/check-anim-record-bytes.mjs` 从内核写入序列推出、与各消费端对账）。

**颜色 keyframes（多段序列）**同批可用：`keyframes: [{ to, durationMs, curve? }, …]` 按通道展开，
语义与标量序列**完全同源**（段边界精确、端点钉死——同一条求值机器）。

**★仍有的边界（如实标注，两条）**：

1. **颜色是 paint-only 但「非合成」⇒ 不进平台零参与路径**。原因不是"它会触发布局"（它不会——与
   `opacity` 同一成本类，动画期**零布局**），而是**跨端一致**：Android 的 `RenderNode` 可插值集里
   **没有背景色**（`setBackgroundColor` 不在 RenderThread 动画属性中）⇒ 若 iOS 单边放行
   （`CALayer.backgroundColor` 理论上可由 CA render server 插值），两端就会**分档**——同一份源码
   在两个端走不同路径，是本仓最忌讳的分叉。⇒ 统一走 **tick 路径**。
2. **文字色只覆盖"整段文本一个色"**（`CATextLayer` / `textPaint` 直接绘制）。富文本
   **run 级着色**（一条文本里多段不同色）不在本引擎范围——那是文本排版层的职责，另批立项。

> **与逃生口的关系（这条边界的语义变了）**：`color` 现在是**契约能力**，不再需要走 `escapes.register`。
> 但"不得静默引入第二条实现"的纪律不变：**画面里颜色在动，就必须能追溯到指令**
> （判据：双端 P 组 —— 断言"声明 → 四条通道 → 宿主真写层 → 复位回底色"全链，
> 且探针**真读** `CALayer.backgroundColor` / Android 宿主取色表）。

## 与"第二 JS runtime"的关系

方案里的路线 B（引入第二 runtime 执行任意动画逻辑）**在当前阶段不启动**：它要求同时满足「有真实业务场景无法编译期分析」+「实测证明主线程方案掉帧」+「团队接受额外内存与启动成本」三条。现状是路线 A（指令驱动）已由 RT0 对照实验证明可行且快得多——N=1000 时内核每帧仅 **2.38µs**，且每帧工作量**不随节点数增长**。

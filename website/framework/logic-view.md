# 逻辑层与视图层

跨端框架的第一性问题：**你的代码在哪里跑，界面在哪里渲染**。Proteus 把答案收敛为一句话——业务写「逻辑 + 视图声明」，执行模型交给框架与后端。

## 业务视角：两段代码

| 段 | 角色 | 跑在哪 |
|---|---|---|
| `<script setup>` | **逻辑层**：状态、事件处理、能力调用 | 同一 JS 逻辑层——Web 同线程 Vue 运行时 / 小程序独立逻辑层 / App 经 JSI 载体 / SSR Node |
| `<template>` + `<style>` | **视图层**：界面结构与样式声明 | 各端各自渲染引擎：Web DOM（vue-dom）/ 小程序 WebView 或 Skyline / iOS·Android·鸿蒙 原生控件 / Flutter Widget |

逻辑层与视图层的耦合方式（同线程直驱 vs setData 桥）是各端唯一差异，收敛在渲染后端与桥接层——语义与业务代码零分支。全部端的状态见 [端与成熟度](/docs/framework/ends-matrix)。

## 小程序的双线程模型

小程序端逻辑层与视图层**物理分离**：逻辑层跑在独立 JS 运行时（无 DOM/BOM），视图层由 WebView 或 Skyline 原生渲染。两者通过 `setData` 桥通信——这正是 `ref` 读写被编译器重写为 `setData`（16ms 批量合并）的原因。

Web 端没有这道墙：Vue 同线程渲染。Proteus 把两种模型**编译期吸收**，业务代码零感知。

## 视图层声明 = 语义

视图层不是自由 HTML——p-* 语义组件声明「要什么」（网格意图、扫码入口），后端按语义实现。这是与「模板就是 HTML」框架的根本区别，也是 AI 能安全产码的前提（IR 上有约束）。

## 本分区怎么展开

- **编译期**（5 讲）：逻辑层重写与视图层映射的具体规则
- **运行期**（含调试）：两端各自的实际执行模型
- **组件框架**：p-* 组件的生命周期/事件/样式机制

# 折叠姿态与连续性

> **折叠屏是动态形态**：同一台设备在「折叠态外屏 / 半开（悬停）/ 展开态内屏」之间切换，应用不应重启、不该丢状态，布局应连续重排。柔性系统把姿态做成一等数据——`postures[]` 声明每个姿态的拓扑、导航、视口、折痕位置与度量基准。

## 先分清：两类折叠是**两种设备**

折叠屏不是一种设备的两姿态 —— 真机内外屏比例**恰好互换**（三星官网实测）：

| 设备类型 | 内屏 | 外屏 | 半开铰链 |
|---|---|---|---|
| **书本式 / 左右对折**（Z Fold6 · Mate X5 · MIX Fold） | 2160×1856 → **近方形 0.86** | 968×2376 → **竖长条 0.44** | **竖直**（Book 模式，左右两半） |
| **翻盖式 / 上下对折**（Z Flip6 · MIX Flip） | 2640×1080 → **竖长条 0.41** | 720×748 → **近方形 0.96** | **水平**（TableTop 模式，上展示/下操作） |

本仓据此拆为两个形态：`fold`（书本式）与 `flip`（翻盖式）——此前把它们混为一个 `fold`，
导致「展开 0.70 / 折叠 0.69 几乎同比例」这种真机上不存在的数据，以及**水平铰链被错配给书本式**。
小米《大屏应用 UX 设计指南》原文明分「Book 书本模式（左右对折）」与「TableTop 桌面模式（上下对折）」，
即为此二分的直接依据。

## ★★半开（悬停）：应用区只是**内屏的一半**

> **命名纪律**：书本式设备是被**打开约 90°**（half-**open**，悬停态），不是「折成两半」；
> 「半折」只适用于**翻盖式**（clamshell，确实折了一半）。「半折（书本模式）」是早期版本自造的说法，已撤销——
> 小米原文只写「Book 模式」/「TableTop 桌面模式」。

半开时朝向用户的那半屏才是应用区，另一半平放或背向 —— 所以**半开视口不可能等于内屏视口**。
按真机像素与展开态同一比例尺（÷3）换算：

| 设备 | 内屏（px → pt） | 半开应用区（px → pt） | 占比 |
|---|---|---|---|
| 书本式 Fold6 | 2160×1856 → **596×693**（0.86 近方形） | 2160×928 → **693×298**（2.33 **横长条**） | **50%** |
| 翻盖式 Flip6 | 1080×2640 → **360×880**（0.41 竖长条） | 1080×1320 → **360×440**（0.82 竖方形） | **50%** |

`validateFormProfiles` 强制三条（机器门禁，删数据即红）：
① 半开/展开**面积比须在 40–75%**（真机恰为 50%）② 半开视口**不得与展开态同值**
③ 折叠态（外屏）**不得声明折痕**（外屏看不到折痕——早期演示在折叠态也画了一条，是**假折痕**）。

## 姿态表（fold · 书本式）

| 姿态 `key` | 视口 | 拓扑 | 导航 | 折痕 | 特殊语义 |
|---|---|---|---|---|---|
| `folded` 折叠态（外屏） | **320×727**（0.44 竖长条） | `stack` 单列 | `side-tabs` | 无 | 外屏像一部窄手机 |
| `book` 半开（悬停 half-open） | **693×298**（2.33 **横长条**） | `duo` | `side-tabs` | 水平 · 窗口**底缘** | 左半展示 / 右半操作（设备转 90°，铰链仍竖直） |
| `expanded` 展开态（内屏） | **596×693**（0.86 近方形） | `duo` 双窗格 | `side-tabs` | 竖直 · **贯穿中部** | 主图 + 详情分列 |

## 姿态表（flip · 翻盖式）

| 姿态 `key` | 视口 | 拓扑 | 导航 | 折痕 | 特殊语义 |
|---|---|---|---|---|---|
| `folded` 折叠态（外屏） | **340×354**（0.96 近方形） | `glance` 一屏一意 | `page-stack` | 无 | 外屏小卡展示 |
| `tabletop` 半折（桌面模式） | **360×440**（0.82 竖方形） | `stack` | `side-tabs` | 水平 · 窗口**底缘** | **水平**铰链——上半展示 / 下半操作 |
| `expanded` 展开态（内屏） | **360×880**（0.41 竖长条） | `stack` 单列 | `bottom-tabs` | 水平 · **贯穿中部** | 常规竖屏手机形态 |

```ts
// packages/fluid/src/formfactor.ts（fold 画像摘录——真机像素 ÷3）
postures: [
  { key: 'folded',   topology: 'stack', nav: 'side-tabs', viewport: { width: 320, height: 727 },
    ratio: { baseFont: 13, ref: 320, min: 0.85, max: 1.5 } },   // ← 姿态级度量
  { key: 'book',     topology: 'duo',   nav: 'side-tabs', viewport: { width: 693, height: 298 },
    hinge: 'vertical', crease: { axis: 'horizontal', at: 'bottom' } },  // 半开：铰链在窗口底缘
  { key: 'expanded', topology: 'duo',   nav: 'side-tabs', viewport: { width: 596, height: 693 },
    crease: { axis: 'vertical', at: 'middle' } },                       // 展开：折痕贯穿中部
]
```

## 折痕几何：`hinge` 与 `crease` 是**两个不同的量**

- `hinge` = **设备固有轴**（书本式竖直 / 翻盖式水平）——这是硬件的，不随姿态变；
- `crease` = **折痕在本姿态窗口内的走向与位置**——随姿态变：
  - 半开（悬停）：朝向用户那半屏的下方是铰链 → `{ axis: 'horizontal', at: 'bottom' }`（书本式半开时设备被转 90°，铰链轴仍竖直，但屏幕上的折痕是水平的）；
  - 展开（平坦）：折痕贯穿屏幕中部 → `at: 'middle'`（fold 竖直 / flip 水平）；**不画带**（平坦态折痕是浅痕，不构成布局区域）；
  - 折叠（外屏）：**不声明** —— 看不到折痕。

组件按 `crease.at === 'bottom'` 渲染可见折痕带（`.pf-crease`，带内不得有元素）；`data-pf-crease` /
`data-pf-crease-geom` 是对外可断言的诊断面。端可注入真机铰链带宽度（`crease-band` prop /
`env(fold-*)`）——**机型几何交给端**，框架只收规则与形态类。

## 连续性契约

1. **形态不重启**：业务状态（表单输入、选中项、滚动位置）跨姿态保留——由「同一组件实例重排」保证，不是重新挂载。
2. **拓扑连续重排**：`stack` ⇄ `duo` 是结构变化，不是缩放；折叠/展开拓扑**必须不同**（`validateFormProfiles` 强制），否则「形态切换」名不副实。
3. **视口递增**：展开态视口必须宽于折叠态，门禁校验。
4. **度量随姿态**：姿态可覆写 `ratio`——外屏 320pt 若沿用内屏基准（ref 420）会得到 k=0.76 → 正文不可读；改按窄手机基准后正文 ≥11px。

> ★**诚实边界**：演示页的「状态不丢」目前是「同一实例重排」的**证据**（`data-biz-*` 可断言，
> 面板给出切换前后对照）；框架级连续性**契约**（`onFormChange` / 端姿态事件源）仍在
> [OS 级路线图](/docs/system/01-overview) P0/P1，尚未交付。**S4 之前不得对外宣称「框架保证状态连续」**。

## 半开的取舍（两类设备各按自己的几何）

半开的可视区只有内屏一半，实现按**优先级取舍**而非等比压缩：

- **书本式**（横长条 693×298）：左半 = 展示（媒体为底 + 标题/价格）· 右半 = 操作（规格 / 主操作 / 推荐列）；
- **翻盖式**（竖方形 360×440）：上半 = 展示（左媒体 + 右文案）· 下半 = 操作（规格 + 主操作）· 推荐压成单行卡；
- 两类都：**只**收起长描述（次要信息）；**规格（SKU）保留**——它是购买路径。

> ★★三区域规则（2026-09-28 借鉴**国内厂商统一基线**：ITGSA 金标联盟白皮书 / 小米《大屏应用 UX 设计指南》原文，OPPO·vivo·小米共同署名）：
> 「将展示性内容收拢至区域 2，将可交互功能下沉至区域 1，并**避免区域 3 内出现任何元素**」
> —— 区域 2 = 上半屏（展示）· 区域 1 = 下半屏（操作）· 区域 3 = 折痕/形变区。
> 本实现取「**空行 + 独立折痕带元素**」：折痕带所在网格行不分配给任何元素 → 「带内无元素」由结构保证，
> e2e 另有几何断言（折痕带矩形与各内容块零交集）。
>
> ★配套原文：「**不要使用 rotation，而是根据宽高的大小做布局处理**」（小米）与华为《布局基础》把
> 断点分为**横向（宽度）+ 纵向（宽高比）**两条独立维度 —— 本仓据此新增 `resolveAspectClass`
> （tall / balanced / wide / ultra-wide）并让媒体高度上限随宽高比收紧（`aspectMediaCap`）：
> 越扁的画布，媒体越让位给信息与操作。车机 8/3（ultra-wide）与 TV 16:9（wide）因此区分开——
> 二元 `orientation` 做不到这件事。
>
> ★两处按 Apple HIG 修正（2026-09-28）：
> ① **不再隐藏 SKU**——原文两条：「Maintain the same functionality across device poses」（跨姿态必须能访问**同样的控件与内容**）与「Avoid extreme layout changes as people fold … favor small adjustments over rearrangement」。SKU 被隐藏即丢功能，现改为紧凑排布；演示页的「功能对照条」把每个被收起的控件连同理由一起列出（不得静默丢失）。
> ② **折痕语义**：内容不得跨折痕；但**只有能看到折痕的姿态才画折痕**（折叠态/展开态不画）。

## 厂商档位对照（ITGSA / 小米宽度 + 高度断点）

国内厂商统一基线给的是**两套断点**，与我们的容器断点（设计稿驱动，188/328/469/609）是**两套坐标**：

| 维度 | 厂商档位（ITGSA / 小米，引 Google） |
|---|---|
| 宽度 | `<600dp` Compact · `600–840dp` Medium · `≥840dp` Expanded |
| 高度 | `<480dp` Compact · `480–900dp` Medium · `≥900dp` Expanded |

`vendorSizeClass(width, height)` 把任意窗口翻译成厂商档（宽度档与高度档**各自独立**——
华为「双维度断点」的原意）；我们的容器断点仍管「同一组件在容器里怎么连续变化」。
演示页的折叠面板把两套值并列显示（如书本式半开 693×298 → 厂商宽度档 medium / 高度档 compact）。

## 铰链几何

真机（Web 折叠屏）经 `env(fold-*)` 提供铰链带宽度，框架发射 `--pf-fold-width` 并由 `duo` 拓扑消费：

```css
.topo-duo .pf-body {
  /* 真机 env(fold-width) > 0 时自动让开折痕；普通屏幕回退 0px = 与设计间距一致 */
  column-gap: max(calc(var(--pf-gap) * var(--pf-gap-dense)), var(--pf-fold-width, 0px));
}
```

> 历史坑：早期实现同时输出「左侧按铰链左缘缩进」与「右侧按右窗格宽缩进」——中置铰链设备上两侧内边距之和 = 100%，**内容宽归零**。正确语义是「单流内容只避让铰链带」，而非双向内边距。

## 姿态如何被消费

| 环节 | 说明 |
|---|---|
| 声明 | 宿主传 `posture="folded \| book \| tabletop \| expanded"`（演示页走 `?posture=` 可分享） |
| 生效条件 | **仅当该形态的画像真有此姿态**才生效——`phone + posture=book` 会被忽略（否则会静默套用折叠布局，声明与渲染打脸） |
| 覆盖范围 | `topology` / `nav` / 视口 / `ratio`（度量基准）/ 折痕渲染 |
| 诊断属性 | 根节点 `data-pf-posture` / `data-pf-topology` / `data-pf-nav` / `data-pf-crease` / `data-pf-crease-geom`（可被 e2e 断言） |
| 端注入 | `crease-band` prop（真机铰链带宽度）；机型几何/姿态事件仍在端侧 |

## 诚实边界

- 姿态**来自宿主声明**。Web 端可读 `display-mode: fold/span` 做增强，但真机姿态事件（WM FoldingFeature / ArkUI foldStatus / hinge 角度）属**形态感知服务**范畴，尚未接入——愿景见 [OS 级路线图](/docs/system/01-overview)。
- 当前只建模三个离散姿态；铰链**角度**是连续量，不扩成枚举（按几何输入处理属规划项）。
- 机型几何**只用三星 Fold6 / Flip6**（已核实）；华为 Mate X5 / 小米 MIX Fold / vivo X Fold 规格**未核实**，
  在演示中不作为依据引用（§「代表机型」见计划 03 §1.5）。
- 华为原文的诚实边界适用：**小屏（手表）与特殊比例（Pura X 外屏）无法靠一套布局适配**——需单独设计，
  演示里标注而非假装自适应。

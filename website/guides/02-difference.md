# Proteus 与传统跨端框架的区别

Proteus 的主要开发语言是 Vue（标准 SFC），对前端开发者来说上手成本不高。它与传统跨端框架的根本区别在于**架构站位**：

> **任何跨端问题 = 语义定义（框架做） + 后端实现（平台做）**

框架只做两件事：定义「你要什么」（语义接口 / IR），定义「怎么验证做对了」（conformance 套件 / 编译期约束）。平台提供「怎么做」（后端实现）。**业务开发者只消费语义接口，对后端零感知。**

## 与常见跨端框架的对比

| 维度 | 常见跨端框架 | Proteus |
|---|---|---|
| 业务写法 | 平台 DSL（`view` / `text`）或单端语法锁定 | 标准 HTML + 标准 Vue SFC |
| 渲染底座 | WebView 或锁定单一引擎 | 可插拔，同一 App 按页面选引擎 |
| AI 介入方式 | 无 IR，只能文本替换 | 操作 IR + 编译期强制校验 |
| 工具链 | IDE 锁定 | 纯 Vite 插件，任何 CI 可跑 |

普通 DSL 映射是「换种语法写原生代码」；Proteus 是「定义语义，让任何后端实现它」。

## 「不绑定」是同一个设计动作

「不绑定」不是口号，而是同一个设计动作在全部架构维度上的重复：每一层先定义语义契约，再把具体实现做成可插拔后端——平台 API、渲染引擎、编译器、容器形态、宿主运行时、执行载体，全部如此。完整总表见[可插拔架构](/docs/framework/22-architecture)。

## 这对 AI 意味着什么

竞品缺的不是某个 API，而是「显式语义 + 可编程 IR + 后端原生映射 + 强制校验」。AI Agent 操作的是 **IR**——IR 上挂着编译期约束，所以 AI 产出的代码不靠约定俗成，靠机器校验。详见 [AI 原生开发](/docs/32-ai-agent)。

# 规约增量变更：宿主容器层（G-42）

> **类型**: 架构级新增层 + 原则扩展

> **规划体系**: 55 份 plan + 1 哲学 + 1 规约

---

## 1. 新增原则（#13.18 ~ #13.20）

### **原则 #13.18** 页面生命周期必须有单一 Owner

> 页面状态必须由 IR 实例唯一持有。禁止"JS 状态 ↔ 原生 View"双边持有。

**理由**：双边持有 = 人工配对 = 必然泄漏。这是传统框架的结构性缺陷。

---

### **原则 #13.19** 资源必须由框架代管

> 定时器/监听/订阅/请求等资源必须走框架代管接口，禁止业务裸用全局 API。

**理由**：人工配对必然有漏。代管后销毁自动回收。

---

### **原则 #13.20** 容器形态必须可插拔

> 页面组织方式（单页/栈/超级应用/小程序/窗口/嵌入）必须是可替换策略，禁止硬编码。

**理由**：方法论第六次泛化——不绑容器形态。

## 2. 分层全景图更新（新增 L2 容器层）

```
┌─────────────────────────────────────────────────┐
│ L0  业务应用（128 语义原语）                      │
├─────────────────────────────────────────────────┤
│ L1  框架内核（IR / Diff / 响应式 / 调度）         │
├─────────────────────────────────────────────────┤
│ L2  ★ 宿主容器（G-42）  ← 本轮新增               │
│     页面栈 / 业务沙箱 / 资源配额 / 生命周期治理   │
├─────────────────────────────────────────────────┤
│ L3  宿主运行时（G-39）                            │
│     线程 / 事件循环 / 执行载体 / 原生桥           │
├─────────────────────────────────────────────────┤
│ L4  后端层                                        │
│     G-27 渲染 · G-28 能力 · G-40 载体             │
├─────────────────────────────────────────────────┤
│ L5  原生宿主（iOS / Android / Harmony / Web ...） │
└─────────────────────────────────────────────────┘
```

**注**：G-39 之前描述为"宿主运行时层"，现细分为 L2 容器 + L3 运行时两层。职责更清晰：

- **L3 运行时**：管"进程怎么跑"（线程/循环/桥）
- **L2 容器**：管"页面怎么组织、内存怎么管、业务怎么隔离"

## 7. 风险边界（诚实声明）

| 不适用 | 原因 |
|--------|------|
| 非托管语言宿主（C/C++ 主程序） | 无 GC，框架代管资源模型不适用，需 L3 进程隔离兜底 |
| 单页无导航场景 | Stack 容器无意义，用 SinglePage 即可 |
| 已有成熟容器的平台（如微信） | 复用宿主容器，Proteus 容器层降级为 Embedded |
| 极端内存受限设备（<10MB） | 沙箱开销过大，建议 SinglePage + 无隔离 |

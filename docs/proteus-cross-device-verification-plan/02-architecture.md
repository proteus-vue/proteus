# G-52 架构

## 1. 二维验证空间

```
                执行环境 →  L0 文档 | L1 模拟 | L2 真机   (G-51)
               设备形态 →  等价类代表 × 四维        (G-52)
```

G-52 在 G-51 之上加"设备层"，形成二维验证空间。

## 2. 分层

```
TestSuite
   │
   ▼
DeviceMatrixRunner.executeOn(matrix, suite)
   │
   ├─ Backend.runOn(device, suite)   ← 每设备执行（并行 Promise.all）
   │
   ├─ DeviceEquivalenceClass        ← 划分 + 代表采样
   │
   ├─ DriftFingerprint              ← 四维指纹
   │
   └─ normalize()                   ← 去噪 → 可 diff
```

## 3. 归一化流水线

```
原始结果 → 设备指纹 → 等价类比对 → 偏差≤ε?
                                        ├─ 是 → 一致
                                        └─ 否 → 漂移归因(四维) → 记录
```

## 4. 云端策略：本地优先

- L0/L1：本地即可跑（文档、模拟）
- L2：本地矩阵优先（开发者手上的真机）
- L3 云端：仅当本地覆盖不足时按需补充，**不强制联网**

## 5. 成熟度（与 G-51 合并）

```
L0 文档自检       ← G-50
L1 IR 模拟        ← G-51
L2 真运行时       ← G-51 + G-52(设备矩阵)
L3 跨设备(云端)   ← G-52 (本份：仅定义接口，云端调度留待 G-53)
```

# Proteus 超级应用视觉设计规范

> 适用工程：`superapp/`（Proteus 超级应用 = **框架最终验收场**）
> 版本 v1 · 2026-10-04 · 配套 `superapp/styles/global.css`（**机器可消费的唯一事实源**）
> 定位：**生产可用的视觉标准**——不是 examples 里那种"能跑就行"的 demo 视觉

---

## 0. 为什么需要这份规范（先说清楚它不是什么）

**它不是"一套好看的配色"。** 它是**验收标准的一部分**：
「超级应用生产可用」这句话如果只有功能判据（八条场景能触发），就还是 demo 级——
真实的超级应用要经得起**用户全天使用**（可读性 / 信息密度 / 一致性），而不是"能演示"。

| | examples（内部测试） | showcase（对外演示） | **superapp（本规范）** |
|---|---|---|---|
| 用途 | 编译/渲染边界用例 | 展示框架能力 | **验收"生产可用"** |
| 视觉要求 | 无（能验证即可） | 亮眼、品牌感 | **克制、耐看、信息密度优先** |
| 色彩 | — | 品牌紫（#7c5cff，明亮） | **靛蓝（#5b5bd6，沉稳）** |
| 正文 | — | 15–16px | **14px（密度优先）** |
| 状态色 | — | demo 惯例（浅底白字） | **压深一级（AA 全达标）** |
| 卡片边界 | — | 阴影为主 | **1px 线 + 轻阴影（不发光）** |

> 一句话：**showcase 是"给人看能力"，superapp 是"给人用系统"。**

---

## 1. 三层结构

```
L1  设计 token      颜色 / 字号 / 间距 / 圆角 / 阴影 / 动效     ← styles/global.css 前半
L2  组件规范        卡片 / 列表 / 徽标 / 按钮 / 空态 / 文本工具  ← styles/global.css 后半（.sa-* 共享类）
L3  页面模式        工作台 / 列表 / 设置 / 表单 / 详情 / 结果     ← 本文 §4（骨架约定，不强制共享类）
```

**L1/L2 是机器可消费的**（`superapp/styles/global.css`，两端同一份：MP → `app.wxss`；Web → `main.ts` import）。
**L3 是叙事**（页面骨架约定，由页面自己按模式写）——因为页面模式与业务耦合度高，
强行共享类会让页面变僵（本仓教训：抽象要等第三个用例出现）。

## 2. L1 · 设计 token（摘要；全文见 global.css）

### 2.1 品牌色：靛蓝

| token | 值 | 用途 |
|---|---|---|
| `--sa-brand` | `#5b5bd6` | 主操作、选中态、品牌标识 |
| `--sa-brand-ink` | `#4a4ab8` | 图标/文字用的深一档（保证 AA） |
| `--sa-brand-soft` | `rgba(91,91,214,.10)` | 浅底（标签/头像底） |
| `--sa-brand-soft-2` | `rgba(91,91,214,.18)` | 稍重的浅底（激活态） |

**为什么不是 showcase 的紫**：靛蓝比紫更**冷、更稳**——与"业务系统"的语义一致
（金融/工具/后台类超级应用的主流色相）；且 `#5b5bd6` 上白字对比度 **5.1:1**（正文 AA 达标临界）。

### 2.2 中性面（浅色 / 深色两套）

| token | 浅色 | 深色（`.sa-dark`） | 说明 |
|---|---|---|---|
| `--sa-bg` | `#f4f5f7` | `#14161b` | 页面底（**冷灰**，不是纯白） |
| `--sa-surface` | `#ffffff` | `#1c1f26` | 卡片面 |
| `--sa-surface-2` | `#fafbfc` | `#232730` | 卡片内浅一级（按下态） |
| `--sa-line` | `#e4e6eb` | `#2e3340` | 边框 |
| `--sa-line-soft` | `#eef0f3` | `#262b36` | 细线（列表分隔） |
| `--sa-text` | `#1a1c22` | `#eef0f5` | 主文字 |
| `--sa-text-2` | `#5a5e6b` | `#a8aebc` | 次要文字 |
| `--sa-text-3` | `#9298a4` | `#767d8c` | 辅助文字 |

**为什么底线不是纯白**：生产应用页面多、卡片多——纯白底会让卡片边界消失
（只能靠阴影，那是低对比 + 打印不可读）；冷灰底 + 白卡片让**层级不依赖阴影**。

### 2.3 语义状态色（**全部满足 WCAG AA**）

| token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--sa-ok` | `#1f9d5f` | `#3ec27e` | 成功/已完成 |
| `--sa-warn` | `#c47f17` | `#e0a53a` | 警告/进行中 |
| `--sa-rec` | `#d64545` | `#f07070` | 危险/未读/紧急 |
| `--sa-info` | `#2f6fd6` | `#6da2f0` | 信息 |

**★这条是"生产 vs demo"的分水岭**：demo 常用「浅绿底 + 白字」（`#22c55e` + white = 2.2:1，
远低于 AA 4.5:1）——真机阳光下根本看不清。本规范的状态色**全部压深一级**，
白字对比度 ≥ 4.5:1；深色模式则**反向提亮**（深底上用亮色）。

### 2.4 字号 / 间距 / 圆角 / 阴影

| 组 | 值 | 关键决策 |
|---|---|---|
| 字号 | xs 11 / sm 12 / **md 14** / lg 16 / xl 20 / xxl 26 | **正文 14**（比演示类小一号 ⇒ 信息密度优先） |
| 行高 | tight 1.25 / normal 1.5 / loose 1.7 | 长文用 loose，列表用 tight |
| 间距 | `--sa-1..10`（4 的倍数） | 与《单位系统与舍入规范》物理像素整数对齐 |
| 圆角 | sm 6 / md 10 / lg 14 / xl 20 / pill 999 | **语义化**——页面禁写裸 px 圆角 |
| 阴影 | sm / md / lg（都很克制） | **靠明度差 + 1px 线表达层级**，阴影只做轻微抬升 |

### 2.5 动效

| token | 值 | 说明 |
|---|---|---|
| `--sa-dur-fast` | 140ms | 按钮/开关反馈 |
| `--sa-dur-med` | 240ms | 主题切换、面板显隐 |
| `--sa-dur-slow` | 380ms | 转场类 |
| `--sa-ease-out` | `cubic-bezier(.22,.61,.36,1)` | 进入 |
| `--sa-ease-in-out` | `cubic-bezier(.4,0,.2,1)` | 双向 |

**生产应用：快而稳，不炫技**——没有弹跳（bounce）、没有超过 400ms 的动画。

### 2.6 深色模式机制（★MP 约束下的实现）

```vue
<view class="sa-page" :class="{ 'sa-dark': theme === 'dark' }"> ... </view>
```

- 变量覆盖块 `.sa-dark` 定义在 `global.css` 里（`page` 级生效，元素天然继承）
- **不用 `prefers-color-scheme`**：小程序内主题由**应用内开关**控制（用户在设置页选）
- **不用 `:root.dark`**：MP 端无 `:root`（WXSS 根选择器是 `page`，构建期改写；见 global.css 头注）
- ★动态 class 必须**字面量键**（`{'sa-dark': cond}`）——拼串会被编译期插 scopeId ⇒ 与 CSS 不匹配
  （本仓 T12/A 类陷阱，GP4-a 实测）

## 3. L2 · 组件规范（共享类，全部在 global.css）

| 类 | 形态 | 用途 |
|---|---|---|
| `.sa-page` | 全高 + 底安全区 | 页面根（每页最外层） |
| `.sa-section` | 分区标题 | 页面内分组（生产应用靠它建层级，不靠大留白） |
| `.sa-card` + `__body/__title/__sub` | 卡片 | 基本容器（1px 线 + 轻阴影） |
| `.sa-list` + `.sa-item` + `__main/__label/__desc/__value/__arrow` | 列表 | **生产应用最重的模式**（左主文 + 右值/箭头） |
| `.sa-badge` | 圆角徽标 | 未读数（99+ 截断在业务侧做） |
| `.sa-tag` | 小标签 | 状态标记（紧急/新） |
| `.sa-btn` / `.sa-btn--ghost` | 页面级大按钮 | 主操作（44px 高；小按钮用 `p-button`） |
| `.sa-empty` + `__icon/__text` | 空态 | 列表空/加载失败 |
| `.sa-t1..t5` | 文本工具 | 五级文本（字号+色+字重成套） |
| `.sa-ok/.sa-warn/.sa-rec` | 状态文本色 | 语义着色 |

**规则**：
1. **交互组件优先用框架 `p-*`**（`p-button` / `p-input` / `p-modal`）——它们有语义与平台对齐；
   `.sa-*` 只补"纯视觉骨架"（无状态、无事件）。
2. **列表项点击态**用 `.sa-item--tap`（`:active` 变浅底）——不用 JS 管理按压态。
3. **禁止**在页面里重定义上述类名（那是规范的一部分，改了就是分叉）。

## 4. L3 · 页面模式（六种标准骨架）

| 模式 | 骨架 | 本工程示例 |
|---|---|---|
| **工作台** | 问候/概览 → 数据卡片 → 快捷入口 → 待办列表 | `pages/index.vue` |
| **列表** | 标题行（含计数）→ 操作区 → 会话/条目列表 → 说明 | `pages/messages.vue` |
| **设置** | 头像区 → 分组卡片（开关/跳转行）→ 关于 | `pages/mine.vue` |
| **表单** | 字段组 → 校验提示 → 底部主按钮（吸底） | （待业务需要时补） |
| **详情** | Hero 区 → 属性列表 → 正文 → 底部操作栏 | `pages/article.vue` |
| **控制台** | 标题+说明 → 逐行（信息/按钮组/读数）→ 日志 | `pages/verify.vue` |

**通用约定**：
- 标题字号：工作台/列表用 `xxl`（26px）+ `letter-spacing:-0.3px`；详情/设置用 `xl`
- 每个分组的标题一律 `.sa-section`；分组间距统一 `--sa-3`
- 页面底部留 `calc(var(--sa-6) + var(--sa-safe-bottom))`（`.sa-page` 已含）

## 5. 与框架约束的关系（★写规范时必须同时知道）

| 框架约束 | 对视觉规范的影响 |
|---|---|
| **MP 默认 scoped**（每 .vue 的 `<style>`） | L2 共享类必须走 **global 通道**（`globalStyle`）——写在页面 `<style scoped>` 里匹配不上 |
| **`globalStyle` 只接受单文件** | L1+L2 合成 `styles/global.css`（**不能拆两文件**——会静默漏一半） |
| **动态 class 必须字面量键** | 深色主题用 `{'sa-dark': cond}`；**禁止**拼串类名 |
| **MP 不支持 `position: fixed`**（Skyline） | 全局浮层走 root-portal（Overlay 层）；全局层内用 `absolute` + 层级变量 |
| **文本不支持嵌套 `<text>` 内 flex** | 文本节点用 `<text>`，盒模型容器用 `<view>`（S52） |
| **坐标舍入只在内存**（卡 I2） | 视觉间距一律用 token（4 的倍数）——避免页面级手算像素 |

## 6. 验收挂钩（本规范怎么被"验收"而不是"声称"）

| 检查 | 方式 |
|---|---|
| L1/L2 被真实消费 | 两端构建产物含 `styles/global.css` 的类（MP：`app.wxss`；Web：构建输出） |
| 无裸色值 | `check:host-rounding` 之外，本工程以"页面 CSS 只用 var(--sa-*)"为纪律（评审检查） |
| 页面模式落地 | 各页面按 §4 骨架写；`verify.vue` 为控制台模式的参考实现 |
| **验收模块**（八条场景） | `pages/verify.vue` 逐条触发 + 读数；自动化 e2e 复用 `tests/e2e-mp-gp5` 的模式 |

# 架构更新（G-55）

## 泛化定位（不占泛化序）

> **「不绑定性能载体」**：性能内聚于内核（常驻 + 增量），
> 不依赖宿主编辑器的选型。

第 18 次泛化（G-54）解决了"形态不绑定"（不绑定 IDE 形态），
G-55 补上**性能维度**——证明"不绑定"与"高性能第一原则"不冲突，
前提是性能责任放在内核而非宿主。

> **不占泛化序（沿 G-37→G-27 / G-38→G-29 先例：实现落地不占泛化序）**——本份是 G-54 的工程落地：内核按 G-54.1 唯一实现、宿主适配器可插拔；若计为新泛化，单实现的"性能载体"反而构成假 SPI（AP-01）。原稿误作"第 16 次泛化"（基于旧序计数），决策 #392 修正；官方泛化数维持 **18 次**。

## 新增原则

- **#13.63** 性能内聚于内核：宿主选型不决定框架工具的性能上限
- **#13.64** 确定性优先于精确性：CI 断言用计数，墙钟仅观测
- **#13.65** 接口冻结是可验证的架构契约（内核 API 冻结 = 分层证明）

## 成熟度模型

```
L0 文档自检       G-50
L1 IR 模拟        G-51
L2 真运行时       G-51 + G-52
L3 跨设备         G-52 / G-53
L4 编码期集成     G-54 + G-55  ← 本份
L5 开放生态       G-50（依赖 G-49 L3）
```

G-55 将开发者工具推至 **L4 编码期集成**：
能力定义（G-54）+ 落地形态与性能工程（G-55）闭合。

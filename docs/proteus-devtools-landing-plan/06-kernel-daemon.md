# G-55 内核守护进程设计

## 1. 生命周期

```
首次调用 → 启动 daemon（冷启动，全量索引）
         → 常驻内存
文件变更 → 增量索引（只算受影响子图）
         → 精确缓存失效
查询     → 内存命中 / 未命中则重算并缓存
空闲超时 → 可退出（或保持常驻）
```

## 2. 增量索引算法

```
changed  = 变更文件集合
affected = changed ∪ reverseDeps(changed)
touched  = |affected|
```

**复杂度 O(|affected|)，不是 O(N)。** 改一个文件不该重扫全项目。

反向依赖表由依赖图维护，文件 deps 变更时同步更新。

## 3. 缓存结构

```
key    = 能力 + 参数（含激活后端）
value  = 计算结果
deps   = 该结果依赖的文件集合   ← 精确失效的关键
used   = 逻辑时钟（LRU 用）
```

## 4. 并发与隔离

- 索引与查询分离：索引期间查询可返回旧值（标注 `stale`），不阻塞
- 多工作区：每个工作区独立索引命名空间，互不污染
- 内核崩溃不得拖垮宿主：宿主侧捕获异常 → 降级为纯 LSP 基础能力

## 5. 语言选型的真实权衡

| 语言 | 性能 | 工程成本 | 结论 |
|------|------|---------|------|
| **Rust** | ★★★★★ | 高 | 推荐，但要评估团队能力 |
| Go | ★★★★ | 中 | 可接受替代，性能差一档 |
| Node | ★★ | 低 | **不推荐**：CPU 密集 + 大内存索引是弱项 |

**Rust 不是教条。** 若团队无 Rust 能力，用 Go 换工程成本是合理的，
只是要相应下调预算目标并在文档标注。

## 6. 分层规则语义

```
diff = rank(被依赖方) - rank(依赖方)

diff > 1  → SKIP_LAYER（跨级上依赖，如 L0 直连 L2）
diff > 0  → UPWARD    （低层依赖高层）
diff <= 0 → 合法      （同层或向下依赖，含跨级向下）
```

**向下依赖（含 L2 直连 L0）合法**——高层用低层是分层的本意。
被禁止的是**向上**：核心层不得反向依赖宿主层。

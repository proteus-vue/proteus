# G-55 铁律

## G-55.1 — 绝不 fork 编辑器

宿主层只写适配器。fork 的收益（编辑器运行时状态）我们不需要，
代价（安全滞后、维护成本、生态缺失）全额承担。

## G-55.2 — 适配器只做翻译，零业务逻辑

违反后果：每换一个 IDE 就行为分歧，内核唯一性失效。

## G-55.3 — 内核常驻，索引增量

改一个文件只重算受影响子图。全量重扫是性能事故。

## G-55.4 — 缓存失效精确到 deps

全清空会让增量索引退化成每次全量，预算 2 直接失效。

## G-55.5 — 内核 API 冻结

新增宿主适配器不得改动 `KnowledgeProvider`。
需改内核 = 分层失败，必须重构而非绕过。

## G-55.6 — 性能断言必须确定性

**计数断言阻断，墙钟断言仅 warn。**
会随机变红的 CI 断言比没有断言更糟——团队会学会无视红色。

## G-55.7 — 数字不虚报

预算值标注为"目标"（来自公开 benchmark 对标）。
对外宣称任何性能数字前必须实测（G-37）。

## G-55.8 — 宿主缺能力是常态，不是错误

❌ 能力 → SKIP + 覆盖率标注，不报错、不阻断。

## 反模式

- **AP-PF-01** fork 编辑器换取"深度集成"——收益不成立，代价全额
- **AP-PF-02** 在适配器里写业务逻辑——多宿主行为分歧
- **AP-PF-03** 文件变更触发全量重扫——增量索引形同虚设
- **AP-PF-04** 缓存全清空式失效——同上
- **AP-PF-05** 为接新宿主改内核——分层已失败的信号
- **AP-PF-06** 用墙钟时间做 CI 阻断断言——必然 flaky
- **AP-PF-07** 未实测就对外宣称性能数字——违反 G-37

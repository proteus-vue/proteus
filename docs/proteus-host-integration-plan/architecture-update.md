# 规约增量变更（G-41）

> 合并进 `proteus-architecture` 的增量部分。

---

## 1. 新增原则

| 编号 | 条文 |
|------|------|
| **#13.15** | **宿主接入必须有组合验证**：单插槽 conformance 通过，不等于三方组合正确。必须有跨层的 Host Conformance（G-41 的 H-01~H-08） |
| **#13.16** | **绑定层必须插槽化**：框架与前端框架（Vue）的绑定必须通过 nodeOps 等标准插槽，禁止直接依赖具体渲染实现 |
| **#13.17** | **注册先于启动**：宿主必须在 bootstrap 前完成 Runtime / Carrier / Backend / Capability 全部注册 |

**#13.15 是原则 #11 的第五次兑现**（G-27 渲染 → G-38 编译 → G-39 运行时 → G-40 载体 → G-41 接入），证明它不是一次性规则，而是架构级不变量。

## 2. 架构全景图（更新至六层 + 三方）

```
┌─────────────────────────────────────────────────────────┐
│ L0  业务应用       128 语义原语（G-31/32）                │

┌─────────────────────────────────────────────────────────┐

                       ↓ 运行在

│                    JSI / AOT / WASM                      │
└──────────────────────┬──────────────────────────────────┘
                       ↓ 由
┌─────────────────────────────────────────────────────────┐
│ L4  宿主运行时     HostRuntime（G-39）                    │

                       ↓ 承载
```

**三方正交关系：**

```
框架 Core  ×  渲染引擎  ×  宿主  =  三者自由组合
   （定义插槽）  （实现渲染）  （提供环境）
```

## 5. 路线图落点

| 里程碑 | G-41 内容 |
|--------|----------|
| **M1** | B1（Dispatcher 契约）+ B2（Host Conformance）——与 G-27/35/36/37 B1 同批，都是"定义 SPI shape" |
| **M2** | B3（Vue 绑定实现）+ B4（五宿主接入）+ B5（热切换/混合渲染） |
| **M3** | B6（宿主 × 引擎组合矩阵验证） |

**M1 的五个 B1 是同一批**：G-27 nodeOps、G-38 CompilerIR、G-39 HostRuntime、G-40 Carrier、G-41 Dispatcher——**五者互相依赖，必须同批定义**。

## 6. 风险边界

| 边界 | 说明 |
|------|------|
| 不改 Vue 编译器 | Vue 编译器是稳定公共资产，改造风险高于收益 |
| 不承诺所有组合可用 | 36 组合中仅 Tier 1 组合（约 25 个）承诺验证 |
| 不承诺热切换零成本 | 重建开销 O(n)，由 Backend 决定 |
| 不要求宿主支持全部引擎 | Tier 2/3 宿主可只支持部分（capabilities 声明） |

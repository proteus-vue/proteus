## 5. 接缝命题

### 5.1 与 G-55 架构试金石接缝

```
G-55 INV（三宿主不改内核） ∧ G-56 INV-ST-01（自有宿主不改内核）
   ⇒ 内核对"自有"与"第三方"宿主一视同仁
```

**这条最关键**：自有宿主最容易获得"开后门"的诱惑。**恰恰是这种情形最能验证分层真伪。**

### 5.2 与 G-53/G-54 设备链接缝

```
G-53 DeviceBridge ∧ G-56 视频通道扩展
   ⇒ 四个宿主共用同一设备抽象，画面来源对宿主透明
```

### 5.3 与 G-51 降级语义接缝

```
G-51 INV-02（能力缺失 → 降级 ≠ 崩溃）
   ∧ G-56 INV-ST-05（嵌入失败 → 降级）
   ⇒ 降级语义从"验证执行"推广到"宿主形态"
```

## 6. 已验证项 vs 未验证项

### ✅ 已验证（reference-impl.cjs 可跑）

- 八条不变量的逻辑正确性
- 降级链五档决策
- 能力边界矩阵决策断言
- 归一化坐标拒绝
- 风险上报诚实性
- 架构试金石快照比对
- 9 条负向用例

### ❌ 未验证（诚实标注）

| 项 | 原因 |
|----|------|
| libmpv 离屏 FBO 真嵌入 | 需 PoC，无验证环境 |
| Tauri 2 移动端性能 | 无实测设备 |
| iOS 跨 App inspect | 无先例，需探索 |
| Linux WebKitGTK 风险触发率 | 无 Linux + NVIDIA 环境 |
| Tauri 性能数字（3.2MB/380ms/42MB） | **框架级 benchmark，非 Proteus 实测** |

> **按 G-55.7 纪律：未实测的性能数字不得对外宣称。**

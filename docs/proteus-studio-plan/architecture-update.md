# 架构更新（G-56）

> 新增原则 #13.66 ~ #13.68，成熟度模型更新。

---

## 1. 新增原则

### #13.66 — 自有宿主不享有特权

> 宿主可以是第三方（VSCode / IntelliJ / Zed），也可以是自有的（Studio）。
> **内核对两者一视同仁，不做任何特化。**

这是 #13.61「不绑定 IDE 形态」的完备化——
**证明"不绑定"在"自有宿主"这个最容易产生诱惑的极端情形下依然成立。**

### #13.67 — 自研编排，集成组件

> 编辑器、终端、解码器、GUI 框架一律集成；
> 自研仅限：知识内核、面板 UI、编排层。

**判断依据不是"能不能做"，而是"做了会不会掉进维护陷阱"。**

### #13.68 — 移动端是宿主的一等形态

> 调试界面不应只在桌面上存在。
> 真实用户设备上应当能直接查看运行时自检结果。

## 7. 下一步建议

**不要一开始做移动端伴侣**——它是风险最高、先例最少的部分。

```
阶段 1  Studio 桌面版（编辑器 + 终端 + 设备嵌入）
阶段 2  Linux 降级链 + libmpv PoC 验证
阶段 3  ★ 伴侣模式（先 companion.sdk，一定能做成）
```

**阶段 2 的 libmpv PoC 是决定性的**——它决定了 device.native 这个"唯一 ✅"是否真的成立。
若 PoC 失败，Studio 的独特价值就只剩 form.mobile。

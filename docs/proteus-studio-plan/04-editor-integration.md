# G-56 编辑器与组件集成

> 原则：**自研编排，集成组件。**
> 本章记录三个关键组件的集成方案与决策依据。

---

## 1. 编辑器：CodeMirror 6

### 1.1 为什么不是 Monaco

| 维度 | CodeMirror 6 | Monaco |
|------|--------------|--------|
| 体积 | **~50 KB** | 2-5 MB |
| **移动端** | ✅ 可运行 | ❌ 不支持 |
| 框架耦合 | 无 | 与 VSCode 强耦合 |
| 生产验证 | **Replit 生产环境** | VSCode |

**决定性因素是移动端，不是体积。**

Monaco 在手机上跑不了，而**移动端伴侣是本份的独特价值**。选 Monaco 等于提前放弃这条。

### 1.2 复用收益

CodeMirror 6 同时用于：

```
Studio 编辑器面板  ┐
Web 版 DevTools    ┘  一份组件，两处使用
```

这与 G-55 的 Web 兜底档天然对齐——**Web 版 DevTools 和 Studio 的编辑器是同一个组件**。

### 1.3 集成要点

| 项 | 方案 |
|----|------|
| LSP 接入 | `codemirror-languageserver` 插件，复用内核 LSP |
| 诊断内联 | G-54 能力 3（断言内联）直接映射到 CM6 linter API |
| 语义跳转 | 复用内核 RPC，与 G-54 行为一致 |
| gutter icon | CM6 gutter API，对齐 Zed 的实现 |

## 2. 终端：xterm.js + portable-pty

### 2.1 选型依据

| 项目 | 状态 |
|------|------|
| **Terax** | Tauri 2 终端，**已上线** |
| `tauri-plugin-pty` | 现成插件 |
| xterm.js | 事实标准 |

**有生产先例，不需要自研。**

### 2.2 集成要点

```rust
// portable-pty 提供跨平台 pty
let pty = native_pty_system().openpty(PtySize{..})?;
// xterm.js 前端渲染，通过 Tauri IPC 传输
```

**关键点**：pty 在 **Rust 侧**（真正子进程），xterm.js 只在前端渲染——**这不是终端模拟器，是真终端**。

> 这比 IntelliJ/VSCode 的内置终端在架构上更干净：两者都是真 pty，但 Studio 可以直接把 pty 输出接到内核做结构化解析（而不只是显示文本）。

### 2.3 Studio 专属增强：结构化输出

**三个宿主的终端输出都只是文本流。** Studio 可以做得更多：

```
pty 输出 → 内核结构化解析 → 断言结果面板联动
```

例如 conformance 失败时，**终端里的失败行可以直接点击跳转到源码**——这是 console.custom 能力在 Studio 上的自然延伸。

## 3. 模拟器嵌入：libmpv

### 3.1 为什么是 mpv

| 方案 | 评价 |
|------|------|
| **libmpv `--wid`** | 三平台实证（Windows HWND / Linux Xlib / macOS NSView） |
| **libmpv 离屏 FBO** | **真嵌入**，非"跟随父窗口移动" |
| VLC | 体积大，嵌入 API 不如 mpv |
| 自研解码 | 🚫 禁区 |

### 3.2 ⚠️ 必须注意的坑：≠ 真嵌入

社区有反馈：**mpv-tauri 的部分实现并非真嵌入，只是"跟随父窗口移动"。**

**真嵌入必须走离屏路径**：

```
libmpv vo=libmpv (离屏渲染) → FBO → 宿主画布合成
```

这条路径我核到过实践记录但**未验证**。实施时必须先做 PoC 确认，不能默认可行。

### 3.3 三平台路径

| 平台 | `--wid` 类型 | 备注 |
|------|-------------|------|
| Windows | `HWND` | 稳定 |
| macOS | `NSView` | 稳定 |
| Linux X11 | `Xlib Window ID` | 可用 |
| **Linux Wayland** | ❌ | **无窗口句柄概念 → 降级到独立窗口** |

### 3.4 视频源

```
iOS Simulator  : serve-sim (simctl io → MJPEG/H.264)
Android        : adb screenrecord / scrcpy 流
真机           : 云真机平台流
```

**统一抽象为 `StreamEndpoint`**，宿主不关心来源——这正是 G-53 `DeviceBridge` 的价值。

## 4. 三个组件的关系

```
┌───────────────────────────────────────┐
│  Proteus Studio (Tauri 2 壳)           │
│  ┌─────────┬──────────┬────────────┐  │
│  │ CM6     │ xterm.js │ libmpv     │  │
│  │ 编辑器   │ + pty    │ 设备画面    │  │
│  └────┬────┴────┬─────┴─────┬──────┘  │
│       │         │           │         │
│       └─────────┼───────────┘         │
│                 ▼                     │
│        ┌─────────────────┐            │
│        │ 编排层（自研）    │            │
│        └────────┬────────┘            │
│                 ▼                     │
│        ┌─────────────────┐            │
│        │ 内核（G-55 复用） │            │
│        └─────────────────┘            │
└───────────────────────────────────────┘
```

**三个组件彼此独立，只通过编排层与内核通信。** 任一组件可替换而不影响架构。

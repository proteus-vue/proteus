# G-60 铁律

## G-60.1 — API 文档必须是 renderer，不是副本（红线）

插件 API 参考页**一律由 WIT 生成**。
任何"手写 API 签名/参数表/返回值"的行为，**在 review 阶段直接拒绝**。

允许手写的只有：为什么、怎么做、边界（P4：机器不知道的部分）。

> 判据：一段内容若**能从 WIT 推导出来**，它就不该手写。

## G-60.2 — 漂移即阻断，不警告

`checkDrift()` 返回 `stale` 时 CI **必须失败**。

理由沿用 G-59 的论证：警告会被忽略，个体理性导致集体劣化，
**只有硬拒绝能把成本内部化**。

## G-60.3 — 未知版本返回 null，禁止静默降级

用户点的是旧链接。静默跳到新版会让他**以为看的就是目标版本**，
然后按新版 API 写代码、跑在旧版上报错。

与 G-51 的 `SKIP ≠ PASS` 同源：**"没有答案"和"答案是最新"是两回事。**

## G-60.4 — 未命中即未命中，不猜测

`resolve()` 与 `pick()` 未命中一律返回 `null`。

> 错误的下载比没有下载更危险——用户装上跑不起来的包，会归咎于产品质量。

## G-60.5 — 版本无关内容单一源

`/shared` 目录 + transclusion。**禁止跨版本复制**。

> 复制 N 份 = 绑定 N 次（原则 #0）。

## G-60.6 — 废弃标记元数据驱动

版本状态存 `versions.json`，横幅与 `noindex` 由构建系统注入。
**禁止手工编辑 markdown 加废弃标记**（P2.4：必然漏页、口径不一致）。

## G-60.7 — 数字不粉饰（★ 官网专项）

官网是**对外宣称的出口**，天然倾向把数字写好看。

- 所有性能数字**必须标注"目标"或"实测"**
- 未实测的**一律标为目标**，不得删除标注后对外发布
- 数字审计接入 CI（阶段 5）

> G-37 说"未实测不宣称"。官网是最容易破例的地方，故单列铁律。

## G-60.8 — 更新私钥不可恢复，先备份再生成

> if you lose this key, you will NOT be able to publish new updates to your current user base.

- 私钥永不入仓库，存 CI secret
- **离线冷备份，异地多份**
- 轮换后**旧公钥必须继续保留在旧版本 app 内**
- 正确顺序：**先建备份流程，再生成第一把私钥**

这是全套体系中**唯一不可逆**的风险，其余都可以重来。

## G-60.9 — 删除页面等于制造 404

已发布的文档 URL 一旦进入别人的书签和搜索引擎，就应当**永久可访问**。

- 已移除 API **保留页面**，标注 `removed in X.Y`
- 版本归档只加 `noindex`，不删文件

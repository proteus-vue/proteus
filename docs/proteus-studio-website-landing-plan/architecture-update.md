# 架构更新（G-60）

## 新增原则

- **#13.80** 文档即契约：对外文档与代码同等地位，漂移等同缺陷
- **#13.81** 参考页是 renderer：可推导内容一律生成，人只写不可推导部分
- **#13.82** 版本可寻址：任何已发布 URL 永久可访问，删除即破坏外链
- **#13.83** 宣称可验证：对外数字必须带"目标/实测"标注（G-37 的官网延伸）

## 第 23 次泛化：不绑定文档形态

```
不绑定后端 → 不绑定环境 → 不绑定设备 → 不绑定编辑器
   → 不绑定宿主来源 → 不绑定可观测性来源 → 不绑定扩展来源
   → ★ 不绑定文档形态
```

**含义**：文档不被"手写在哪"绑定。
API 参考由 spec 生成，指南由人书写，共享内容单一源引用——
三者形态不同，但都指向同一份事实。

> **官方序注（决策 #397）**：本份为第 **23** 次（前承：G-54=18 IDE 形态、G-56=19 宿主来源、G-57=20 可观测性来源、G-58=21 扩展来源、G-59=22 生态治理模式；G-55 为 G-54 落地不占序）。原稿误作第 19 次。

## 成熟度模型更新

官网/文档侧独立成一条成熟度线：

```
L0  静态页 + 手写文档     ← 行业默认，漂移高发态
L1  版本化 + 元数据驱动横幅
L2  ★ API 文档生成 + 漂移阻断   ← 本份目标
L3  插件市场 + 性能预算公示看板
```

与既有 L0-L6（验证成熟度）并列，**不合并**——
两者度量的对象不同：一个是"验证可信度"，一个是"文档可信度"。

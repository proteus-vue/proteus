## 三、冻结协议（改动必须走这条路）

> ★守卫测试红了 = 有人动了冻结值。**不要**直接改测试里的期望值——那是把守卫变成橡皮章。

1. **新决策号**（decisions.md 追加，注明为什么动冻结值 + 新验收判据）；
2. 改 `glass.wgsl` + `reference.rs`（**必须同源**，本仓 parity 门禁会抓漂移）；
3. `node scripts/gen-shaders.mjs`（重生成四端产物）；
4. `bash hosts/ios/check-glass-pixel-parity.sh`（**四态 max 1/255**）；
5. `pnpm check:shader-generated`（四端无漂移）；
6. **更新守卫测试** `tests/glass-frozen-model.test.ts` 的对应定稿值（同步改名/改值 + 注明新决策号）；
7. **真机复测**（双态截图对比本文表格；新值写回本节）；
8. 三端重跑（若动到跨端面）。

### 已知的"下一档"边界（护栏值 · 手滑前先读）

- **白端**：条面已到屏幕极限 **255**（再推只会裁平；#1018 起头寸用尽）。
- **透射率**：**32%（亮）/ 38%（暗）**已低——接近"内容不可见"区（≲25%）。继续推 = 从"通透玻璃"滑向"实心霜面"，
  建议先真机滚动场景目视内容流动（#1021 已在决策里登记此护栏）。
- **胶囊对比**：Δ28/Δ50——继续拉会让胶囊从"灰药丸"变"实心色块"（iOS 原版 Δ18/34）。

## 四、诚实边界

1. **iOS/鸿蒙真机未逐项复测**：算法真源同源、生成物已同步（`check:shader-generated` 绿），parity 在 macOS Metal 上验证
   了落地等价（四态 max 1/255）；但 iOS/鸿蒙的宿主链（背板捕获口径）差异未做逐端验收。
2. **宿主预模糊只在 Android 落地**（#1015）：iOS 架构本就"先糊背板再采样"（本修是向它对齐）；鸿蒙宿主链同 Android 模式。
3. **两态校准口径 = 白卡/纯黑内容**（用户场景）；彩色/中灰内容上的碗形（#1006 边缘效应）行为保留未动。
4. **色彩管理残差 ±2 级**（真机 vs iOS 截图的屏幕色彩管理成分，不追）。

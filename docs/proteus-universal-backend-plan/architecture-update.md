## 1. 新增章节

### §X. 任意端接入（G-30）

**位置**：置于 G-27 / G-28 / G-29 之后，作为"四层可插拔"的**泛化证明**。

#### X.1 端的形式化定义

```
Platform = (R, C, J)

R: 渲染宿主 → ProteusRenderBackend (G-27)
C: 能力宿主 → ProteusNativeBackend (G-28)
J: JS 运行时 → JSI
```

#### X.2 接入等级（Tier）

| Tier | 条件 | 说明 |
|------|------|------|
| 1 | R + C + J | 一等公民 |
| 2 | 缺 J 或 缺 C | 受限可用（编译期裁剪） |
| 3 | 仅 R | 纯渲染 |
| 4 | 仅 J | Headless / SSR / AI |

#### X.3 铁律（详见 `rules.md`）

- G-30.1 单一 IR 约束
- G-30.2 开放封闭
- G-30.3 显式能力声明
- G-30.4 降级可见

## 2. 原则更新

**原则 #10**（原）：统一语义 + 后端实现（渲染、原生能力）

**原则 #10**（新，G-30 后）：统一语义 + 后端实现，**对任意端成立**。

> 任何满足"渲染宿主 + 能力宿主 + JS 运行时"三元组之一的平台，均可通过实现 Backend 接入 Proteus；缺失维度通过 Tier 显式降级，禁止隐式失败。

## 6. 风险边界（明确不承诺）

- 纯后端服务（非"端"）→ 不在 scope
- 无 JS 且无渲染的裸 MCU → 不在 scope
- 强实时/强安全隔离（航空、医疗）→ 走原生
- 封闭生态不允许嵌入 JS → Tier 3 纯渲染

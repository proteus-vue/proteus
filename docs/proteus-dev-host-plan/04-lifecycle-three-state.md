> **定位**：原则 #0「不绑定」第九次泛化的**完整性补丁**——把"双层产物"升级为"三态生命周期"

## 0. 动机：机制四的缺口

G-45 主文档「双层产物」拆开了稳定层（基座）与变化层（JS + 插件模块），实现了开发态的秒级热更。但**只覆盖了"开发态"一态**。

现实交付有三个截然不同的阶段，各自受不同的**硬约束**：

| 阶段 | 核心诉求 | 硬约束来源 |
|------|---------|-----------|
| **开发态** | 改了立刻生效 | 无审核约束，追求速度 |
| **发布态** | 进商店、可分发 | **应用商店审核规则** |
| **运行态** | 已上线后做灰度 | **禁止下发可执行代码** |

把三态混为一谈，是 G-45 被质疑"iOS 怎么做到"的根本原因。**本文件把三态显式建模，每一态都用合规的方式达成"不重打基座"的目标。**

## 1. 三态生命周期

```
┌─────────────────────────────────────────────────────────────┐
│  开发态 (dev)                                                │
│  ─────────────────────────────────────────                    │
│  • 全热替换：Android DexClassLoader / 鸿蒙 HSP / iOS 模拟器   │
│  • dev server push 插件模块（秒级）                          │
│  • 签名：开发证书（可自签）                                 │
│  • pending 回放 + conformance 快检（NAT-C）                  │
│  • 基座 0 次重打，JS 上下文 0 次重启  ← G-45 主机制已解决    │
└──────────────────────┬──────────────────────────────────────┘
                       │ 发布构建（一次，非每次改动）
                       ↓
┌─────────────────────────────────────────────────────────────┐
│  发布态 (release)                                            │
│  ─────────────────────────────────────────                  │
│  • 稳定层静态链接（基座 + 所有插件 ABI 冻结）               │
│  • 插件声明预注册（manifest 编译期校验）                    │
│  • cacheKey = hash(框架版本 + ABI)  ← 与业务规模无关         │
│  • 产物：合规的 apk / ipa / hap                             │
│  • ★ 复用 G-39 HostRuntime SPI + G-42 容器 SPI 作为         │
│         ABI 版本管理的契约对象                               │
└──────────────────────┬──────────────────────────────────────┘
                       │ 商店审核通过，安装到设备
                       ↓
┌─────────────────────────────────────────────────────────────┐
│  运行态 (runtime)                                            │
│  ─────────────────────────────────────────                  │
│  • 能力灰度开关（Remote Config）—— 非代码下发               │
│  • 降级后端兜底（G-45 机制三 / 原则 #4 降级不崩溃）         │
│  • 插件模块：仅限**声明过的、已链接的能力**做参数灰度        │
│  • 禁止：下载并执行新原生代码                                │
└─────────────────────────────────────────────────────────────┘
```

**关键洞察**：发布态的"稳定层 ABI 冻结"**不需要发明新接口**——G-39 宿主运行时 SPI 和 G-42 容器 SPI 定义的正是"稳定层契约"。G-45 复用这两层定义的稳定接口作为 ABI 版本管理的对象。

## 2. 状态转换协议

### 2.1 dev → release：发布构建

```
collectManifests()            // 收集所有插件 manifest
  → validateABICompat()      // 校验插件 ABI 与基座版本兼容
  → freezeStableLayer()      // 基座 + 兼容插件静态链接
  → generateArtifactHash()   // 产物哈希，用于升级校验
  → emitComplianceReport()   // 合规报告（声明所有原生能力来源）
```

**ABI 兼容性校验规则**：

| 规则 | 说明 |
|------|------|
| `abi.major` 必须一致 | 基座与插件的主版本不一致 → 拒绝链接 |
| `abi.minor` 向后兼容 | 插件 minor ≤ 基座 minor 可链接 |
| `abi.features` 子集 | 插件声明的 feature 必须是基座 expose 的子集 |
| `signature.chain` 同源 | 插件签名证书链必须与基座同源（见 `rules.md` G-45.7） |

### 2.2 release → runtime：仅参数灰度

上线后**不允许新增能力**，只允许**已链接能力的参数调整**：

```yaml
# remote-config.yaml（合法：参数灰度，非代码）
features:
  glass_material:
    enabled: true           # 开关
    level: L2               # 参数调整
  video_stream:
    enabled: false          # 降级关闭
```

```yaml
# ❌ 禁止：运行时引入新原生能力
modules:
  - name: new_native_plugin  # ← 未预注册，禁止动态加载
    url: https://cdn.example.com/plugin.so
```

### 2.3 三态不可越界

| 越界操作 | 结果 |
|----------|------|
| release 态尝试热加载新插件 | **拒绝装载**（conformance 门禁） |
| runtime 态下载可执行代码 | **拒绝执行**（合规铁律 G-45.6/8） |
| dev 态使用发布签名 | **拒绝推送**（签名校验） |

## 3. ABI 冻结协议（详见 `05-abi-versioning.md`）

### 3.1 什么是"ABI"

在 Proteus 语境下，**ABI = 稳定层对插件暴露的契约**，包含：

- **接口形状**：NativeBackend SPI 的方法签名（G-28）
- **数据类型布局**：跨边界传递的结构体字段（G-43 所有权模型的 `Owned<T>` 内存布局）
- **能力枚举**：BackendCapabilities 的 capability key 集合
- **版本号**：`abi.major.minor`

### 3.2 冻结时机

```
开发期：ABI 浮动（插件可演进接口）
    ↓ 发布构建触发
冻结点：abi.major 锁定，写入产物 manifest
    ↓
运行期：ABI 只读，任何变更需走"下一版本发布"
```

### 3.3 向后兼容策略

| 变更类型 | major | minor | 兼容策略 |
|---------|-------|-------|---------|
| 新增可选 capability | 不变 | +1 | 旧基座可忽略 |
| 修改既有接口签名 | +1 | 0 | **破坏性变更，需新版本** |
| 删除 capability | +1 | 0 | 破坏性变更 |
| 新增字段（末尾） | 不变 | +1 | 旧插件忽略新字段 |

## 4. 平台差异（诚实边界）

| 平台 | 开发态热替换 | 发布态 | 运行态灰度 |
|------|------------|--------|-----------|
| Android | DexClassLoader（可写→只读演进） | 静态链接 / App Bundle | Remote Config |
| 鸿蒙 | HSP 动态共享包（**应用内共享，须随宿主打包**） | 静态链接 | Remote Config |
| iOS | 模拟器全热替换；真机**增量重签** | 静态链接（App Store 2.5.2） | 能力开关（非代码） |
| Web | HMR（原生支持） | 静态产物 | Feature Flag |

**鸿蒙 HSP 官方限制**：主要支持应用内共享，须随宿主一起打包，不能独立分发。**这印证了"发布态必须静态链接"的结论——动态加载本质是调试/内部分发通道。**

## 5. 与既有体系的关系

```
G-39 HostRuntime SPI ──→  ABI 契约对象（稳定层接口定义）
G-42 容器 SPI      ──→  ABI 契约对象（容器能力边界）
G-43 所有权        ──→  跨边界数据布局（Owned<T> 内存约定）
G-44 测试          ──→  ABI 兼容性校验的 conformance 用例
G-45 主文档        ──→  本文件补全"发布态/运行态"两态
```

**G-45 的完整语义 = 三态 × 四件套。**

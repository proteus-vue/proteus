# SPI-First 工程方法论

> **把"拆分量化、逐个攻破、迁移复用"从经验升为方法。**
> **Proteus 体系的元方法论（Meta-Methodology）。**

---

## 这是什么

Proteus 在成长中重复应用了同一种拆分手法九次（G-27 → G-45）。把动作抽出来、剥离 Proteus 依赖，得到一套**不依附于任何具体系统、可套用到任何大工程的通用工程方法论**。

核心理念：

> **找到系统中所有"换 X 要改很多文件"的 X，把它们逐一提升为"语义接口 + ≥2 后端 + conformance + 诚实边界"，直到业务层对任何具体实现零知识。**

---

## 五步法（概览）

| Step | 名称 | 一句话 |
|------|------|--------|
| 1 | 找耦合点 | grep 具体实现名，出现 ≥2 文件 = 候选 |
| 2 | 语义收敛 | 接口只用业务语言，禁用技术名词 |
| 3 | 可插拔后端 | ≥2 个后端，含 Mock/Headless |
| 4 | conformance | 同一份测试，对所有后端都可判定 |
| 5 | 诚实边界 | 声明性能 / 能力 / 适用三条边界 |

## 快速开始（30 秒）

1. 打开 `cheatsheet.md`，打印或贴工位
2. 在你的项目根目录跑：
   ```bash
   grep -rc "<具体SDK名>" . | sort -t: -k2 -rn | head -20
   ```
3. 把出现次数 ≥ 2 的填进 `coupling-audit-template.md`
4. 对每个 P0 候选，按五步法改造
5. 完成后对照 `anti-patterns.md` 自检

# G-47 组合一致性 Conformance（Combined Consistency）

> **一句话**：G-27（外·渲染）与 G-46（内·资源）各自 conformance 通过，**不等于二者组合后正确**——G-47 专治跨层交界处的静默失败。
>
> **方法论定位**：原则 #0「不绑定」系列第十一次投影的**验证层应用**——不绑定"测试层级"（单层测试 → 组合测试）。是 G-44 INT 系列的正式扩展。

---

## 1. 问题：为什么单层 PASS 不够

G-27 的 conformance 验证"**一个渲染后端内部渲染正确**"；G-46 的 conformance 验证"**资源池本身正确**"。二者各自绿，**交界处仍可静默失败**。

### 1.1 三类交界处漏洞（G-47 要抓的）

| 漏洞 | 表现 | 单层测试能否抓到 |
|------|------|----------------|
| **L1：会话字段丢失** | Compiler 产出 IR 时未把"当前会话"传给 Render Backend → 切后端后登录态丢 | ❌ G-27/G-46 各自绿 |
| **L2：后端私有资源** | Flutter Backend 不读共享 ResourcePool，自维护空 Token → 业务侧已登出而渲染侧不知 | ❌ |
| **L3：竞态** | 切后端瞬间恰触发登出 → 清理与切换谁先谁后，最终态不确定 | ❌ |

**这是「内外一致性」闭环的最后一块**：G-27 解决外（渲染后端可插拔），G-46 解决内（登录态/请求/缓存共享），**G-47 证明二者组合后"切后端时数据链不断"**。

### 1.2 与既有体系的关系

```
G-27 渲染后端 SPI ────┐
                       ├── 组合点 → ★ G-47 Combined Conformance
G-46 资源池 SPI  ─────┘
                       ↓
G-44 Test IR（INT 系列）← G-47 是 INT-06~INT-0N 的载体
                       ↓
G-44 统一 runner（测试结果标准化）
```

**关键**：G-47 **复用 G-46 ResourcePool + G-27 Backend SPI**，不发明新抽象——它是**对既有两层的组合断言**。

## 2. 核心：六个跨层不变量（Invariants）

组合正确性不靠"跑通示例"，靠**机器断言的不变量**：

| 编号 | 不变量 | 直觉 |
|------|--------|------|
| **INV-01** | 切后端后登录态不丢（Cookie / Token 跨 Backend 等价） | 切引擎 ≠ 重新登录 |
| **INV-02** | 切后端后缓存命中不丢 | 切引擎 ≠ 重新加载 |
| **INV-03** | 登出 × 切后端**串行**，最终态一致（交换律） | 顺序无关 |
| **INV-04** | 并发切后端 + 并发读写资源 → 不崩溃、最终一致 | 竞态安全 |
| **INV-05** | 同一 IR 在两后端产出的资源视图一致 | SPI 语义等价（G-27.4） |
| **INV-06** | 后端不可用时降级不崩溃 | 原则 #4 |

---

## 3. 设计原则

| 原则 | 说明 |
|------|------|
| **P1：资源归宿主，后端借用**（OWN-06） | 登录态/Cookie/Token 存于共享 ResourcePool，**不属于任何 Backend**；Backend unmount 不销毁资源 |
| **P2：后端只读不写池**（单向依赖） | Backend 通过 `readAuth()` 读池，**不缓存副本**；写操作走池的唯一入口 |
| **P3：可插拔 + conformance** | 任何新 Backend 必须过 G-47 六不变量才能接入 |
| **P4：降级不崩溃** | 不可用后端 → 装载失败 + 回退后端兜底（INV-06） |

---

## 4. 诚实边界

1. 当前为**可运行模拟**（node 环境），Android/iOS/鸿蒙真实桥接的并发语义待 B3 验证
2. **多进程场景**（同一 App 多进程各持 Backend）的跨进程资源协调**未覆盖**——已知缺口
3. 六不变量是**正确性底线**，不承诺"切换 0 帧闪烁"等性能目标（属 G-22 柔性布局范畴）

# G-47 架构：组合一致性 Conformance

## 1. 测试金字塔中的位置

```
              /\
             /E2E\         （业务场景：真实切换全流程）
            /──────\        ←  G-47 在此层（跨层组合）
           / INTEG  \       Compiler→Render→Pool 全链路
          /──────────\      ←  G-46 / G-27 单层 conformance
         /  UNIT/SPI  \     ResourcePool / Backend 各自
        /──────────────\    属性测试
```

**G-47 是金字塔中上层的"接缝测试"**——专门覆盖层与层之间的接口，这是单元测试覆盖不到、E2E 又过于昂贵的部分。

## 2. 组合点抽象

```
┌────────────────────────────────────────────┐
│  业务组件（.vue）                           │
└────────────────┬───────────────────────────┘
                 ↓ 编译
┌────────────────────────────────────────────┐
│  统一 Render IR                            │
│  （p-grid / pg-glass / ... / ★ sessionRef） │  ← INV-05：IR 含会话引用
└────────┬───────────────────┬───────────────┘
         ↓                   ↓
┌──────────────┐   ┌──────────────────────┐
│ RenderBackend│   │   ResourcePool (G-46) │
│ VueDom/      │──→│  L1 Cookie/Token     │
│ Flutter/     │   │  L2 Request          │
│ Native/...   │   │  L3 Cache            │
└──────────────┘   └──────────────────────┘
   ↑                   ↑
   └── 通过 readAuth() 读共享池（P2 单向依赖）
```

**关键契约**：Backend **只通过 `readAuth(domain, origin)` 读池**，不持有资源副本。这是 INV-01/02 成立的架构前提。

## 3. 测试矩阵

| 维度 | 取值 | 组合 |
|------|------|------|
| Backend | VueDom / Flutter / Native | 3 选 2 切换 |
| 登录态 | Cookie 轨 / Token 轨 / 未登录 | 3 |
| 操作 | mount / unmount / read / logout | 4 |
| 顺序 | 先切后登出 / 先登出后切 | 2（交换律） |

**核心用例**：`VueDom → Flutter → Native` 三后端对同一 IR 的资源视图**完全一致**（INV-05，INT-A7/A8）。

## 4. 并发模型（INV-04）

```
线程 A：反复 mount/unmount Backend
线程 B：反复 readAuth() / cacheGet()
线程 C：logout() 清空池
        ↓
  不变量：不崩溃 + 最终态 = 已登出（无僵尸会话）
```

**为什么重要**：真实 App 中，网络回调（线程 B）可能在页面切换（线程 A）与登出（线程 C）之间抵达——**三者的交错是崩溃与僵尸登录态的高发区**。

## 5. 降级链（INV-06）

```
首选后端 (VueDom)
    ↓ 装载失败
回退后端 (Flutter)  ←  登录态仍由共享池提供，不依赖特定后端
    ↓ 亦失败
拒绝装载 + 降级 UI（原则 #4）
```

**关键**：降级**不影响登录态**——因为登录态在池里，不在后端里（P1）。

## 6. 与 G-46 / G-27 的契约一致性

| 命题 | 承担者 |
|------|--------|
| 池内部正确（级联清理、TTL、双轨） | G-46 conformance |
| 后端内部渲染正确 | G-27 conformance |
| **池 × 后端组合正确（六不变量）** | **★ G-47** |
| 端到端业务场景 | G-44 E2E |

**G-47 是唯一"跨两层的"**，这也是它独立成 plan 的原因。

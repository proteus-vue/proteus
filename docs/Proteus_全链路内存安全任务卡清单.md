# 执行顺序与并行建议

```
MS0（5 卡并行）────────────────────────────► 🔴 全部完成前不得开始 MS5
   │
   ├──► MS1（a/b/c 可部分并行）
   │       │
   │       ├──► MS2（编译期检查）
   │       ├──► MS3（预算模型，需导航方案输入）
   │       │       └──► MS4（水位响应）
   │       │               └──► MS6（白屏防护）
   │       └──► MS5（last-will，🔴 设计取决于 MS0 窗口结果）
   │               └──► MS7（指标）
   │                       └──► MS8（对外）
```

**三条执行提醒**

1. 🔴 **MS0 不可压缩、不可跳过**——写盘窗口决定 MS5 整体设计（完整快照 vs 预写骨架）。
   基于"应该够用"的推测直接实现，是 Hermes 选型、团结引擎平台支持那几次的同类错误。

2. **MS0-d（小程序水位）是关键**——若无水位回调，last-will 在该端落不了地，
   必须改为周期快照兜底，**且对外表述要同步改**。

3. **MS3 需要导航方案输入**——多栈保活是内存负担，
   保活上限必须由预算反向约束，不能只按交互体验定。两个方案要一起定，不能各定各的。

Backend 决策（IR 落地）
同一份 ProductDetail.sfc，六端渲染出不同形态——差异 100% 来自 RenderBackend 对语义的 layout / columns / nav / input 推导，业务源码零改动。 p-adaptive 的断点是语义约束，不是 CSS 媒体查询—— 车机 / TV 由 input（dpad）与 usage-distance（10ft）触发，而非屏幕像素。

● 绿色能力 = Backend 已声明支持  ·  ● 橙色 = 需 @conditional 降级（如手表无 SKU 多选、车机隐藏详情长文）
❌ 传统「响应式」

同一份 DOM + CSS 媒体查询，只是把桌面页面缩放/折叠到小屏——手机端仍是"缩小的 PC"，车机/TV/手表直接不可用。

❌ 小程序多端

靠 #ifdef 条件编译为每个端写分支，代码量随端数线性膨胀，一套逻辑散落 N 处。

✅ Proteus 柔性框架

一份语义 SFC + 多 Backend 实现。布局拓扑、导航范式、输入方式由端形态推导，业务代码不写任何 if (isPhone)。

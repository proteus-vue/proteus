# 07 · 多端文档规范（原则 W-7：不绑定端叙事）

> **原则 W-7（#401 新增）**：文档按「语义（端无关）→ 端矩阵（结构化差异）→ 端页（深度指南）」三层组织，禁止在正文散文里散落端分支——正如业务代码禁止 `#ifdef`。
> 依据：W-2（文档单元 = 语义原语，不是平台 API）在**文档叙事层**的推广。

---

## 1. 问题：文档层的「端耦合」

当前文档大量使用「Web 端 / 小程序端」二元叙事：

- 表格列写死 `Web 端产物 | 小程序端产物`
- 正文散落「在小程序端……在 App 端……」
- 运行时页按「Web 运行时 / 小程序运行时」二分

但框架的核心主张是 **Platform = (R, C, J) 三元组 + Tier1-4 端模型**，RenderBackend SPI 已注册 **9 后端**（vue-dom / flutter / native-ios / native-android / native-harmony / skyline / skia / canvas2d / headless），后续接入 App（iOS/Android 原生）、鸿蒙、快应用时：

> **文档如果把「双端」写死，接入第三端时文档就要大面积重写——这正是框架在代码层消灭的「端耦合」，在文档层复发了。**

## 2. 三层内容组织（规范核心）

| 层 | 写什么 | 形态 | 示例 |
|---|---|---|---|
| **L-A 语义层（默认）** | 端无关内容：语义组件、配置、状态、路由**语义**、编译期契约 | 正文默认形态，**不出现端名** | 「`ref` 读写由桥接层批量合并」（不写"小程序端"） |
| **L-B 端矩阵层** | 必须呈现端差异时，用**端矩阵表**：行 = 行为维度，列 = 端注册表中的端 | 标准表格，列来自端注册表（§4） | 生命周期映射表（`onMounted → mounted / onReady`） |
| **L-C 端页层** | 某端的深度指南（运行时内部、工具链、平台限制） | 独立页面，slug = `runtime-{end}.md` / `{end}-backend.md` | `runtime-web.md` / `runtime-mp.md` / 未来 `runtime-harmony.md` |

**判定规则**：一段内容若**只对单一端成立** → 移入端页或端矩阵行；若**跨端同语义** → 留在语义层，删掉端名。

## 3. 端注册表（End Registry，SSOT）

所有文档的端名、端序、状态**必须来自端注册表**，禁止手写第二份清单：

| 端 ID | 端名 | 渲染引擎（BackendId） | 逻辑层运行时 | 状态 |
|---|---|---|---|---|
| `web` | Web SPA | vue-dom | Vue 3（同线程） | ✅ |
| `mp-weixin` | 微信小程序 | skyline（WebView 降级） | 独立 JS 运行时 | ✅ |
| `app-ios` | iOS 原生 | native-ios | JSI 载体（G-40） | 🟡 原型映射 |
| `app-android` | Android 原生 | native-android | JSI 载体 | 🟡 原型映射 |
| `app-harmony` | 鸿蒙 | native-harmony（ArkUI） | JSI 载体 | 🟡 原型映射 |
| `flutter` | Flutter 混合 | flutter | 同一 JS 逻辑层 | 🟡 |
| `quick-app` | 快应用 | 快应用引擎 | 待定 | ⬜ 未开始 |
| `headless` | Headless（SSR/测试） | headless | Node | ✅（工具档） |

- 状态纪律沿用全库四档：✅ 已落地可验证 / 🟡 部分落地 / 📋 规划已入库 / ⬜ 未开始——**每个端特有断言必须带状态**
- 注册表 SSOT = `packages/render-backend/src/spi.ts` 的 `BackendId` ∪ 宿主/工厂矩阵（Pinia 工厂、工具命令）；文档侧在 `website/src/ends.ts` 消费（后续生成端矩阵表）

## 4. 新端接入流程（文档侧）

新端（如鸿蒙）从⬜到✅，文档按以下顺序推进——**每步一个提交，状态列同步**：

1. **⬜→📋**：端注册表加行（端名 / 引擎 / 运行时占位）+ 该端相关 plan 链接
2. **📋→🟡**：端矩阵表**扩列**（受影响页：生命周期映射 / 产物对照 / 能力降级表）；端特有断言带状态
3. **🟡→✅**：新增端页（`runtime-harmony.md` / `{end}-backend.md`）+ 快速开始旅程**仅当端可跑通**才扩列
4. 全程禁止：在语义层正文补丁式加端名；跳过状态标注宣称支持

## 5. 反模式

| ID | 反模式 | 后果 |
|---|---|---|
| AP-W7-01 | 正文散文散落「在 XX 端……」 | 接入第 3 端时全文重写 |
| AP-W7-02 | 端矩阵表手写端列（脱离注册表） | 端清单漂移，与代码 SEMANTIC_BACKEND_MAP 脱节 |
| AP-W7-03 | 端特有断言不带状态标注 | 违反 G-37 / W-4，虚假宣称 |
| AP-W7-04 | 端页 slug 不按 `runtime-{end}` / `{end}-backend` 约定 | 文档入口不可预测 |
| AP-W7-05 | 把端特有内容写进语义层正文 | 语义层被端名污染，初学者认知负担倍增 |

## 6. 与既有规范的关系

- **W-2**（文档单元 = 语义原语）的叙事层推广：组件文档按语义组织，端差异进矩阵
- **W-4**（证明先于宣称）的状态纪律：端矩阵的每一格都可追溯（SEMANTIC_BACKEND_MAP / conformance）
- **G-60.1**（文档即契约）：端注册表变更 → 受影响页漂移检查（gen 流程扩展项）
- **原则 #0**：文档「不绑定端叙事」= 语义收敛在文档层的投影

# 架构更新（G-59）

## 新增原则

- **#13.75** 激活时机是契约，不是优化项
- **#13.76** ★ 权限的锚点是数据敏感度，不是 API 危险度
- **#13.77** ★ 信任不可继承：更新即重新授权
- **#13.78** 废弃必须提供替代，不留生态真空
- **#13.79** 不可度量的承诺等于没有承诺（破坏率必须公开）

## 第 22 次泛化

```
不绑定后端 → 不绑定环境 → 不绑定设备 → 不绑定编辑器
→ 不绑定宿主来源 → 不绑定扩展来源 → ★ 不绑定生态治理模式
```

前 21 次泛化处理的都是**技术形态**；
G-59 第一次处理**治理形态**——
生态规则本身也应该可被替换、可被度量、可被验证。

> **官方序注（决策 #396）**：本份为第 **22** 次（前承：G-54=18 IDE 形态、G-56=19 宿主来源、G-57=20 可观测性来源、G-58=21 扩展来源；G-55 为 G-54 落地不占序）。原稿误作第 19 次。

## 成熟度模型更新

```
L0 无契约              ← Atom 式（暴露权力）
L1 有 API 无约束        ← 早期 VSCode
L2 权限模型             ← G-58
L3 +性能/版本/数据契约   ← ★ G-59
L4 +治理与破坏率看板     ← G-59 阶段 3（需真实生态数据）
```

## 与既有体系互校

- **G-58** capability 模型 → 升级为数据敏感度分级（不推翻）
- **G-55** 内核性能预算 → 与 G-59 启动预算构成宿主整体冷启动目标
- **G-37** 未实测不宣称 → 扩展为数字三分类标注纪律
- **G-52** 跨设备等价类 → 同构思想：有限集合上建模

## 已知缺口

- 激活耗时为声明估算，非真实执行计时
- tier 映射仅代表性 API
- 破坏率无真实历史数据支撑
- **生态冷启动（如何吸引第一批作者）是运营问题，架构无解**

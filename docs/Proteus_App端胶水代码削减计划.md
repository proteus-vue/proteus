## 一、最大胶水源：**动态 `:class` 不生效**（★首选）

**现象（开发者被迫手写胶水）**：`:class="{ on: open }"` / `:class="[a, b]"` 在 App（Vapor）端**静默不解析**
  → 类样式的切换（选中态/禁用态/主题）不生效 → 开发者只能用静态 class + 手写 `:style` 映射，或按平台分支。

**用量**（真项目普查）：组件库 **64 处** `:class` + examples **27 处** + showcase **3 处**；形态以
  `:class="{ 'is-disabled': disabled }"` / `{ on: cond }` 这一类**对象字面量、键为类名**为主。

**★关键发现（本轮核实，令其成本大降）**：**编译器其实已经发射了 `paint.class` 绑定**——
  `buildVaporSubscriptions('<view :class="{on:open}">')` 产出 `propKey: 'paint.class'` + 求值程序
  `{k:'obj', props:[{key:'on', value:{k:'root', name:'open'}}]}`。
  ⇒ **缺的只是「运行期解析」这一环**：`onPaintProp(nodeId, 'paint.class', classObj)` 收到值后，**没有**把它
    （对象/数组/字符串）解析成**类名集**、再按 `<style>` 规则表算出样式字段。
  证据：`hosts/android/bridge/entry-vapor.ts:1939`（`onPaintProp` 把 `paint.class` 记为 field `class`，宿主 spec 无此字段 ⇒ 丢弃）。

**削法（分两步，先做自匹配子集）**：
1. **编译期**：把 class 规则表里**只自匹配**的规则（选择器为单段：`.a` / `.a.b`，**无**后代/子组合）
   连同「类名 → 字段」映射**发射进 subscription 表产物**（新增一段：`classRules`）。
2. **运行期**（`slot-runtime/runtime.ts` 的绘制出口 + 各端 entry 的 `onPaintProp`）：收到 `paint.class`
   → 解析值为类名集（对象取 truthy 键 / 数组取元素 / 字符串按空白切）→ 合集自匹配规则字段 →
   按 `paint.<field>` 逐条下发（复用既有绘制键出口——**通道已在**）。
   ★**仅自匹配**（无祖先/后代）⇒ 不需要子树重算；含后代组合的规则如实诊断（不静默）。
3. **判据**：编译器（规则表发射）+ 运行期（解析+下发，含数组/对象/字符串三形态 + 未知类忽略）+
   e2e（真机：切 `:class` ⇒ 背景色/文字色变）+ capability 清单加行。

**成本**：中（compiler 发射 + runtime 解析 + 3 端 entry 接线；**无引擎/宿主绘制改动**——绘制键通道已通）。
  **收益**：组件库/示例 **94 处**写法照标准 Vue 直接工作。

## 二、`v-model` 只有下行、无回写（表单类超级应用硬伤）

**现象**：`<input v-model="x">` 在 App 端**值→文本下行**，但**输入不回写**（`VAPOR_VMODEL_NO_INPUT_CONTROL`）
  ⇒ 开发者为表单手写事件 + 手动 `x = e.detail.value`，或整页保留 Web 渲染。

**证据**：`packages/compiler/src/vapor/template.ts:1958`（诚实诊断）；用量：examples `forms` / `devtools-open-api-demo` /
  showcase `p-checkbox`/`p-slider` 等（组件库大量）。

**削法（三件，缺一不可）**：
1. **编译器**：`v-model` 编为「下行绑定（已有）+ **回写绑定**」——回写走**宿主输入事件**（`input`/`change`）
   → `$event` 写入源槽位；修饰符 `.trim`/`.number` 编进回写表达式。
2. **三端宿主输入通道**：Android `EditText`/`InputConnection` · iOS `UITextField`/`UITextView` ·
   鸿蒙 `TextInput`/`IME`——把输入事件经**既有事件通道**上报（`dispatch` 已有 tap/longpress；加 input 类）。
3. **判据**：编译器（回写绑定形态）+ 运行期（事件→源写回）+ 真机（输入 ⇒ 数据变 + 文本槽位更新）。

**成本**：**大**（编译器 + 三端**原生输入控件** + 事件通道）；是"表单超级应用"的**必答题**，但要独立立项。

## 四、★顺带的纪律发现（非胶水，但同源）

**批 26/27/28 揭示的"覆盖语义"类**：编译器声明解析此前只看"能不能折"，没看"**层叠后对不对**"——
  · 批 27：重置声明（`border:none`）**直接 skip** ⇒ 覆盖失效；
  · 批 28：`inherit` 关键字被诊断跳过 ⇒ 取父值失效。
  ⇒ **级联/组合探针**（构造 `.a`+`.b` 双类场景）应作为**常规取证手段**之一（已入档）。

2. `order` 编译期重排（§3.3，小、组件库 15 处）。

> **目标文件**：`proteus-architecture.md`（合并后）

---

## 1. 原则层变更

### 原则 #0（统摄）— 新增第六支柱候选（待 TC 确认是否升级为 #11）

> **#0.6 原语完整性**：框架内置原语必须覆盖对标平台的 **100%** 通用能力（以小程序现行全量能力为完整性标尺），覆盖率由自动化审计（`proteus audit:coverage`）保障，缺口 = 0 才可发布。

**理由**：G-31 定义了「约 15 原语」的骨架，但真实业务会触及小程序能力的长尾。若不强制 100% 覆盖，生态会回退到「小程序 API 直调」，破坏语义层（即退化成 uni-app/Taro 的失败模式）。

### 原则 #10（统一语义 + 后端实现）— 补充 #10.13

> **#10.13 原语即契约**：所有业务可写的 `<p-*>` 组件与 `use*()` API 均为 **L1 内置语义原语**，数量冻结为 128（6 大类）。任何新增须经组合性审查（CMP009）与完整性复算。

## 2. 规则总表新增

| 编号 | 规则 | 级别 |
|------|------|------|
| **G-32.1** | L1 原语覆盖率必须 = 100%（小程序官方能力），CI 门禁 | 铁律 |
| **G-32.2** | L1 原语禁止与小程序组件同名（`view`/`scroll-view` 等），同名须走 compat | 铁律 |
| **G-32.3** | L1 能力原语必须 3+ 端实现（Web/iOS/Android 至少三） | 铁律 |
| **G-32.4** | 能力原语必须返回 `Result<T>` 或 `Promise<T>`，禁止回调风格 | 铁律 |
| **G-32.5** | 原语属性必须是「约束描述」，禁止暴露 CSS / 平台 API 名 | 铁律 |
| **CMP009** | 新增原语须经组合性审查，能用现有原语组合则不得新增 | 严格规则 |

## 7. 风险与边界（合并进规约）

1. **128 原语过多** → 文档按场景索引 + IDE 自动导入；核心 34（G-31 骨架）+ 扩展 94
2. **小程序私有能力** → 显式标记 ⬛，收敛到 C47 `useMiniProgram()`，**不进 L1**
3. **平台复合组件**（如 `<canvas>` 2d/webgl/skia） → 归 L2 Backend 包，L1 只定义语义接口
4. **宿主拒绝嵌入 JS**（Tier 4） → G-30 降级，原语退化为静态/SSR

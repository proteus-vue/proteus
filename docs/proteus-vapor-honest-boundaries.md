| 8 | **`INSERT_BLOCK`/`MOVE_NODE`/`CALL_COMPONENT_UPDATE` unsupported** | 需编译期块实例 / 组件边界调度，属后续里程碑；**上报而非静默**（这点是达标的） |
| 9 | **真机绝对读数受热降频影响** | **为什么接受**：物理限制（SoC 热管理），任何软件手段都无法消除。<br>缓解手段已到位：**同轮 A/B**（对照在同一热状态下）+ 三轮中位 + 明确"比值可信、绝对值不可跨轮比"。<br>**重审条件**：需要跨轮绝对值时 ⇒ 改跑**冷启动 + 固定预热**并记录温度，或改用**结构性判据**（如调用次数/字节数，本仓 #11 的做法） |
| 10 | **`bytes → JSON 数组` 跨边界形态**（iOS JSExport 不支持 `ArrayBuffer`） | **为什么接受**：指令流极小（实测 **45 字节**）⇒ JSON 数组包装成本可忽略。<br>★对照：Android 侧 JNI **原生支持 `jbyteArray`**（无需包装）——同一条指令流在两个平台走不同跨界形态，是**平台 API 差异**不是设计不一致。<br>**重审条件**：指令流增长到 KB 级，或 `in_bytes` 成为可观测瓶颈时 ⇒ iOS 侧改 JSI 直传 |
| 11 | **`proteus explain` 的 L1 覆盖率是单页读数** | **为什么接受**：覆盖率是**按页**量的（"这一页有多少槽位走 L1"），本来就不该有"全局覆盖率"这个数——不同页的模板复杂度天然不同。<br>命令已能逐页输出（`proteus explain --vapor`）。<br>**重审条件**：若要用它做**版本间回归** ⇒ 需固定一组代表性页面作为**基准集**（属工程化，不在本档范围） |

## 三、纪律清单（本阶段累积——都来自实测踩坑）

| # | 纪律 | 来源 |
|---|---|---|
| 1 | **测量装置本身必须先被验证** | 5 次同类（未挂载 / 脏标记 / 计数器 / 微任务排空 / 时钟分辨率） |
| 2 | **任何 >5ms 的分段都必须再拆** | `layers` 只报总数时把"不是瓶颈"当瓶颈查了两轮 |
| 3 | **用例必须通过破坏性验证才算数** | 写过"击不倒任何东西"的用例；守卫未被触发过 |
| 4 | **计时必须配「变化量」自检** | 基准树缺 `flexShrink` ⇒ 改行高不产生几何变化却照报耗时 |
| 5 | **「恰好为 0 的偏移」会让坐标类错误隐身** | 潜伏坐标缺陷存活至今（目标都在偏移 0 处） |
| 6 | **树 id 必须等于模板序元素序号** | 指令写到错误节点，且症状伪装成坐标错 |
| 7 | **绝对/相对坐标在断言里必须标明口径** | `rects`=绝对 · `node.rect`=相对父 · 重排后子节点=相对范围根 |
| 8 | **连续两次猜测未果 ⇒ 转确定性诊断** | 三层嵌套试错四轮，打印内部状态一次定位 |
| 9 | **标定实验优先于推断** —— ★★**但标定的结论也会推反**（见 #17） | 字节序我猜 BGRA ⇒ 标定读数正确（纯红→`#0000FF`），**结论却写成了"是 RGBA"**，错了半年 |
| 10 | **跨用例共享的视图状态必须在新树建立时归零** | `contentOffset` 泄漏 ⇒ "几何对但屏幕错" |
| 11 | **守卫必须可观测**（记下"被哪条拒绝"） | 否则"有守卫"与"守卫生效"无法区分 |
| 12 | **同一语义一处实现** | `apply_ops` 重复实现被收敛为 `apply_ops_impl` |
| 13 | **★加读数时先确认端到端能读到非空** | 本轮为拿一条 `engine_diag` 折腾 4 轮（内联副本绕过统一入口 → 侧信道没写 → 宿主没透传 → JS 取错路径） |
| 14 | **★★"建了但没存"是静默的**（跨调用复用点必须验证状态真的留下） | `build_taffy` 产物未存 ⇒ 无报错，只表现为"优化没效果"（与度量表/文本回报同族） |
| 15 | **结构变更的失效判据不能只看长度**（splice 只断链不删节点） | `splice_remove_detaches_subtree` 抓到引擎用了旧树 |
| 16 | **跨语言/跨层形状契约两端各留判据** | `text` 顶层 vs `style` 内：单端测试只能证明自己那一半 |
| 17 | **★★标定（自检）必须进判据——"只记录、不断言"等于没测** | 三色标定的读数一直是对的，但从未进 verdict ⇒ R/B 互换长期恒绿（见 #27） |
| 18 | **★★测"通道"还要测"方向"** | 色标定无法发现**翻转**——现象是"通道全对、位置全错"（每个点取到另一个位置的合法颜色）。⇒ 自检必须含**空间**维度（上红下蓝） |
| 19 | **★★判据的样本色要跨通道** | 此前像素判据只用**纯绿** ⇒ 绿在 R/B 互换下**不变** ⇒ 该判据对这类变换完全免疫。加上紫色圆点（`#6F4AE8`）才暴露 swap |
| 20 | **★★"更新与物化解耦"：被跳过的东西必须落到真源** | 虚拟化下行未物化 ⇒ 若更新被丢弃，滚入时显示**旧内容**而所有几何断言全绿（V12 的 `offscreenUpdateVisible` 就是为它设的） |
| 21 | **★★"跨层隐式契约"要换成"自描述载荷"** | textStyleKey 若加字符串维度就得两端维护同一张槽位表（表错了不报错）⇒ 改逐维度混算；字体族发**角色字符串**而非下标（未知值可见）；"未识别"与"识别为默认"必须可区分 |
| 22 | **★★同一语义的第 N 份手写副本 = 下一个静默缺陷** | 绘制字段抽取在宿主有 **4 份**（全量 render / splice / styleOf / 度量循环）⇒ 加 `fontFamily` 时必漏一处（全量挂载无字族、增量有）。加维度前先 grep 有几处 |
| 23 | **★"没生效"要先怀疑路径语义，再怀疑实现** | `mount` 是增量语义且只处理布局字段 ⇒ 第二次 mount 一棵只改字体的树**什么都不做**；V13 对照组两组读数完全相同，差点被读成"该维度不影响结果" ⇒ 用 `clearTree` 做真重建 |
| 24 | **★★键形（camel/kebab）是又一类静默形状分叉** | 模板静态 style 经 Vue 编译是 `{"font-family":...}`，`:style`/`h()` 是 camelCase ⇒ 只认一种则另一种不报错不生效；漏掉 kebab 的后果是 `fsNum=NaN` ⇒ **整个字体块被跳过**（不只是少一个维度） |
| 25 | **★★★"提交 ≠ 交付"：漏推送是**结构性**遗漏，不是"忘了"** | 一天 **111 个提交**（含多次真机闭环）全部只在本地 —— `pnpm test`/`check:*`/`verify` 全是**本地**门禁，`git status` 的 `ahead N` **不报错** ⇒ 没有任何机制提醒。⇒ 新增 `scripts/check-pushed.mjs`（默认提醒 exit 0 / `--require` 判红）+ 接进 `verify` 末尾 + AGENTS.md 红线。★纪律：**"我推了" ≠ "推上去了"**（与"改完了"≠"改对了"同型），推完必须再 `git status -sb` 确认 |
| 26 | **★解析器的字符集就是它的能力边界**（少一个字符 = 某类合法输入被静默漏掉） | 门禁名单解析正则用 `[\w-]` ⇒ `check:pushed:strict`（**第二个冒号**）解析不出来 ⇒ 明明登记了仍报"未接线"（**假红**）。同日第三例同族缺陷（前两例：适配器 `font-family` 少 kebab 键形 ⇒ 整个字体块被跳过；`\w-` 少 `:` ⇒ 整个门禁名被跳过）。**若同样的正则用在"过滤放行"方向就是假绿**——本仓对后者尤其敏感 |
| 27 | **★新门禁会先被**别的**门禁抓到——这正是"守卫必须可观测"的价值** | 新增 `check:pushed` 后 `check:gates-sync` **当场红**（"未接入任何 workflow，也未在 LOCAL_ONLY 声明理由"）⇒ 被迫写明"CI 的 detached HEAD 下恒为 0 ⇒ 接 CI 是假门禁"。**一个门禁的接线不是靠记忆，是靠另一个门禁盯着** |
| 28 | **★★平台侧只执行、不重判**（"看起来合理的优化"可能破坏上游簿记） | 宿主加"屏幕外不建"裁剪 ⇒ 核心已记 acquired 的行不再下发 ⇒ **滚进可见区也永远不被建**（屏幕真的缺行）。**发现靠对账探针**（`max_missing_in_visible`），不是看图。任何"平台侧再裁一次"都是把上游策略复制成第二份 |
| 29 | **★构建/工具的失败必须直接取退出码**（管道会吃掉它） | `javac \| grep \| head \|\| true` ⇒ 编译失败照样打包 APK（本仓第二次：iOS 是 `\| tail -1`）⇒ 等于在测旧产物 |
| 30 | **★★生成物必须在构建路径上**（"记得手工跑"= 下一个旧产物事故） | 跨语言夹具不刷新 ⇒ 构建成功、设备跑**旧形状** ⇒ 用例绿着而契约已分叉。⇒ 生成步骤写进 `build-and-run.sh`，失败即 exit 3 |
| 31 | **★别在宿主里重写上游的编码/决策**（第三份实现 = 又一处必然漂移） | Android 无 JS 引擎 ⇒ 诱惑是在 Java 里再写个指令编码器（= 第三份），且只会测"自己编自己解"。⇒ 构建期用 TS 真实编码器产出、冻结字节，设备只发不编 |
| 32 | **★★设备验证前必须确认真机装的是刚构建的包** | 用 `--no-install` 构建后直接跑用例 ⇒ 设备上还是**破坏性验证那个包** ⇒ "已修好的用例"报 FAIL。`--no-install` 只用于"只看编译是否通过" |
| 33 | **★★局部变量不得与字段同名**（遮蔽的报错极具误导性） | `root`（局部 JSONObject）遮蔽类字段 `FrameLayout root` ⇒ 报"找不到符号 addView(…)，位置：类型为 JSONObject 的变量 root"，看起来像 View 体系的问题 |
| 34 | **★★复用率类比值对"运行长度"敏感——比之前先对齐分母** | 同一实现：12 步×25 行 0.914 / 30 步×9 行 0.912 / 107 步含回滚 **0.974**（iOS 600 帧 0.997）。冷启动建的对象是**固定成本**，跑得越久摊得越薄 ⇒ 报告必须同时给总步数/总样本，否则比值不可比 |
| 35 | **★★"读数恒为 0"不是"还没做"，是"读数恒假"** | `first_frame_ms` 挂了很久当"后续项"，实际是静态量惰性初始化（起点=终点）⇒ 恒 0。**0 会被读成"极快"**，比报错危险 ⇒ 见到"某个读数恒为 0/恒定"先怀疑装置 |
| 36 | **★★跨接口传坐标前先确认两端口径**（"数字看着合理"最危险） | 屏幕坐标 vs 内容坐标：传错后命中的是**另一行**（~449 确实是某行的 y，只是不是目标行）⇒ 探针改为**同时给两套坐标**，各取所需 |
| 37 | **★★判据的目标是"正确时的样子"，不是"覆盖两个分支"** | 我写过"命中已物化与未物化两种状态各一次"——而可见区内的行**永远应已物化** ⇒ 那条判据**要求实现出错**才算通过。⇒ 改成 `可见区内命中的行必须已物化`（真正的正确性断言） |
| 38 | **★★并列的定长数组，长度必须由同一处派生** | `int[] hitDone = {0}` vs `int[] hitPlanStep = {...3 项}` ⇒ `hitDone[1]` 越界 ⇒ **主线程 FATAL、进程直接死**；Java 不会报"两数组长度不一致"（非编译期可判）|

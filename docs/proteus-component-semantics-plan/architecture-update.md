# Architecture Update: G-31 合并进规约

> 将 `G-31-component-api-semantics.md` 的变更合并入 `proteus-architecture` 增量清单。
> 编号沿用现有体系：原则 #0（PROTEUS-METHODOLOGY）+ G-31.x + CMP005~8。

---

## 1. 原则层变更

### 新增：原则 #0 具体化至"开发者书写面"

> **原则 #0（统一语义收敛）** —— 增加第五个投影面：

```
① 编译（G-29）→ CompilerIR
② 渲染（G-27）→ RenderIR / VNode
③ 能力（G-28）→ Capability IR
④ 端（G-30）  → Platform = (R, C, J)
⑤ 入口（G-31）→ Component IR ← 本次新增
```

**断言**：方法论五支柱同时应用于组件与 API 的设计（见 `G-31 §2`）。

---

## 2. 铁律新增

### G-31.1 语义命名
> 内置组件必须以 `p-` 前缀 + 语义名词命名；禁止与小程序/HTML 组件同名进入 Layer 0。

### G-31.2 属性可降级
> 每个组件属性须声明 Tier 降级行为；缺声明 → `CMP006`。

### G-31.3 异步即 Promise
> Layer 0 API 一律 Promise/Hook；禁止回调式全局 API（`no-callback-api`）。

### G-31.4 组件多端验证
> 组件进 L1 须 ≥3 端 conformance；不足 → L2/L3。

### 代码层规则（CMP005~8）

| 编号 | 触发 | 处置 |
|------|------|------|
| CMP005 | 业务直调平台 SDK | 改 `useNative()` |
| CMP006 | 属性无降级声明 | 编译期报错 |
| CMP007 | 回调式 API 入 Layer 0 | lint 阻断 |
| CMP008 | 组件 L1 不足 3 端 conformance | 降级 L2 |

| G-31 规则 | 复用对象 | 关系 |

## 4. 全景图更新

```
源码（SFC）
  ↓ G-31（本次）：组件/API → Component IR（语义层）
CompilerIR（G-29）→ 优化/校验
  ↓
RenderIR（G-27）→ Backend 渲染
Capability IR（G-28）→ Backend 能力
  ↓
Platform（G-30）：Tier 1/2/3/4 降级
```

**G-31 填补"源码 → IR"这一环**，使全链路从源码到像素均为语义收敛，无任何环节泄漏平台 API。

## 7. 风险边界（诚实声明）

- **不 100% 兼容小程序组件名**（交给 compat 层，不污染语义层）
- **不内置大量业务组件**（支柱 ④ 渐进覆盖，生态 L2/L3）
- **迁移需人工介入语义还原**（scroll-view/swiper → 布局原语，AI 辅助）

# G-48 规约增量

## 新增原则

> **原则 #13.37（小程序运行时中立）**：宿主运行时 MUST NOT 绑定特定小程序平台；平台差异 MUST 封装在 Platform Adapter 内，业务代码 MUST 零平台分支。

> **原则 #13.38（双线程语义）**：小程序逻辑层与视图层 MUST 通过序列化通道（setData）通信；逻辑层 MUST NOT 直接操作 DOM，视图层 MUST NOT 直接修改逻辑层状态。

> **原则 #13.39（凭证派生）**：小程序凭证 MUST 为宿主登录态的派生值（scopedToken），绑定 AppID 与过期时间；MUST NOT 向小程序暴露原始登录态。

> **原则 #13.40（兼容分级声明）**：每个 Platform Adapter MUST 为每个能力声明兼容级别（L0/L1/L2/L3），运行时据此生成兼容矩阵；L2/L3 MUST 有明确降级路径，MUST NOT 静默失败。

## 诚实边界（写入对外文档）

**G-48 可宣称**：

- ✅ 自有 + 受控第三方小程序，AppID 级逻辑隔离
- ✅ 凭证最小化（scopedToken）+ 存储隔离 + 代码签名
- ✅ 兼容微信标准小程序，90%+ API 一致（L0+L1 ≥ 90%）

**G-48 不可宣称**（需 G-49 + G-50）：

- ❌ 任意第三方代码安全运行（需进程级隔离 + 审核）
- ❌ 防恶意小程序代码注入（MVP 逻辑隔离可被高级绕过）
- ❌ 资源完全隔离（配额限速属 G-49）

## 已知缺口（后续 G-49 覆盖）

1. 真双线程隔离（独立 JS 引擎上下文 / Worker 线程）
2. 代码包分包加载的完整实现（MVP 仅骨架）
3. 进程级沙箱（V8 isolate / WASM / 独立进程 + IPC）→ 机制清单见 G-49/G-50
4. 资源配额（CPU / 内存 / 网络限速）→ G-49/G-50
5. 支付宝 / 抖音 Adapter 完整实现（结构已就绪，可并行扩展）

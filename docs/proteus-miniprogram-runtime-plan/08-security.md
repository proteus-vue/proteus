# G-48 安全模型：第三方小程序信任

> **信任级别**：MVP = **受控第三方**（自有 + 审核过的生态，逻辑隔离）；开放平台级（任意第三方）= **G-49**（进程隔离 + 审核体系）。**G-48 不承诺"任意代码安全运行"。**

---

## 1. 信任模型分级

| 级别 | 代码来源 | 隔离 | 适用 | 对应 |
|------|---------|------|------|------|
| **L1 自有** | 宿主官方小程序 | 逻辑隔离（AppID） | 宿主内置功能 | G-48 MVP |
| **L2 受控** | 合作方（审核/签约） | 逻辑隔离 + 能力白名单 | 生态初期 | G-48 MVP |
| **L3 开放** | 任意开发者 | **进程级** + 审核 + 配额 | 开放平台 | **G-49 + G-50** |

**G-48 覆盖 L1 + L2。L3 明确属后续（G-49 运行时 + G-50 平台）。**

---

## 2. 攻击树（含在 MVP 范围内需防御的）

> 注：本树只列 L1 逻辑隔离（MVP：自有 + 受控第三方）范围内需防御的攻击；进程级攻击面与实现反模式（开放 bridge / 机制 vs 规范 / 配额逃逸 / 平台宣称差异）已由 G-49 反模式 AP-09~12 收录，本文不重述。

### 2.1 凭证窃取

```
恶意小程序
 ├─ 直接读宿主登录态 → RSC-01 拦截（scopedToken 隔离）
 ├─ 跨 AppID 读他人凭证 → SBX-L1-02 拦截（命名空间隔离）
 └─ 伪造 appId → G-45 签名校验拦截
```

### 2.2 数据泄漏

```
 ├─ 读取其他小程序存储 → SBX-L1-02
 ├─ 读取宿主存储 → RSC-01（host 命名空间不可访问）
 └─ setData 传递函数/循环引用 → RT-02/03 序列化拦截
```

### 2.3 资源滥用

```
 ├─ 无限定时器/监听 → G-43 所有权级联释放（销毁时清理）
 ├─ 无限网络请求 → G-49 资源配额（MVP 仅软限制）
 └─ 阻塞逻辑层 → G-49 真双线程隔离（MVP 单进程有风险）
```

### 2.4 代码注入 / XSS

```
 ├─ 篡改代码包 → G-45 签名 + manifest 哈希校验
 ├─ 动态执行 eval → G-49 禁用（L3 级）
 └─ 原型链污染 → G-49 独立上下文（MVP 需业务自律）
```

### 2.5 权限滥用

```
 ├─ 未授权调蓝牙/NFC/相机 → CAP-05 权限校验
 ├─ 伪造支付 → 支付需平台资质 + 二次确认
 └─ 静默分享 → 分享需用户触发（不静默）
```

## 3. 铁律（CMP-103-109，L1 安全集）

| 编号 | 铁律 |
|------|------|
| CMP-103 | **凭证最小化**：小程序只拿 scopedToken，不拿原始登录态（RSC-01） |
| CMP-104 | **AppID 隔离**：存储/凭证严格按 AppID 分桶，跨桶访问即拒绝 |
| CMP-105 | **代码包签名**：未通过签名 + 哈希校验，拒绝装载 |
| CMP-106 | **销毁级联**：小程序销毁必须释放全部资源（G-43 Drop） |
| CMP-107 | **能力白名单**：每个小程序声明所需能力，未声明 → 拒绝 |
| CMP-108 | **敏感能力需用户触发**：支付/分享/授权不得静默执行 |
| CMP-109 | **诚实边界**：MVP = L1 逻辑隔离，开放平台（任意代码）需 G-49，禁止宣称过度 |

## 4. 能力白名单机制

每个小程序 `app.json` 声明能力：

```json
{
  "appid": "wx_xxx",
  "requiredCapabilities": ["login", "storage"],
  "optionalCapabilities": ["shareAppMessage"],
  "permissions": ["camera"]
}
```

**运行时校验**：

- 调用未声明能力 → **拒绝**（CMP-107）
- 声明但平台不支持（L3）→ **降级提示**（不崩溃）
- 敏感权限（camera/bluetooth）→ **需用户授权 + 运行时弹窗**

> 注：权限清单 schema（requiredCapabilities / optionalCapabilities / permissions）与 **G-49 MiniProgramManifest 对齐**——后者为权威（权限声明/签名/配额契约），见 `sandbox-isolation-plan/03-spi.md`。本表仅作 L1 白名单语义说明。

## 5. 审计日志（防注入，CMP088 同源）

所有敏感操作**记录审计日志**（不可篡改）：

- 小程序装载（appId + 签名 + 版本）
- 能力调用（capability + 参数脱敏）
- 凭证派生 / 吊销
- 权限授予 / 拒绝
- 资源配额超限

**用途**：事后追溯 + 异常检测（如某小程序异常高频调支付）。

## 6. 与 G-46 安全的协同

| G-46 铁律 | G-48 复用方式 |
|-----------|--------------|
| RSC-01 HttpOnly 隔离 | scopedToken 派生（不暴露原始登录态） |
| RSC-02 登出全池清理 | 宿主登出 → 所有小程序 scopedToken 级联失效 |
| RSC-03 同源白名单 | 小程序间通信须走宿主中转（白名单） |
| RSC-04 Token 可刷新 | scopedToken 过期 → 用 masterSecret 重新派生 |
| RSC-05 SSO 防重放 | 代码包下载 / 装载的签名防重放 |

**G-48 不是另起安全体系，而是把 G-46 的凭证池 + 所有权模型扩展到"多小程序"场景。**

---

## 7. 诚实边界总结（对外宣称用）

**G-48 可宣称**：

- ✅ "自有 + 受控第三方小程序，AppID 级逻辑隔离"
- ✅ "凭证最小化（scopedToken）+ 存储隔离 + 代码签名"
- ✅ "兼容微信标准小程序，90%+ API 一致"

**G-48 不可宣称**（需 G-49 + G-50）：

- ❌ "任意第三方代码安全运行"（需进程级隔离 + 审核）
- ❌ "防恶意小程序代码注入"（MVP 逻辑隔离可被高级绕过）
- ❌ "资源完全隔离"（配额限速属 G-49）

**这条边界在 `README.md` + `architecture-update.md` + 对外 positioning 中**一致声明**——沿用 G-40 CMP046「未实测不宣称」。

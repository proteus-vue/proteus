# G-48 隔离（L1 基线）：AppID 级逻辑隔离

> **定位**：G-48 提供隔离强度 **L1 基线 = AppID 级逻辑隔离**——凭证、存储、销毁按 AppID 分桶与级联，面向**自有 + 受控第三方**小程序（信任级别 L1/L2，见 08-security）。
> **边界**：进程级隔离机制**不在本文展开**——L2/L3/L4 归属见文末「前向引用」（G-49 / G-50），本文只给 L1 语义与机制。

---

## 1. L1 基线：隔离对象

| 对象 | 隔离维度 | L1 基线机制 | 更高层归属（引用，不重述） |
|------|---------|------------|--------------------------|
| **凭证** | AppID | scopedToken 派生（HMAC） | 独立密钥/存储权限隔离 → G-49 |
| **存储** | AppID | G-46 L3 按 origin 命名空间 | L2 存储权限隔离 → G-49 |
| **代码** | AppID | 代码包签名 + manifest 哈希（G-45） | L3/L4 运行时沙箱 → G-49 / G-50 |
| **资源** | AppID | 生命周期所有权 + 销毁级联（G-43 Drop） | 资源配额（CPU/内存/网络） → G-49 / G-50 |
| **线程** | AppID | MVP：单进程模拟双线程（04 §1.2） | 真进程/线程隔离 → G-49 |

## 2. 凭证隔离（L1 核心）

### 2.1 scopedToken 派生

```
masterSecret (宿主, 安全存储)
   + appId
   + userId
   + scope
       ↓ HMAC-SHA256
scopedToken = base64(alg || appId || exp || mac)
```

**特性**：

- **不可逆**：无法从 scopedToken 反推 masterSecret / 原始登录态
- **绑定 AppID**：换 AppID → 验证失败（防跨小程序调用）
- **可过期 / 可吊销**：登出清 G-46 池 → 所有派生失效

### 2.2 凭证访问规则

```
小程序 A (appId=A) → 只能读 scopedToken(A)
小程序 B (appId=B) → 只能读 scopedToken(B)
宿主全局登录态     → 任何小程序不可读（HttpOnly 隔离，RSC-01）
```

**违反** → `SANDBOX_VIOLATION`，conformance 校验（见 §5 SBX-L1 集）。

---

## 3. 存储分桶（复用 G-46 L3）

G-46 的 L3 缓存按 `origin` 命名空间隔离，小程序**直接复用**：

```
G-46 ResourcePool:
  L3 (cache): {
    "mp:<appId_A>": { ... },   ← 小程序 A 的存储
    "mp:<appId_B>": { ... },   ← 小程序 B 的存储
    "host": { ... }             ← 宿主（小程序不可访问）
  }
```

**关键**：小程序**只能访问 `mp:<自己的 appId>` 命名空间**，`host` 命名空间**只读不可写**（且不含 HttpOnly 凭证）。

---

## 4. 生命周期与销毁级联（G-43 Drop 应用）

小程序 = **一个所有权根节点**：

```
MiniProgramRoot (G-43 Ownership)
 ├─ AppService (逻辑层 JS 上下文)
 ├─ PageFrame[] (视图层)
 ├─ setDataChannel (消息队列)
 ├─ ResourcePool 命名空间 (mp:<appId>)
 └─ 定时器 / 事件监听 / 网络请求
```

**销毁时（destroy / onUnload）** → G-43 **级联 Drop**：

- 清空消息队列
- 取消所有定时器 / 事件监听
- 释放网络请求（abort）
- 清空 `mp:<appId>` 存储（可选，按配置）
- **不允许循环引用泄漏**（G-43 循环检测）

**这是 G-43 所有权/Drop 模型在小程序场景的直接应用**——`04-standard-runtime.md` 的 RT-06/07 conformance 验证此点。

## 5. conformance 用例（SBX-L1：G-48 L1 逻辑隔离集）

| 编号 | 场景 | 期望 |
|------|------|------|
| SBX-L1-01 | 小程序读宿主原始登录态 | **拒绝**（RSC-01，返回 null） |
| SBX-L1-02 | 小程序 A 读 B 的存储 | **拒绝**（SANDBOX_VIOLATION） |
| SBX-L1-03 | 小程序伪造他人 appId | **签名校验失败**（G-45） |
| SBX-L1-04 | 登出宿主 → 小程序 scopedToken | **级联失效** |
| SBX-L1-05 | 小程序销毁 → 定时器/监听 | **全部释放（无泄漏）** |
| SBX-L1-06 | 小程序间通信 | **只能通过宿主中转（显式 API）** |
| SBX-L1-07 | 代码包篡改（manifest 哈希不匹配） | **拒绝装载** |
| SBX-L1-08 | 循环引用（页面 ↔ 全局） | **循环检测报告 + 强制清理** |

> 命名注记：SBX-L1-xx 是 **G-48 L1 逻辑隔离用例集**；G-49 的 SBX-01~08 是 **L1-L3 全层不变量集**——撞名不同义，引用时勿混（见 rules.md 编号避让登记）。

## 6. 诚实边界（L1 vs L2-L4）

**G-48 的 AppID 级隔离是"逻辑隔离"，不是进程隔离**：

- ✅ 同一进程内，恶意小程序**理论上可绕过**（如原型链污染、共享全局）
- ✅ **适用于"自有 + 受控第三方"**（代码来源可信 / 审核过的生态）

**若要做"任意第三方代码安全运行"（开放平台级）**，必须升级隔离强度——机制归 G-49/G-50，见文末前向引用。本文只做 L1 语义，不重述进程级实现清单。

**这条边界写入 G-48 铁律（rules.md G-48.6）**，避免对外宣称过度。

---

## 7. 安全清单（开发自查，L1 范围）

- [ ] 所有凭证读取走 scopedToken，**无原始登录态暴露**
- [ ] 所有存储操作带 appId 前缀，**无跨小程序读写**
- [ ] 代码包**签名 + manifest 哈希校验**（G-45）
- [ ] 小程序销毁**级联释放**（G-43 Drop，无定时器泄漏）
- [ ] 小程序间通信**必须经宿主**（无共享全局）
- [ ] 敏感能力（支付/蓝牙/NFC）**需系统权限 + 资质校验**
- [ ] 明确标注 MVP = L1 逻辑隔离，**开放平台场景需 G-49（L2-L4）**

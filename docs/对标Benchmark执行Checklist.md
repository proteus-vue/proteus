# Proteus 对标 Benchmark 执行 Checklist

> 用法：**照着勾，勾完再跑**。任何一项未勾选即产出的对比数据一律作废
> 对标对象：uni-app x 官方性能基准（小米 Fold4 / 骁龙 8 Gen 3 / Android 16）
> 配套文档：《Proteus_对标uni-appx基准测试方案》（定义与口径以此为准）

## 阶段一：设备与环境准备

### 1.1 设备

- [ ] **主测设备**：小米 Fold4（骁龙 8 Gen 3 / Android 16）——建议采购同款
- [ ] 若非同款：已在报告中**明确标注设备差异**，且承诺只比倍率
- [ ] **中端对照设备**：荣耀 10（麒麟 970 / Android 10 / 60Hz）或同级
- [ ] 两台设备均已恢复出厂或清理至干净状态

> 📌 **为什么 Fold4 值得买**：设备成本 << 数据被质疑的代价。
> 同设备才能让倍率对比无懈可击。

### 1.2 环境控制九条（逐条勾选，缺一不可）

- [ ] ① **电量** ≥ 90%
- [ ] ② **性能模式**：已禁用节能模式
- [ ] ③ **性能模式**：已禁用性能模式
- [ ] ④ **后台应用**：已禁用所有其他应用
- [ ] ⑤ **温度**：已配置监控，确认无降频
- [ ] ⑥ **核调度**：Perfetto 观测，**被调度到超大核的数据已剔除**
- [ ] ⑦ **运行环境**：确认跑在**普大核**
- [ ] ⑧ **作弊禁止**：未使用应用层强制提升手段（nors 等）
- [ ] ⑨ **包名**：普通包名，未预载

### 1.3 AOT 状态（★ 最容易漏，也最关键）

- [ ] 已理解：**闲时优化是大多数用户的真实场景，为主数据**
- [ ] 已记录「初次安装」组数据
- [ ] 已执行 AOT 预编译命令：

```bash
adb shell cmd package compile -m speed -f <包名>
```

- [ ] 已记录「闲时优化」组数据
- [ ] **两组结果都已出**（只出一组视为未完成）

### 1.4 补充控制（Proteus 自身要求）

- [ ] 每次测试前**杀进程重启**
- [ ] 测试前**重启手机并静置 2 分钟**
- [ ] 所有测试均为 **release 包**（debug 数据无效）

### 2.3 渲染模式 × AOT 状态（4 组全测）

- [ ] Proteus · 拍平 · 闲时优化

### 2.4 重复与记录

### 2.6 对照组

### 3.3 采集方式（严格照搬基准）

- [ ] 已**关闭 HWUI 呈现模式条形图**
- [ ] 通过 **adb** 提取滚动期间数据

## 阶段四：测试三 · 组件级

> 基准只有定性展示、无量化数字——**我们量化出来就是差异化机会**。

### 4.1 rich-text

- [ ] 场景：**5 万字长文 + 59 张插图**
- [ ] 采集：加载耗时、滚动帧率、内存占用
- [ ] 已产出量化数字

### 4.2 swiper

- [ ] 场景：**无等待呈现 59 张图片**
- [ ] 采集：首图呈现延迟、切换帧率、图片内存
- [ ] 已产出量化数字

### 4.3 canvas（★ 先决策，再决定测不测）

- [ ] 已评估：2 万小球碰撞是**计算密集型**（每帧 2 万次位置更新 + 碰撞检测）
- [ ] 决策：□ 参与对比　□ **暂不参与（推荐，除非确认有优势）**

> 📌 此项考验逻辑层而非渲染层。若性能不占优，硬测会成为明显失分项。

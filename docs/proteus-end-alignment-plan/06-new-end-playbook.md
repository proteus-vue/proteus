# 06 · 新端对齐 Playbook（★本计划的核心交付）

> **本文件是"标准"的落点**：后续 iOS / Android / 鸿蒙 / Flutter **每一个端的对齐，都按这套流程执行**。
> 小程序为**首个执行端**（已跑通，见 M1/M2），本 Playbook 由它提炼。

---

## 0. 一句话

> **新端对齐 = ① 建该端能力标尺 → ② 对照 IR 找缺口 → ③ 三层绑定补齐 → ④ 门禁 + 待办清单。**

---

## 1. 前置：选定"对标端"

新端（如 iOS）要回答：**"这个端的原生能力，我们覆盖了多少"**。

| 端 | 对标源（覆盖度标尺） | 获取方式 |
|---|---|---|
| 微信小程序 | 官方组件文档（77 组件/793 属性） | 网页抓取（已实现） |
| **iOS** | **Apple HIG + UIKit 控件清单** | 人工整理 / 官方文档索引 |
| **Android** | **Material Design + Jetpack 控件** | 人工整理 |
| **鸿蒙** | **ArkUI 组件清单** | 人工整理 |
| Web | MDN HTML 元素 + WAI-ARIA | 人工整理 |

**要求**：对标源必须是**外部权威**（EA-1），且可**固化为快照**（EA-6）。

---

## 2. 步骤

### Step 1 · 建端标尺快照

```
docs/generated/end-<name>-capabilities.json   # 该端原生控件/能力清单（+ 属性）
```

形态与 `miniprogram-component-attrs.json` 一致（组件 → 属性数组）。

### Step 2 · 对照 IR 找缺口

```
IR 语义（component-ir/primitives.ts）
        ↕ 对照
新端能力清单
        ↓
缺口报告：本端有、IR 无（→ 评估是否登记新语义）
          IR 有、本端无（→ 标 unsupported 或找 fallback）
```

**关键**：IR 是**对齐基座**——两端都往 IR 靠，而不是"端 A 抄端 B"。

### Step 3 · 三层绑定补齐

| 层 | 新端要做的事 |
|---|---|
| Layer 1 IR | 若新端带来**新语义能力** → 登记 `primitives.ts`（谨慎，跨端承诺） |
| Layer 2 组件 props | 一般**不动**（同源码跨端）——只有新语义才加 |
| Layer 3 原生映射 | **主要工作**：实现 `SEMANTIC_BACKEND_MAP` 的该端映射 |

> ★**预期**：新端接入主要落在 Layer 3。**若发现要动 Layer 2/1，说明 IR 抽象不足——这是框架要修的，不是端要绕的。**

### Step 4 · 属性降级声明

新端对每个属性的三态（03-degradation-tiers.md）：supported / fallback / unsupported。

### Step 5 · 门禁 + 待办

- 更新 `alignment-ratchet.json` 棘轮水位
- 生成该端缺口待办（按重要性排序，同 `04-batches.md`）

---

## 3. 验收（新端对齐完成的定义）

| 项 | 要求 |
|---|---|
| 端标尺快照 | 已固化，可 `--check` |
| 属性覆盖 | ≥ 目标阈值（核心 ≥ 80%，宿主 ≥ 70%） |
| 降级声明 | 无空白格（EA-5） |
| Layer 3 映射 | `SEMANTIC_BACKEND_MAP` 该端条目完整 |
| 演示 | showcase 该端可跑（若该端支持跑宿主） |
| 棘轮 | 水位已登记，CI 绿 |

---

## 4. 反模式（禁止）

| 反模式 | 为什么禁止 |
|---|---|
| 从端 API 直接抄属性到组件 props（跳过 IR） | 破坏跨端一致性（EA-2）——端私有形态泄漏到开发者面 |
| 用"某端跑通"当作"跨端完成" | 未验证异端降级（G-31.2） |
| 手写覆盖清单自证覆盖 | 同义反复，缺口永不红（EA-1，本项目已踩坑） |
| 端私有属性不标 Tier | 开发者误以为跨端可用（EA-4） |
| 只改 Layer 3 而不回归标尺 | 缺口再次不可见（回到起点） |

---

## 5. iOS 作为下一个端（建议）

选 iOS 的理由：能力集与小程序重叠适中（相机/地图/权限/存储），且 UIKit 控件清单**相对稳定易整理**。

```
建议顺序：iOS（M7 验证 Playbook）→ 鸿蒙（ArkUI 结构清晰）→ Android → Flutter
```

**M7 的验收 = 用本 Playbook 把 iOS 对齐一遍跑通**，过程中发现的 Playbook 缺口回补到本文件。

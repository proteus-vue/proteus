# G-46 跨页资源所有权（G-43 所有权语义应用）

> **本篇定位**：本篇是「G-43 资源所有权（ownership）——Owned / Rc / Weak / Managed + 所有权图 + 确定性 Drop，语义见 docs/proteus-ownership-plan」在登录态 / Cookie / Token / 缓存域的应用实例；页面级联、登出清理等本域细节如下。

## 1. 核心命题

> **登录态归宿主所有，页面借用，销毁时归还。**

这与 G-43「宿主拥有渲染资源、Backend 借用」完全同构，是原则 #0 的第 10 次泛化的自然延伸。

## 2. 引用计数模型

| 引用类型 | 语义 | 应用 |
|---------|------|------|
| **Rc（强引用）** | 页面持有登录态，阻止销毁 | `pageAttach(pageId, session)` |
| **Weak（弱引用）** | 页面观察登录态，**不阻止销毁** | `pageObserve(pageId, cookie)` |
| **Drop（销毁）** | 页面关闭 → 级联清理其引用 | `pageDestroy(pageId)` |

```
宿主 (Rc=1，根所有者)
 ├── 页面 A (Rc+1，借用 session)
 └── 页面 B (Weak，观察 cookie，不阻止清理)
        ↓ 页面 A 关闭
  pageDestroy('A') → A 的强引用清空，但 session 仍归宿主
        ↓ 登出
  logout() → 宿主 Rc 归零 → L1/L2/L3 + 所有 Weak 引用全清
```

## 3. 为什么需要 Weak

**场景**：多个 WebView 页面观察同一份 Cookie（如「已登录」状态），但**不应因某个页面关闭就清掉登录态**。

- 用 Rc：页面关闭 → 引用减一，**最后一个页面关掉就丢登录态**（错误）
- 用 Weak：页面关闭 → 观察消失，**登录态仍归宿主**（正确）

→ **登录态用 Rc（谁在用），纯观察用 Weak（谁在看）。**

## 4. 循环引用检测

G-43 的循环检测复用：若页面 A 持有页面 B 的 Token 引用、B 又持有 A 的 Cookie 引用，**登出时双方互相等待 → 泄漏**。

**处置**：所有权图（DevTools 可视化，G-43）标记循环 → 强制打破（以宿主为根）。

## 5. 泄漏定位

```
📍 LeakyPage.vue:23  Cookie('sid') 被页面强引用，页面销毁时未归还
   └─ 持有链：宿主 → 页面 LeakyPage → Cookie
   └─ 建议：改用 Weak 观察，或显式 pageDestroy
```

**这是 G-46 在本域的可观测性增益**：把「内存泄漏」的排查思路用到「登录态泄漏」上。

## 6. 与登出级联的关系

`logout()` 必须：
1. 清空 L1（Cookie + Token + SSO 已用 code）
2. 取消 L2 进行中请求
3. 清空 L3 缓存（按 origin）
4. **清空所有页面的 Rc + Weak 引用**（跨页级联 —— 防悬挂指针）

**缺第 4 步 = 已注销页面仍持有旧 Token 引用 = 安全漏洞。**

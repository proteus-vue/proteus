> **原则溯源**：#13.23 所有权关系 100% 可观测

## 1. 传统 DevTools 为什么不管用

### 1.1 堆快照给你的是"对象"，不是"关系"

```
Heap Snapshot (8.2 MB)
├─ ArrayBuffer      ×1   8,388,608 B
├─ Object           ×1,247
├─ Closure          ×389
└─ (total 3,912 objects)
```

**你看到了什么**：有个 8MB 的 ArrayBuffer。
**你不知道的**：
- 谁持有它？
- 它该不该还活着？
- 在哪行代码创建的？
- 哪条引用链是意外的？

### 1.2 根因：GC 只知道"可达性"

```
GC 的视角：
  这个对象从 GC Roots 可达 → 不能回收

GC 不知道：
  这个对象是"还在用"还是"忘了放"
```

**"可达"和"该活着"是两回事** ——
一个被遗忘在全局缓存里的 8MB buffer 是"可达"的，但它不该活着。

### 1.3 所有权图补上缺失的信息

```
我们的视角（额外知道）：
  • 谁是 Owner
  • 谁是 Borrow（临时的）
  • 谁是 Weak（不阻止释放）
  • 什么时候创建的、在哪创建的
  • 预期什么时候释放
```

**有了"意图"信息，才能判断"该不该活着"。**

## 3. 四类检测

### 3.1 泄漏路径检测

**算法**：从"预期已释放"的节点反向追踪引用链。

```
输入：页面 A 已销毁
步骤：
1. 取 A 拥有的所有资源节点
2. 检查是否有节点仍为 alive
3. 对仍 alive 的节点，反向 BFS 找引用链
4. 输出最短路径 + 源码位置

输出示例：
  PageB.timer → closure → pageA.context
  📍 ProductCard.vue:47
```

**为什么传统工具做不到**：没有 Owner 信息，无法定义"预期已释放"。

### 3.2 长期借用检测

```
规则：Borrow 持续时间 > 阈值（默认 1000ms）→ 告警

原因：借用本应是临时的。
      长期借用通常意味着"业务把 Borrow 存起来了"
      → 这是 escape 的运行时表现
```

### 3.3 跨页面强引用检测

```
规则：页面 A 的 Owned 被页面 B 强持有 → 告警

原因：这会让 A 销毁时资源无法释放
解法：改用 transferTo（Move）或 weak
```

### 3.4 无主资源检测

```
规则：所有权图中 owner === null 的节点 → 严重告警

原因：无主资源 = 必然泄漏（没人负责释放）
     这通常是框架 bug 或 Backend 未正确登记
```

## 4. 与 G-19 DevTools 的集成

### 4.1 新增面板

```
Proteus DevTools
├─ Components      （已有）
├─ IR Inspector    （已有）
├─ Performance     （已有）
└─ ★ Ownership     （G-43 新增）
    ├─ Graph        所有权图
    ├─ Leaks        泄漏路径列表
    ├─ Timeline     资源分配/释放时间线
    └─ Quota        配额使用（与 G-39 联动）
```

### 4.2 时间线视图

```
内存
 │     ╭─╮                    ╭──╮
 │     │ │      ╭──╮          │  │
 │  ───╯ ╰──────╯  ╰──────────╯  ╰────
 │     ↑alloc   ↑alloc        ↑alloc
 │        ↑drop       ↑drop       ↑force-drop(page destroy)
 └──────────────────────────────────────→ 时间

  ▼ 标注：
    • 每个 alloc 有源码位置
    • 每个 drop 有释放字节数
    • 未配对的 alloc 高亮为可疑
```

**这直接解决了"内存曲线无法解释"的痛点** ——
每条上升和下降都能点到具体代码行。

## 5. 生产环境策略

### 5.1 开发期 vs 生产期

| 维度 | 开发期 | 生产期 |
|------|--------|--------|
| 所有权图维护 | ✅ 全量 | ⚠️ 采样或关闭 |
| 源码位置 | ✅ | ⚠️ 仅保留资源类型 |
| 借用追踪 | ✅ | ❌（性能考虑） |
| 泄漏检测 | ✅ 实时 | ✅ 采样上报 |

### 5.2 生产期最小化开销

```
策略：默认只维护计数，不维护完整图
     → 内存开销 O(1) 每资源
     → 开启「诊断模式」才构建完整图（可远程下发）
```

### 5.3 遥测

```
生产环境上报：
  • 未配对的 alloc 计数
  • 各 ResourceType 的总量
  • 页面销毁后仍存活的资源数（= 泄漏指标）
  • 配额使用率

→ 这些指标能直接衡量「内存健康度」
→ 传统框架只能上报"堆大小"，无法定位
```

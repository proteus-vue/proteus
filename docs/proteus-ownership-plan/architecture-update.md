# G-43 规约增量变更

> **定位**：合并进 `proteus-architecture` 的增量清单
> **规划体系**：55 → **56 份 plan**

---

## 1. 新增原则

### **原则 #13.21 资源所有权可插拔**

> 边界资源（GC 管不到的资源）的所有权管理必须是框架定义的语义层能力，
> 不得依赖特定语言或运行时的内存管理范式。

**推论**：
- 所有权模型是 SPI，不是硬编码策略
- 不同执行载体（G-40 JSI / AOT / WASM）可实现不同的所有权策略
- 但语义契约（Owned / Borrow / Weak / Drop）保持一致

---

### **原则 #13.22 确定性 Drop**

> 边界资源的释放时机必须是确定的，不得依赖 GC。

**理由**：GC 时机不确定会导致配额虚占、句柄耗尽、内存曲线不可解释。

**实现**：
- 业务显式 `drop()`
- PSS strict 下编译器自动插入作用域级 drop
- 页面销毁时强制回收（G-42 五原子）

---

### **原则 #13.23 所有权关系 100% 可观测**

> 所有权图必须完整维护 Owner / Borrow / Weak 关系 + 源码位置 + 生命周期，
> 且必须在 DevTools 可视化。

**理由**：传统堆快照只有"可达性"，没有"意图"，
无法判断资源"该不该活着"，因此泄漏难排查。

---

### **原则 #13.24 所有权可验证**

> 所有权实现必须通过 Conformance 测试（当前 33 项）。

**这是原则 #11 的第六次兑现**：
G-27 渲染 → G-38 编译 → G-39 运行时 → G-40 载体 → G-42 容器 → **G-43 所有权**

## 3. 铁律总表增量

```
新增铁律：
  G-43.1  边界资源必须归属某个 Owner
  G-43.2  Move 后原所有者不得再访问
  G-43.3  借用不得逃逸其作用域
  G-43.4  默认路径框架代管，业务零心智负担
  G-43.5  所有权关系必须 100% 可观测
  G-43.6  确定性 Drop，禁止依赖 GC 时机

新增补充规则：
  CMP067  禁止业务直接释放框架代管资源
  CMP068  跨设备转移必须原子
  CMP069  不可转移资源显式拒绝
  CMP070  释放失败禁止静默
  CMP071  Owned<T> 禁止 ref/reactive 包装
  CMP072  PSS strict 禁止引入未声明第三方库
  CMP073  配额记账必须与所有权图一致
```

**编号避让验证**：G-43.1-6 + CMP067-073 与既有 G-27~G-42 全部编号零冲突。

## 4. 方法论文档更新建议

`PROTEUS-METHODOLOGY.md` 建议增补两节：

### 4.1 第七次泛化

```
原则 #0 的泛化历程：
  G-31/32  不绑平台 API
  G-27/34  不绑渲染引擎
```

### 4.2 外部印证：鸿蒙

```
Proteus 的「约束换能力」思路并非孤例。
鸿蒙 ArkTS 通过限制 TS 动态特性换取 AOT 编译能力，
Stage 模型通过标准化生命周期换取容器可替换性，
分布式软总线通过统一抽象换取跨设备一致性。

这与原则 #0「统一语义收敛」是同一设计哲学的不同投影。
鸿蒙在 OS 层验证过的路径，Proteus 在框架层复现。
```

## 7. 风险边界（写入规约）

```
1. PSS 外无法完备检查
   → 动态 JS 下借用检查只能兜底，这是可判定性固有限制

2. 跨设备转移需真机验证
   → 本轮为接口定义 + 模拟验证，不宣称实测性能

3. Vue 响应式与所有权存在张力
   → CMP071 约束 + useOwned 替代方案，B5 专项验证

4. 渐进采用成本
   → 三级模式可选，存量代码无需改写
```

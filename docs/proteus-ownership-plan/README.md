## 三个核心问答

### Q1：是不是要用所有权替代 GC？

**不是。**

- JS 堆内对象（字符串、普通对象、数组）由 GC 管，**引入所有权是自找麻烦**
- G-43 治理的是 **GC 管不到的边界资源**：原生句柄、共享内存、定时器、订阅、文件句柄、流

```
GC 管「可达性」，所有权管「意图」。两者互补，不冲突。
```

### Q2：为什么能根治页面栈泄漏？

因为我们有 **IR 层，天然是单一 Owner**：

```
传统：JS 状态 ←→ 原生 View   （双边人工配对，漏一处就泄漏）
Proteus：IR 实例 ← 唯一真相 → Backend 挂载点（框架完全管控）
```

加上 **框架代管资源**（定时器/订阅/请求），
释放动作不在业务代码里 → 业务代码里没有"忘记"的机会。

### Q3：DevTools 为什么能直接指出泄漏路径？

因为所有权关系是**我们自己登记的**，不是 GC 猜的：

```
传统堆快照：这个对象还活着（可达）
我们：      谁持有它、凭什么持有、该不该持有、在哪行创建的
```

## 鸿蒙吸收（用户特别关注）

| # | 鸿蒙设计 | 我们的吸收 | 价值 |
|---|---------|-----------|------|
| 1 | **ArkTS 限制换能力** | **Proteus Safe Subset (PSS)** | ★ 借用检查从"兜底"升级为"完备" |
| 2 | Stage/Ability 生命周期 | G-42 容器生命周期官方实现 | 与成熟模型对齐 |
| 3 | 元服务 / 原子化服务 | G-42 `AtomicService` 容器形态 | 可分可合、免安装 |
| 4 | **分布式软总线** | **`Owned<T>.transferToDevice()`** | ★ Move 语义的跨设备版本 |

**第 1 点最关键**：它把我原先承认的"JS 无法完备检查"修正为
"PSS strict 内编译期完备，PSS 外运行时兜底"。

**第 4 点最有想象力**：传统跨设备是"重新加载"（状态丢、资源重建），
我们是**所有权转移**（状态不丢、资源不重建）。

## 诚实边界

| 限制 | 说明 |
|------|------|
| PSS 外无法完备检查 | 动态 JS 下借用检查只能兜底，这是可判定性固有限制 |
| 跨设备转移为模拟验证 | 真实分布式通道依赖宿主实现，需真机验证 |
| Vue 响应式存在张力 | CMP071 约束 + `useOwned` 替代，B5 专项验证 |
| 渐进采用有成本 | 三级模式可选，存量代码无需改写 |

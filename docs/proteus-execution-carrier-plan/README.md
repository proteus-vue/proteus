# G-40 执行载体抽象与 JSI 边界治理

> **一句话**：不要绑定任何一种执行载体。JSI 是插槽上的默认实现，不是架构绑定。

---

## 为什么需要 G-40

三条对 JSI 的批评**全部成立**，其中一条是质变：

| # | 批评 | 性质 |
|---|------|------|
| 1 | 跨边界成本不为零（27–181 ns/次，差 5 倍） | 可优化 |
| 2 | 字符串默认拷贝，仅 ArrayBuffer 能零拷贝 | 可优化 |
| 3 | **线程亲和性 → JS 单线程 → 实时系统不可用** | **架构死结** |

RN / uni-app / Lynx **绑定了 JSI**，所以第 3 条对它们无解。
Proteus 没绑定——`createEngine`（G-39）从第一天起就是插槽。

### 2. 两个载体的能力对比（批评三的机器证据）

| 维度 | JSICarrier | AOTCarrier |
|------|-----------|-----------|
| `threadAffinity` | **true**（受限） | **false**（真并发） |
| `trueConcurrency` | false | **true** |
| `realtime.capable` | **false** | **true** |
| `scalarCall` 成本 | 27 ns | **0**（无边界） |
| Worker 数据共享 | 需序列化 | **共享内存** |
| Conformance 结果 | 38 PASS + 4 SKIP | **42 PASS** |

**JSI 的 4 项 SKIP 就是它的能力边界；AOT 的 42 项 PASS 证明路径可行。**

## 六条铁律

| 编号 | 铁律 |
|------|------|
| **G-40.1** | 业务代码禁止假设 JS 运行时存在（静态可检查） |
| **G-40.2** | 三条执行路径语义等价（conformance 强制） |
| **G-40.3** | ★ 实时能力禁止 JS 驱动，必须原生闭环 |
| **G-40.4** | 大块数据（>4KB）强制零拷贝通道 |
| **G-40.5** | RenderBackend 必须实现 `commitBatch` |
| **G-40.6** | 执行载体可观测，`rtJsDrivenViolations` 恒为 0 |

补充规则 **CMP044–CMP050**（避让 G-39 的 CMP035-043）。

```

                  按场景选，业务代码不变
```

## 诚实边界

G-40 **不承诺**：

| 不承诺 | 原因 |
|--------|------|
| JSI 路径能解决线程亲和性 | 固有约束，只能绕开不能修复 |
| AOT 支持全部 JS 动态特性 | 需静态子集 |
| **批处理收益的具体倍数** | **需 M1 实测，现有为推算** |
| 零拷贝在所有端可用 | 依赖端能力 |
| 实时能力在 Tier 3/4 可用 | 无原生能力宿主 |

**CMP046：未实测（`measured: false`）的数据禁止对外宣称。**

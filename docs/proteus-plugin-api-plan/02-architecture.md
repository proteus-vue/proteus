# G-58 架构

> **声明式优先，代码只是少数派。**（Zed 实证，非推演）

---

## 1. 三层插件形态

```
┌──────────────────────────────────────────────────┐
│ Tier 0  声明式插件                                │
│   plugin.toml + 数据文件（JSON）                  │
│   主题 / 片段 / 菜单 / 快捷键 / 配置 / 图标        │
│   ★ 零代码、零 WASM 实例、零运行时开销            │
├──────────────────────────────────────────────────┤
│ Tier 1  WASM 插件                                 │
│   编译目标 wasm32-wasip2                          │
│   语言服务器桥接 / 自定义面板 / 框架语义消费        │
│   ★ 沙箱内、capability 授权、资源限额              │
├──────────────────────────────────────────────────┤
│ Tier 2  外部进程插件                              │
│   LSP / DAP 服务器（rust-analyzer、gopls…）       │
│   ★ 原生进程，不在沙箱内 → 需显式高权限授权        │
└──────────────────────────────────────────────────┘
```

### 为什么必须有三层，不能只要 WASM

**Tier 2 存在的硬理由**：语言服务器是原生二进制，
体积大（数十 MB）、需访问完整项目文件与工具链、
且通常是**既有开源资产**（rust-analyzer、gopls、ts-server）。

**把它们塞进 WASM 不现实，也没必要。**

但 Tier 2 是**权限最高**的一层——它本质上等于"运行一个用户信任的可执行文件"。
所以：

| Tier | 沙箱 | 授权级别 |
|------|------|---------|
| Tier 0 | N/A（无代码） | 无需授权 |
| Tier 1 | ✅ WASM 沙箱 | capability 逐项授权 |
| Tier 2 | ❌ 原生进程 | **显式高权限授权**（等同运行外部程序） |

> **诚实标注层级差异，比假装"都很安全"更专业。**

## 2. 宿主架构

```
StudioShell (G-56)
     │
     ▼
PluginHost                        ← 本份新增
  ├─ ManifestLoader   解析 plugin.toml，校验声明
  ├─ CapabilityGranter  capability 授予与运行时校验
  ├─ WasmSandbox      wasmtime 实例池（每插件独立）
  ├─ ResourceGovernor CPU / 内存 / 超时限额
  └─ ApiRouter        按 apiVersion 路由到对应 WIT 版本
     │
     ▼
FrameworkKnowledgeProvider (G-55 内核，零改动)
```

**PluginHost 是唯一新增组件**，其余全部复用。

## 3. ★ 内置功能与插件同权（架构试金石）

```
Studio 内置面板  ──┐
官方插件        ──┼──→ 同一个 PluginHost + 同一套 API
第三方插件      ──┘
```

**这意味着 Studio 自己的"框架语义面板""断言结果面板"**
**必须用插件 API 实现，不得走内部后门。**

### 为什么这是可断言的

```
步骤 1  记录 PluginHost 暴露的 apiSurface 快照 S1
步骤 2  将某个内置面板改写为插件实现
步骤 3  记录快照 S2
断言    S1 === S2
```

**若内置面板改用插件 API 时需要新增特权接口，说明 API 设计有缺口。**

延续 G-56.2「自有宿主不享有内核特权」——
**本份把它从"宿主"推广到"插件"。**

## 4. 插件生命周期

```
install → validate → grant → activate → run → suspend → uninstall
   │          │         │        │
   │          │         │        └─ Tier1: 实例化 WASM
   │          │         │           Tier0: 仅注册贡献点（★ 不实例化）
   │          │         └─ capability 授予（用户可见）
   │          └─ 清单校验 + API 版本兼容检查
   └─ 来源校验与完整性
```

**关键分叉在 activate**：

| Tier | activate 做什么 |
|------|----------------|
| Tier 0 | **只注册贡献点，不创建任何运行时** |
| Tier 1 | 创建 WASM 实例（受限额约束） |
| Tier 2 | 启动外部进程（需高权限授权） |

## 6. 不做的事

| 不做 | 理由 |
|------|------|
| 兼容 `.vsix` | G-56.9，技术地基不同 + 许可禁止 |
| 插件直接访问文件系统 | Extism 实证：显式传递数据，不放开直连 |
| 插件间相互调用 | 引入耦合与权限传递难题，阶段 1 不做 |
| 自动更新不经用户确认 | 供应链安全，必须显式 |

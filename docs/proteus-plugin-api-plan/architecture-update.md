# 架构更新（G-58）

## 新增原则

- **#13.72** 扩展来源无关：内置功能、官方插件、第三方插件同权
- **#13.73** 默认零权限：能力必须显式声明并逐项授予
- **#13.74** API 只增不改：版本化并存，不兼容变更仅限提案阶段

## 第 21 次泛化

```
G-54  不绑定 IDE          （编辑器形态，第 18 次）
G-56  不绑定宿主来源      （宿主可以自研，第 19 次）
G-57  不绑定可观测性来源  （协议可以叠加，第 20 次）
★ G-58  不绑定扩展来源    （扩展可以来自任何一方，第 21 次，本份）
```

> **官方序注（决策 #395）**：本份为第 **21** 次（G-55 为 G-54 落地不占序）；原稿误作第 18 次。

**核心命题**：

> 内置功能与第三方插件，通过**同一套 API 与权限模型**接入，无一例外。

**这是 G-56.2「自有宿主不享有内核特权」的推广**：
从"自有宿主"推广到"自有插件"。

## 成熟度模型更新

```
L0 文档自检        ← G-50
L1 IR 模拟         ← G-51
L2 真运行时        ← G-51 + G-52
L3 跨设备（云端）  ← G-52/53
L4 开放生态        ← G-50（依赖 G-49 L3）
L5 开发者门户      ← G-50
L6 治理与分佣      ← G-50
```

**G-58 不改变成熟度层级**，但为 **L4 开放生态**提供了
在自有宿主（Studio）上的落地路径——此前 L4 只在 G-50 平台侧定义。

## 与既有体系互校

| 对接 | 关系 |
|------|------|
| **G-51** `TestIRRunner` | 经 capability 暴露给插件跑 conformance |
| **G-54** 六项能力 | 打包为 `kernel.*` capability |
| **G-55** 知识内核 | **零改动**，经插件 API 暴露 |
| **G-56** StudioShell | **零改动**，PluginHost 挂在其上 |
| **G-58** Inspector | 插件可消费三层数据（只读） |

**新增类型仅 4 个**：`PluginHost` / `PluginManifest` / `Capability` / `ApiVersionSpec`。

# G-58 铁律

> 八条铁律。其中 **G-58.1 是红线**——无例外、无降级。

---

## 铁律

### G-58.1 — 内置功能必须走插件 API（红线）

Studio 的内置面板 **不得使用内部后门**，
必须与第三方插件调用**同一套 `PluginHost` 公开方法**。

```
步骤 1  记录 apiSurface 快照 S1
步骤 2  将内置功能改写为插件实现
步骤 3  记录快照 S2
断言    S1 === S2
```

**依据**：VSCode 官方文档——
"many core features of VS Code are built as extensions
and use the same Extension API."

> **若内置功能能开后门，插件 API 就是摆设。**
> 这是可机器断言的架构试金石，不是口号。

**这条不给降级路径。**

---

### G-58.2 — 默认零权限，显式授予，只读优先

- 未声明的 capability 一律拒绝
- `network` / `spawnProcess` / `device.attach` **必须带白名单**
- 越权返回 `denied`，**不终止插件**
- **插件获得的是"查询结果"，不是"内核控制权"**（只读优先）

**依据**：VSCode Extension Host 拥有与 IDE 相同的完整权限，
导致 2025 年出现恶意扩展利用下架扩展名重新发布的事件（ReversingLabs）。

---

### G-58.3 — 声明式优先

> **判断标准：能不能用 JSON 表达完？能 → 不该写代码。**

主题 / 片段 / 菜单 / 快捷键 / 配置 / 图标 → **Tier 0，零 WASM 实例**。

**依据**：Zed 官方文档——
"most extensions will work properly without any Rust code present."

---

### G-58.4 — API 只增不改，版本化并存

已稳定的 WIT 版本**冻结，永不修改**；
新增能力 = 新开次版本文件；
不兼容变更**只能发生在提案阶段**。

**依据**：Zed 用 `since_v0_0_1` → `since_v0_8_0` 并存，
官方说明"ensures backward compatibility for older extensions
while allowing the API to evolve"。

> 版本号规则：主版本=不兼容（禁止对稳定 API 做）/
> 次版本=新增（唯一允许的演进）/ 修订=无接口变化。

---

### G-58.5 — 崩溃隔离，插件不得拖垮宿主

WASM trap、panic、无限循环 → **隔离并记录**，宿主继续运行。
资源超限 → 终止该插件，**不影响其他插件**。

延续 G-51 INV-02。

---

### G-58.6 — 资源限额强制执行

`memoryMB` / `cpuMsPerCall` / `timeoutMs` 必须在清单声明或取默认值，
运行时**强制校验**，超限即终止。

> 无限额的沙箱不是沙箱。

---

### G-58.7 — 能力探测必须是纯元数据查询

`supports(cap)` **零副作用、零网络、零内核调用**。

> **严禁"发一个探测请求看会不会崩"**——
> 这是 G-54 初版踩过的坑（传 `payload: null` 试探，在内核里直接崩）。

---

### G-58.8 — 提案 API 不得用于发布

声明 `proposals` 的插件：可本地开发调试，**禁止发布到市场**。
这是**发布期强制校验**，不是君子协定。

**依据**：VSCode——
"Proposed APIs are subject to change... should not be used in
published extensions."

---

## 反模式（AP-EX-01 ~ AP-EX-07）

| ID | 反模式 | 后果 |
|----|--------|------|
| **AP-EX-01** | 给内置功能开 API 后门 | 插件 API 形同虚设，无人验证其可用性 |
| **AP-EX-02** | 插件默认全权限 | 重蹈 VSCode 覆辙，供应链攻击面 |
| **AP-EX-03** | 简单功能也要求写 WASM | 违背声明式优先，抬高生态门槛 |
| **AP-EX-04** | 修改已稳定的 WIT 版本 | 破坏老插件，生态信任崩塌 |
| **AP-EX-05** | 用"发请求试探"探测能力 | G-54 已验证：会在内核崩溃 |
| **AP-EX-06** | 插件崩溃不隔离 | 一个坏插件拖垮整个 IDE |
| **AP-EX-07** | 提案 API 用于生产发布 | 版本一变更，线上插件全崩 |

# G-57 安全与隐私红线

## 1. 红线一：Debug-only（编译期剔除）

**Release 构建中，Inspector 必须不存在——不是"不启用"，是"编译期没有这段代码"。**

| 纪律 | 内容 |
|------|------|
| 剔除方式 | **编译期**（如 Dart 的 tree-shake / C 的 `#ifdef`），**不是运行时 if** |
| 验证方式 | Release 包扫描 `ext.proteus.*` 字符串，必须**零命中** |
| 参考 | Flutter VM Service **只在 Debug 模式启用**，Release 完全不启用 |

**为什么必须编译期？**
运行时判断的代码仍在包里，可被逆向触发；编译期剔除则**攻击面为零**。

## 2. 红线二：一次性 token 鉴权

**参照 Flutter VM Service 的做法**：连接 URL 带一次性 security token，每次启动变化。

| 纪律 | 内容 |
|------|------|
| 生成 | 每次进程启动随机生成 |
| 传输 | 仅出现在 debug 连接信息中 |
| 校验 | 不匹配 → `UNAUTHORIZED` |
| 生命周期 | 进程结束即失效 |

## 3. 红线三：绑定 localhost 优先

- **默认只监听 localhost / loopback**
- 局域网暴露**必须显式开启**（开发者主动 opt-in）
- 通过 `adb forward` 建立 USB 隧道时，端口不暴露到网络

**理由**：G-57 暴露的是 App 内部结构（SPI 拓扑、隔离域），
一旦无鉴权暴露在公共网络，等于**把架构图交给攻击者**。

## 4. 红线四：绝不采集用户数据

**这是 App Store 审核的生死线。**

| 上报 | 不上报 |
|------|--------|
| SPI 后端激活状态 | 用户身份 / 账号 |
| 分层违规（代码结构问题） | 用户内容 / 输入 |
| 隔离域状态 | 设备标识符 |
| conformance 断言结果 | 位置 / 通讯录 |
| 框架内部性能指标 | 任何 PII |

**G-57 上报的是"框架自己的健康度"，不是"用户的行为"。**

## 5. 后台运行约束（对 Agent 模式）

| 平台 | 约束 |
|------|------|
| iOS | 进后台 **socket server 会被关闭**；保持常驻需声明 background mode（audio/location/voip），**滥用会被拒审** |
| iOS | `BGProcessingTask` **仅几分钟**，且用户长期不打开 App 会逐渐停止调度 |
| Android | 充电时 `WorkManager` 无执行限制，较宽松 |

**因此：**

- Inspector 的**实时查看**模式 → iOS 前台可用，后台中断
- Agent 的**后台跑测**模式 → 必须**分块 + 断点续跑**，且需 `expirationHandler`
- 任务被系统跳过 → 记 `SKIP`，**不是 `FAIL`**

## 6. 诚实边界

- 上述 iOS 后台结论来自 Apple 官方文档与社区实测，**非本框架实测**
- 「Release 零命中」的扫描验证**尚未实现**，需在 CI 中落地
- 局域网暴露的**实际攻击面**未做渗透测试

# G-57 Proteus Inspector：三层可观测性叠加

> 原则 #0「不绑定」系列，第 20 次泛化（官方链：…G-54=18、G-56=19，G-55 落地不占序；#394 修正，原稿误作 17）。
> 编号：G-57 · 依赖：G-19 / G-51 / G-54 / G-56 · 被依赖：后续 plan 按当时段位另定（G-58 已由 plugin-api 占用，不依赖本份）

## 1. 问题

移动/前端框架的运行时可观测性存在一道**割裂**：

| 数据 | 谁能拿到 | 谁拿得到 |
|------|---------|---------|
| 内存、CPU、帧率、网络、widget 树 | 系统 / 运行时 | Flutter DevTools、Flipper、CDP |
| SPI 后端拓扑、分层违规、隔离域状态、conformance | 只有框架自己 | **无工具** |

**结果是"看得见数字，看不见结构"。**

一个典型场景：Flutter DevTools 告诉你"内存涨了 50MB"。你看到数字了，
但**不知道这 50MB 属于哪个隔离域、走的哪个 SPI 后端、是否违反分层**——
**只能靠猜和经验去定位。**

## 2. 关键澄清：是叠加，不是替代

本份**不重新造运行时探针**。

通用运行时数据（L0）是必要基座，由宿主/系统提供，成熟且免费：

- Flutter → Dart VM Service
- React Native → Flipper / Metro
- Web → Chrome DevTools Protocol

**G-57 只做两件事：**

1. **给 L0 的每个指标打上框架语义标签**（L1）← 本份的核心增量
2. **补齐只有框架知道的语义数据**（L2）

> **不是"我们的数据 vs 他们的数据"，而是"他们的数据 + 我们的标签"。**

## 3. 第 20 次泛化：不绑定可观测性来源

```
不绑定后端 → 不绑定环境 → 不绑定设备 → 不绑定编辑器
    → 不绑定宿主来源 → ★ 不绑定可观测性来源
```

**Inspector 不假设运行时数据从哪来。**
它接受任意 L0 源（VM Service / Flipper / 自起服务 / 系统 API），
**只负责叠加语义层**——L0 从哪来无所谓，只要能给出指标。

## 4. 与既有体系的关系

| | 关系 |
|--|------|
| **G-19** | 运行时面板（trace/timeline/state/perf/error）—— **同一数据源的不同消费端** |
| **G-54** | 编码期六项框架独占能力—— **G-54 是静态的，G-57 是运行时的** |
| **G-51** | TestIRRunner 报告可序列化—— G-57 沿用同一规约 |
| **G-56** | Studio 宿主壳—— G-57 的 L0/L1/L2 是其设备面板的数据源 |

## 5. 诚实边界

- G-57 **不实现**运行时探针（内存/CPU 采样）—— 那是宿主/系统的职责
- L1 的语义标注质量**完全取决于拓扑覆盖率**，覆盖率低时 L1 意义有限
- 本份的 L0 源在参考实现中是**模拟数据**，真实接入需按 04 章对接

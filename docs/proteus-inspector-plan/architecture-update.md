# 架构更新（G-57）

## 新增原则

- **#13.69** 可观测性叠加：运行时数据用宿主的，框架只叠加语义
- **#13.70** 语义标注：每个运行时指标都应可关联到框架结构
- **#13.71** 观测出口协议化：内部面板与桌面工具共享同一数据源

## 第 20 次泛化

```
不绑定后端  → 不绑定环境  → 不绑定设备  → 不绑定编辑器
   → 不绑定宿主来源  →  ★ 不绑定可观测性来源
```

> **官方序注（决策 #394）**：本份为第 **20** 次（前承：G-51=15 验证环境、G-52=16 设备形态、G-53=17 设备供给、G-54=18 IDE 形态、G-56=19 宿主来源；G-55 为 G-54 落地不占序）。原稿误作第 17 次。

**含义**：Inspector 不假设运行时数据从哪来。
换宿主、换平台、换探针，**数据模型不变**。

## 三层模型入档

| 层 | 内容 | 来源 |
|----|------|------|
| L0 | 通用运行时指标 | 宿主/系统 |
| **L1** | **语义增强指标** | **L0 × 框架拓扑** |
| L2 | 框架语义数据 | 框架独占 |

**L1 是本份核心增量**——把"数字"变成"带结构的数字"。

## 与既有体系互校

- **G-19** 运行时面板 → G-57 的 **L0 数据源**（不重复采集）
- **G-54** 编码期六项能力 → G-57 的 **L2 静态形态**
- **G-51** TestIRRunner → 共享**可序列化规约**
- **G-56** Studio → G-57 的**消费端**
- **G-52** 跨设备 → 提供**隔离域**概念

## 成熟度影响

G-57 不改变 L0-L6 成熟度层级，但**提升 L2 层的可诊断性**：

```
L2 真运行时
  ├─ 之前：能看到运行时指标，靠猜定位结构问题
  └─ 现在：指标自带框架结构标签，直接定位到隔离域/后端
```

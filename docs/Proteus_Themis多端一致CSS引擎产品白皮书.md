| 问题 | Themis 的回答 |

## 1. 命名

### 1.1 命名逻辑

框架名 **Proteus** 取希腊海神"千变万化"之意；动画引擎 **Morpheus**（梦神，morph = 形变）延续了这个体系。CSS 引擎的命名应指向它的核心隐喻：**裁决与律法**。

CSS 层叠的本质是一场**法庭审判**——每条声明都要出示证据（特异性、@layer、源序、`!important`），由一位不偏不倚的裁判决定谁赢；而 Profile 就是一套**全端共同遵守的律法**。这就是 Themis。

### 1.2 候选与查重结论

| 候选 | 语义 | 查重结果 | 评估 |
|---|---|---|---|
| 🥇 **Themis** | 希腊正义女神：手持**天衡**（权衡 = 特异性权重）与**解纷之角**（裁决 = 层叠 winner），司掌律法与秩序（Profile = 律法） | ⚠️ 有占用但**均不在同领域**：Cossack Labs Themis（移动端加密库）、Themis CMS | **推荐**。层叠 = 裁判的隐喻最贴，双后端"同律同判"的故事自洽 |
| 🥈 **Panoptes** | 百眼巨人 Argus Panoptes 的本名，"全视" | ✅ 仓内/同领域未发现占用 | 语义贴"三层门禁全端对拍"，但作为产品名不易读 |
| 🥉 **Eunomia** | 秩序女神，"良好的秩序" = 多端一致 | ✅ 未发现占用 | 雅致但过于生僻 |

### 1.3 必须排除的名字

| 名字 | 排除原因 |
|---|---|
| ~~**Argus**~~ | **仓内已登记占用**——《全链路内存安全与可归因性方案》（Mnemosyne）的备选名（`docs/Proteus_全链路内存安全与可归因性方案.md:4`），同一命名体系内不得撞名 |

| ~~**Kratos**~~ | 游戏文化强占用；~~**Hermes**~~ | JS 引擎重名（Morpheus 方案已裁定） |

### 1.4 建议

**主推 `Themis`，备选 `Panoptes`。** 下文统一以 **Themis** 指代本引擎；定名前建议再做一次 npm / crates.io / 商标检索（本文档查重基于公开检索，不构成商标意见）。

## 2. 产品的世界：三个端，三套真相

在 Themis 之前，Proteus 的样式链路是**三套互不相干的实现**（`docs/proteus-css-engine-plan/01-baseline-survey.md` 勘察原文）：

- **Web**：浏览器原生 CSSOM——唯一完整实现；
- **Skyline**：微信容器——唯一刚性外部约束；
- **App**（iOS/Android/鸿蒙 共用一套 Rust 引擎）：当时仓内文档的原话是——**"App 端无 CSS 引擎"**，样式在编译期被 `parseStaticStyle` 直折为引擎字段，无层叠特异性、无继承、`margin` 与 `margin-top` 无法正确竞争、动态 `:class` 要么运行期线性匹配要么直接判不支持。

每一个写过跨端样式的人都认识这个局面：**同一份样式表，三个端各自解释，"看起来差不多"靠肉眼验收，"哪里不一样"靠上线后用户发现。**

行业给过两种答案，都不够：

- **运行期 CSS 引擎**（Kraken / Lynx / WebF）：把一个子集引擎塞进客户端——每次启动都付解析、匹配、布局的税，而且"一致"由引擎自己说了算，各宿主引擎版本还会漂移；
- **放弃 CSS**（RN / Flutter）：StyleSheet 对象 / widget 样式——没有层叠、没有继承、没有选择器，能力缺失靠手写平台分支，一致性依然靠肉眼。

**Themis 给出第三种答案：把 CSS 引擎整个搬进编译期，把"一致"从愿望变成门禁。**

## 3. 产品主张（三条）

**主张一 · 算完，再上线。**
CSS 的全部语义——五级层叠、继承、var()/calc()、动态类影响——在构建期算完并算对。运行期只做 O(1) 位图查表与字段应用，选择器匹配/层叠/单位换算在调用栈中**零出现**（INV-CE-03，可用 profile 证明）。启动时不付样式税。

**主张二 · 真值只有一个。**
多端一致性的 `expected` **只有一个来源：Web 端浏览器真实渲染**。不是三端两两互比，不是"以引擎为准"，更不是"被测端自证"。基准三件套（计算样式 / 几何 / 真截图）golden 冻结入仓 + 环境指纹登记，变更须审批、腐化可检测。端间互比只能用于诊断，**不得定案**（INV-CE-09）。

**主张三 · 失败要响亮。**
不能多端一致落地的写法，在 **Web 构建期就报错**（全端禁用）——宁可收窄 Profile，也不允许各端各自近似产生静默偏差；不能语义等价降级的字段，**如实拒绝并给出原因**，不做"看起来差不多"的近似。**用构建失败换静默错位。**

## 4. 工作原理：一条五步管线

```
SFC <style>
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│  ① 解析     长手展开 · @layer 收集 · 特异性计算           │
│  ② 索引匹配 按 key selector 分桶 · 右→左链匹配            │
│  ③ 五级层叠 importance → @layer → 特异性 → 源序             │
│  ④ 继承+计算值 var() 替换 · calc() 常量化 · env() 引用      │
│  ⑤ 动态类预计算 属性维度分解 · 互斥分组 · 爆炸保护          │
└───────────────────────────┬─────────────────────────────┘
                            ▼
                   StyleIR（77 字段闭集 · 版本化）
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
   Web Applier         Skyline Applier      App Applier
   （A 档：IR 作       （wxss 子集）       （Rust 引擎字段
    基准载体）                             + 绘制属性）
        └───────────────────┼───────────────────┘
                            ▼
              三层一致性门禁（全棘轮 · expected = Web）
```

关键设计——**长手层层叠**：CSS 层叠按长手属性判定，`margin: 0` 与后写的 `margin-top: 5px` 竞争的是**同一属性**。在简写层折叠（多数子集引擎的做法）做不到这一点；Themis 的规则表存长手声明，层叠后逐长手取唯一胜者——这是唯一能和浏览器 `getComputedStyle` 对拍收敛到 100% 的做法。

## 5. 七大能力

### 5.1 全语义层叠（Five-Level Cascade）
`!important` → `@layer` → id/类/元素特异性 → 源序，完整实现；支持 id 选择器、命名层、CSS 宽关键字（inherit/initial/unset）、`var()` 含 fallback、结构伪类与 `:not()`。静态类、复合类、后代/子组合全支持。

### 5.2 动态样式 O(1)（Compiled Dynamic Classes）
`:class="{ on: x }"` 在编译期**按属性维度分解**成小查找表（非 2ⁿ 全量枚举）；互斥分组仅在**可证明**时压缩（同源标识符 + 不同字面量、三元两分支）；爆炸保护三档（表 >16 / 值 >8 告警，候选 >32 直接报错）。运行期位图 O(1) 查表——profile 实测**读次数 == 字段数**，并提供表格回退语义。

### 5.3 降级配方（Degrade Recipes）
某端不原生支持某字段时，编译期把 IR 改写为**语义等价**形态：`grid→flex`（仅单行网格——多行/跨行/命名线**拒绝**并给出原因）、`gap→margin`（半距法，首/末项减半）。每个配方返回容器字段 + 子项叠加字段 + 等价性说明（进诊断），应用后由 conformance 与"原 IR 在 Web 的渲染"**对拍验证**（INV-CE-05：编译期、语义等价、可观测）。

### 5.4 构建期拦截（Profile Lint）
E-CSS / W-CSS 两族诊断接入 **Web 构建链**：Profile 外写法在 Web 端也 rc=1 真实拦截。**Web 跑通 = 各端一致**——这条等式由编译器保证，不由约定保证。

### 5.5 三层一致性门禁（Three Ratcheted Gates）
- **① 基准等价**（编译期·硬门禁）：Node/Rust 双后端 IR 逐字节相同；IR vs 浏览器 `getComputedStyle` **逐属性比对**；
- **② 数值等价**（运行期·硬门禁）：各端 snapshot ≡ Web 快照 **≤0.5dp**，容差逐字段（禁全局阈值）；
- **③ 像素观察**（运行期·非门禁）：每端真截图与 Web 基准截图并排登记，缺证据如实标注。
三层**全部棘轮**（只增不减）。

### 5.6 双后端同律（Dual Backend Parity）
同一 SFC，TypeScript 实现与 Rust 实现产出**逐字节相同**的 StyleIR（INV-CE-01）——编译器自身也是被对拍的对象，IR Golden 有真二进制对拍与破坏性验证。

### 5.7 全程可回放（`proteus explain --style`）
每条声明为什么赢、为什么输，完整 trace：选择器匹配过程、命中的 @layer、特异性权重、源序、简写展开来源（`margin-top ← margin`）、继承链。**编译期 CSS 也有 DevTools。**

### 5.8 内置环境变量（Built-in Env Vars）
`var(--pf-status-bar-height)`、`var(--pf-inset-bottom)`、`env(safe-area-inset-*)`、`calc(<env> ± Npx)` 编译期识别为**运行期环境引用**（envRef 变体）：变量名解析成字段索引，运行期一次表查找——环境相关值（安全区/系统栏）与"零运行期解析"并存。`calc()` 常量化与 App 折叠面共用 `calc-fold.ts` 唯一实现。

## 7. 横向对比

| 维度 | **Themis (Proteus)** | uni-app x (uvue) | Taro | React Native | Flutter | Kraken / Lynx / WebF |
|---|---|---|---|---|---|---|
| CSS 语义完整度 | 完整层叠（@layer/id/特异性）+ 继承 + 计算值 + var()/calc() | 子集折叠，无完整层叠 | 依赖小程序容器（Web/Skyline 各异） | 无 CSS（StyleSheet + Yoga） | 无 CSS（widget 样式） | 运行期子集引擎 |
| 样式计算时点 | **编译期** | 编译期折叠 | 运行期 | 运行期 | 运行期 | 运行期 |
| 运行期样式成本 | O(1) 查表 | — | 匹配 + 容器开销 | JS diff | rebuild | 解析 + 匹配 + 布局 |
| 动态类样式 | 编译期属性分解 + 位图 O(1) + 爆炸保护 | 运行期匹配 | 运行期匹配 | JS diff | rebuild | 运行期匹配 |
| 一致性的 `expected` | **Web 真实渲染（唯一基准）+ 三层棘轮门禁 + golden 冻结** | 无统一基准 | 无 | 无 | 无（自定标准） | 引擎自定义（宿主间还会漂移） |
| 能力不支持时 | 编译期报错，或配方降级（可对拍）；**拒绝静默近似** | 静默缺失或端差 | 端差手工兼容 | 手写平台分支 | 手写适配 | 引擎内近似 |
| 可调试性 | `proteus explain` 全 trace | 有限 | 有限 | 手段少 | widget 级 DevTools | 各自 DevTools |
| 编译器自证 | Node/Rust 逐字节对拍 | 无 | 无 | — | — | — |

**一句话差异化**：其他框架把"跨端一致"当作**愿望**——各端尽量实现、文档约定、肉眼验收；Themis 把它当作**可判定的门禁**——基准唯一、逐属性对拍、棘轮只增不减、基准不得自证。代价是收窄了 CSS 面——而这正是产品决策：**一条写法是否进 Profile，判据不是"是否符合 CSS 标准"，而是"它能否多端一致地落地"。**

## 8. 开发者体验

**写错即构建失败，错误信息即修复指引：**

```
error E-CSS-004: :class 表达式无法静态枚举（:class="runtimeVar"）
  → Profile L5 禁止项。改用有限候选集（对象/数组/三元字面量），
    或将动态样式收敛为互斥分组的枚举写法。

warn CSE_DYNCLASS_TABLE_EXPLOSION: 单节点动态类表 > 16（当前 23）
  → 拆分绑定或合并候选类，减少属性维度。
```

**样式问题不再靠猜：**

```console
$ proteus explain --style --node page-header
margin-top: 5px    ← margin-top (style.css:42)  · specificity (0,1,0) · source order wins
                     over margin (style.css:17, expanded to margin-top: 0)
                     layer: components > base
```

**内置变量开箱即用：**

```css
.page-bar { height: var(--pf-status-bar-height); }
.content  { padding-top: var(--pf-inset-top);
            padding-bottom: calc(var(--pf-inset-bottom) + 12px); }
```

## 9. 边界与承诺（诚实边界 = 产品原则）

Themis 把"不支持什么"写进产品文档——这本身就是与其他框架最大的不同。

**v1 不做（显式计数，不静默）：**
- `@media` / `@supports` / `@container` / `@import` 跳过并计数——**不假装响应式**；断点适配走组件/JS 通道
- 兄弟组合、属性选择器、伪元素不支持（显式记 skipped）；含动态类的后代规则（`.on .child`）v1 仅告警
- 不追求"Web CSS 五端像素级兼容"（Flutter/Yoga 的路）；不引 Blink/WebF 路线；不自研文本基础设施（字体/BiDi/RTL/OpenType）

**对外表述纪律（禁语）：**
- 不得说"像素级一致"——判据② 是 ≤0.5dp 数值等价，判据③ 像素仅是非门禁观察
- 不得说"支持完整 CSS"——是"Profile 内完整语义 + Profile 外构建期拦截"
- 不得说"性能无成本"——成本前移到了编译期（动态类逐组合重算、lint 全量扫描）

**常驻风险与升级路径：**
Taffy ⇄ Blink 的布局语义差（margin 折叠、百分比基准等）是结构性的常驻风险。已预登记 **A→B 升级触发准则 E1–E4**（判据封顶/原地打转/基准不稳/降级不可收敛，均需证据包确认"非实现缺陷"才可触发）：一旦触发，切 B 档——IR 成为含 Web 在内的全端唯一标准。**"感觉对齐太难"不构成触发。**

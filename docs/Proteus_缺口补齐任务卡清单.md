- [ ] 模块可独立引用

## 卡 I1 · 指令集规格化与版本化

| 项 | 内容 |
|---|---|
| **优先级** | P0（协作契约） |
| **依赖** | 无 |
| **估时** | 1–1.5 人周 |

### 现状
`render-cmd.ts` 描述了 RenderCmd 设计原则（平台无关、线性、绝对坐标、拍平不产生独立指令），
但**无公开的指令集规格表**。

### 为什么阻塞
多团队并行开发时指令是契约；无规格即无法协作、无法版本协商（Host ABI §6 依赖它）。

### 目标
产出完整指令集规格表并版本化。

### 执行
1. 产出规格表：opcode / 名称 / 参数 / 语义 / 各端实现要求
2. 指令集版本化（复用既有 `ir_version` 机制）
3. 变更走语义化版本，纳入 conformance

### 验收
- [ ] 完整 opcode 清单（Draw / Anim 两大类）
- [ ] 每条指令有参数定义与语义说明
- [ ] 版本号纳入 Host ABI 协商
- [ ] 变更走 major/minor 流程

## 卡 I2 · 舍入时机统一

| 项 | 内容 |
|---|---|
| **优先级** | P0 ★ 低成本高收益 |
| **依赖** | 无 |
| **估时** | 0.5 人周 |

### 现状
RenderCmd 用绝对坐标。鸿蒙**强制整数像素**
（`flex:1/3` 三列时 ArkUI 把 0.333 舍为 0.33，累计误差导致第三列错位）。

### 风险
各平台层各自舍入 → 三端策略不同 → **golden test 全绿但三端差 1px**。

### 目标
**硬性规则：内核产出指令时完成舍入，平台层不得再舍入。**

### 执行
1. 指令生成阶段统一舍入策略（明确定义，如 round-half-up）
2. **平台层移除所有舍入逻辑**
3. 加跨端像素一致性 conformance

### 验收
- [ ] 舍入仅发生在内核，平台层零舍入（**静态检查**）
- [ ] 三端同输入产出完全一致坐标（逐字节比对）
- [ ] 鸿蒙三列布局无错位

## 卡 I3 · paint-hint 编码进指令

| 项 | 内容 |
|---|---|
| **优先级** | P0 ★ 防内存问题复发 |
| **依赖** | I1（指令集规格） |
| **估时** | 1 人周 |

### 现状
内存专题定义 `isMonochrome` / `isPureBackground` / `shareableContent`，应**编译期推导**。
是否编码进指令待核实。

### 风险
若平台层运行时猜 → iOS 上曾出现的 **+78% 内存**会复发（backing store 按最贵格式分配）。

### 目标
paint-hint 成为指令属性，编译期推导，平台层据以决定 backing store 策略。

### 执行
1. paint-hint 作为指令属性编码
2. 编译期从归一化样式推导，**禁止运行时判断**
3. 平台层据 hint 决策

### 验收
- [ ] 指令携带 paint-hint 字段
- [ ] **编译期推导，运行时零判断**
- [ ] iOS 内存增量复测

## 卡 I4 · 文本在指令流中的表达定案

| 项 | 内容 |
|---|---|
| **优先级** | P0 |
| **依赖** | I1 |
| **估时** | 1–2 人周 |

### 现状
RenderCmd 设计已定，但文本如何表达未明确：
- 方案 A：绘制文本指令 + **内核已度量**几何（平台层只管画，最薄）
- 方案 B：文本节点 + 测量回调（平台层参与排版）

### 建议
**选方案 A**——这是唯一能把平台层压到最薄的选择。文本是唯一无法完全平台无关的一块。

### 执行
1. 内核持平台注入的 `text_measure`（Android StaticLayout / iOS CoreText）
2. 指令流携带**已度量完成的几何 + 文本内容**
3. 平台层只负责绘制

### 验收
- [ ] 方案已选定并写入规格
- [ ] 指令含文本度量结果
- [ ] 平台层不参与文本排版
- [ ] 文本跨端一致性纳入 conformance

3. **优先 Android**（既有实测全在此端）
4. 纳入 conformance

### 验收
- [ ] 有可运行的 Android 实现
- [ ] 4050 / 长列表 / 内存**三项复测达标**
- [ ] 纳入 RenderBackend conformance

# 全局执行指令

1. **V1 最先做**——已有成果固化，性价比最高、风险最低。
2. **I2（舍入）与 I3（paint-hint）是硬约束，不是优化项**：
   前者防跨端 1px 误差，后者防 iOS +78% 内存复发。
3. **I1 指令集规格必须先于任何后端实现**，否则多端无法对齐。
4. **不得破坏既有五后端行为**，所有新增须保持既有测试全绿。
5. **V4 安全判定从严不从宽**——误判为 L1 会导致静默的 UI 不更新。
6. **每项必须有可复现的验收脚本**，不接受"跑通了"作为验收。
7. **新增 opcode 与规则自带 AI 说明书**（与既有 69 条一致）。
8. 凡标注「待核实」的现状判断，**落地前先核实再动手**——
   尤其 **C1（G-28）与 C2（G-39/40）的实际进度**，若已部分完成须重排优先级。

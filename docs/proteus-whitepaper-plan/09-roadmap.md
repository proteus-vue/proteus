## 9.5 给决策者的建议

### 如果你是评估方

**重点看三件事**：
1. **方法论的完整性**——SPI-First 五步法 + 22 次泛化的证据链（第 2、3 章）
2. **验证体系的严谨性**——conformance + 负向测试 + 元教训（第 7 章）
3. **诚实边界的清晰度**——不承诺什么，比承诺什么更能说明专业性

### 如果你是潜在采用者

**从小处验证**：
1. 挑一个 SPI（比如 G-46 资源池）→ 看它的参考实现能否真跑
2. 跑 `verify.sh` → 看负向测试是否真的会失败（校验器有牙齿）
3. 检查 conformance 断言 → 看是否覆盖你关心的场景

### 如果你是贡献者

**套用模板**：
1. 找耦合点（Step ①）
2. 定义语义层，禁用技术名词（Step ②）
3. 至少两个后端（Step ③）
4. 写 conformance + 负向测试（Step ④）
5. 声明诚实边界（Step ⑤）

> **任何一份新 plan，都有现成的模板（8-10 份文档 + 参考实现 + verify.sh + 完整性断言）可以直接套。**

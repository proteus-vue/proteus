## 8.3 增量展开（01 未覆盖的对标增量）

### 认知层增量：够用主义 + roadmap 被需求填满

- **够用主义**：99% 用户需求是"跑微信小程序 + H5"，WebView 完全够用。投入 3 年重构核心服务 1% 高端需求，**ROI 为负**。
- **roadmap 被"加平台"填满**：框架团队被业务喂需求，**没人提"请把渲染后端抽象成 SPI"**（底层架构，业务方感知不到）。
- 无 conformance 文化的论证见 01 §1.5（接口靠约定 → 随时间漂移 → 想引擎可插拔时接口已写死成 WebView 形态）。

> 这两点增量直接引出下节的机制层结论：**"枚举式抽象"必然走向腐化**。

## 8.5 关键澄清：uni-app 到底用不用 Vue 自定义渲染？

**是，但只说对了一半。** uni-app 有**两条独立链路**：

| 链路 | 方向 | 机制 |
|------|------|------|
| **DOM 树 → 原生 UI** | Vue → 各端 | **Vue `createRenderer` + 自定义 nodeOps** |
| **Vue 组件 → 小程序** | Vue → 小程序 DSL | **`@vue/component-compiler` 编译转换**（非运行时渲染） |

**关键差别**：

- **uni-app**：`createRenderer` 是**实现细节**——用它接 Weex/原生，但**小程序端完全绕过它**（走编译）。两套机制各自为政。
- **Proteus**：`createRenderer`（nodeOps）被**提升为 Backend SPI 一等概念**，小程序/Canvas/Headless 都是这个 SPI 的实现——**统一抽象覆盖所有平台**。

> **一句话**：uni-app 是"**用 Vue 的能力去适配多端**"；
> Proteus 是"**把多端抽象成一个可插拔接口，Vue 只是其中一个使用者**"。

---

## 8.6 Proteus 的真实差异化

不是某个 G-XX 的技术，而是**最不起眼的那几份文档**：

- `proteus-philosophy.md`（架构哲学）
- `SPI-First-Methodology.md`（元方法论）
- `cheatsheet.md`（速查卡）
- 原则 #0 不绑定系列 + 铁律体系 + 编号治理

> **这些是"让正确架构能持续被做出来的元机制"。**
> **uni-app/Taro 有优秀的代码、庞大的生态，但没有把"如何持续做出正确架构"本身产品化**——
> 所以他们的架构会随时间腐化，而 Proteus 有 conformance + 铁律 + 方法论作为"防腐蚀层"。**

## 8.7 与小米方法论的对齐（叙事增强）

| 小米 | Proteus | 同构点 |
|------|---------|--------|
| **专注**（最小切口） | 原则 #0「不绑定」——每个 G-XX 只收敛**一个**语义维度 | 都是"做减法" |
| **极致**（死磕细节） | conformance 铁律（CMP001、G-27.1、PRIM001） | 把标准机械化 |
| **口碑**（超预期） | 降级不崩溃（原则 #4）+ 开发者只写一次 | 让用户闭眼信任 |
| **快**（洞察快但战略积累快不得） | B1-B6 分批 + DoD + verify.sh 秒级自验证 | 用机制换速度 |
| **5% 红线**（法律文件永久约束） | 铁律 G-27.1、G-45.9、诚实边界 | **用制度约束短期诱惑** |
| **参股不控股 + 技术赋能** | Backend 完全自主、只需过 conformance | 统一标准 + 释放自主性 |

### 三处差异（Proteus 更激进）

| 维度 | 小米 | **Proteus** |
|------|------|------------|
| 传承 | 人治 + 机制辅助（**依赖雷军个人 IP**） | **机制治**——判断力编码进系统（文档 + conformance + verify.sh） |
| 极致可测量性 | 主观（"超预期"） | **客观（PASS/FAIL 数字）** |
| 诚实边界 | 散落在演讲/复盘里 | **写成第一条铁律**（CMP046、G-45.9） |

> **一句话**：**小米方法论是人本主义的极致，SPI-First 是把人本主义"编译"成了机器可执行的版本。**

## 8.8 风险提示（避免过度对标）

**既然认同小米"定语式营销透支信任"的教训，这份对标本身就不能吹过头。**

必须明确区分：
- **哪些是真实同构**（五层方法论结构确实一致）
- **哪些只是类比**（Proteus 尚未经过市场验证，小米是已验证的商业成功）

> **诚实边界**：Proteus 目前是**架构设计与规划体系**（74 份 plan + 20 次泛化 + 机器可验证的参考实现），
> **尚未经过大规模生产验证**。本文档的所有对标，是"方法论结构"层面的同构论证，
> **不等于商业成功的等价宣称**。

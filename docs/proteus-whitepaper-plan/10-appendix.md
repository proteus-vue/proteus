## C. 术语表

| 术语 | 含义 |
|------|------|
| **SPI** | Service Provider Interface，可插拔后端接口 |
| **IR** | Intermediate Representation，语义中间层（与任何具体平台无关） |
| **Conformance** | 一致性测试——任何后端实现都必须通过的同一套测试 |
| **Backend** | SPI 的具体实现（如 VueDomBackend、SkiaBackend） |
| **泛化** | 把"被硬编码的实现"提升为"语义接口 + 可插拔后端"的一次动作 |
| **PSS** | 所有权静态分级（JS 无法全编译期检查时的折中策略） |
| **W×H×F** | 三维断点模型——宽 × 高 × 输入形态（touch/cursor/remote/dial/voice） |
| **等价类** | 设备分组，每组取代表设备（避免组合爆炸） |
| **漂移指纹** | 四维指纹（屏幕/系统/输入/环境），用于跨设备 FAIL 归因 |
| **ε 阈值** | 允许的偏差范围（渲染/触摸天然有浮动） |
| **降级不崩溃** | 能力缺失时优雅降级，而非抛出崩溃（原则 #4） |
| **诚实边界** | 明确声明方案"不解决什么" |

## D. 八大反模式（自检清单）

| ID | 反模式 | 症状 |
|----|--------|------|
| **AP-01** | 单后端 SPI | 声称可插拔，但只有一个实现 |
| **AP-02** | 接口含技术名词 | `SaveToS3` 而非 `StoreArtifact` |
| **AP-03** | 无 conformance | 接口靠文档约定，随时间漂移 |
| **AP-04** | 业务绕过接口 | 业务代码直接调具体实现 |
| **AP-05** | 类型 Only | 只定义 TypeScript 类型，无运行时契约 |
| **AP-06** | 过度设计 | 只有 1 个实现可能，却做了 SPI |
| **AP-07** | 后端爆炸 | 后端数量失控，无治理 |
| **AP-08** | 成本不透明 | 不承认抽象开销 |

**扩展反模式**（后续泛化补充；详细定义在各 G-XX 的 `rules.md`，本文为速查）：
- AP-09~12：沙箱相关（G-49 rules）
- AP-13~17：平台治理相关（G-50 rules）
- AP-18~21：验证执行相关（G-51 rules）
- AP-22~25：跨设备验证相关（G-52 rules）

## E. 验证层踩坑清单（可复用）

| 坑 | 修复 |
|----|------|
| grep 匹配到 `unzip -l` 表头 | `awk 'NR>3 && /\.zip$/'` |
| 残留文件跨目录污染 | 输出文件用绝对路径 + 运行前 `: >` 清空 |
| PASS 名称从不输出 → grep 匹配不到 | 统一 `OK: ` 前缀 |
| 硬编码"X/Y"计数 → 实际改动即失灵 | 动态 `grep -oE 'self-test: N/N'` |
| `MANIFEST` 无扩展名被过滤 → 计数少 1 | 改为逐文件断言 |
| 浮点用 `===` 比较 → 误报 | ε 比对 |
| zip 打成扁平包（无顶层目录） | 从父目录打包 |
| zip 自嵌套 | 打包前清理旧 zip |
| 测试间状态污染 | `freshEnv()` 隔离 |
| 断言与输出格式漂移 | 负向自检（注入故障看是否 FAIL） |

> **这张表的价值远超文档本身**——每个坑都是"只有真跑才会发现"的，
> 现在沉淀为可复用铁律。
>

# 关键路径分析（Critical Path）

> 配套：`01-master-roadmap.md` §5。本文件分析决定总工期的依赖链。

---

## 1. 结论

**理论最短工期 = 关键路径 = 18 个月。**

关键路径是唯一一条**无法被并行化缩短**的依赖链。任何其他优化（加人、加机器、砍需求）都只能缩短非关键路径上的浮动时间，无法触碰关键路径。

---

## 2. 关键路径识别

### 主关键路径（Main Critical Path）

```
[L0 规约定稿]
    ↓ (0.5 月)
[L1 G-27 渲染后端 SPI 设计]
    ↓ (1 月)
[L2 compiler IR 层]
    ↓ (1 月)
[G-27 B4 NativeBackend]
    ↓ (2 月)
[G-27 B5 FlutterBackend]  ★ 唯一技术不确定项
    ↓ (2 月)
[M2.1 混合渲染 demo 验证]
    ↓ (1 月)
[G-28 L2 官方 Backend 生态 ≥30]
    ↓ (5 月)
[M3.7 benchmark + 对标报告]
    ↓ (18 月)
[完成]
```

**累计 = 0.5 + 1 + 1 + 2 + 2 + 1 + 5 + 5 = ~18 月**

### 为什么是这条路径

- **G-27 B5 FlutterBackend** 是整条链上**技术难度最高**的节点（Flutter Embedder C ABI 稳定性）
- **G-28 生态 ≥30 个 Backend** 是**最长耗时**的节点（依赖社区 + 多平台 SDK 维护者）
- **M3.7 benchmark** 需要**真实业务数据积累**，无法压缩

---

## 3. 关键路径上的瓶颈节点

| 节点 | 风险 | 影响 | 缓解策略 |
|------|------|------|----------|
| **G-27 B5 FlutterBackend** | Flutter Embedder C ABI 稳定性不明 | 可能拖垮整条路径 | **最早启动 spike**；参考鸿蒙/三星 Tizen 先例 |
| **G-28 L2 生态 ≥30** | 社区贡献不确定性 | 99% 目标不达 | 官方主导 Top30 + 激励社区 |
| **M3.7 benchmark** | 需要真实业务数据 | 对外叙事延迟 | M1 起采集基线，持续对齐 |

**G-27 B5 是整条关键路径上唯一的技术不确定项**——它的成败直接决定 M2/M3 是否按期。

---

## 4. 浮动时间（Slack / Float）

### 4.1 自由浮动（Free Float）

| 路径 | 浮动 | 说明 |
|------|------|------|
| L3 能力（glass/safe-area/...） | **大**（可延后到 M3） | 非关键，可社区化 |
| L4 工具链（cli/testing/devtools） | **中** | 可延后，不影响核心验证 |
| L5 website | **大** | 完全可在 M3 做 |
| G-25 全终端（车机/TV/手表） | **小** | 影响"六端真机"叙事，建议按期 |
| **主关键路径** | **0** | 无浮动，任一延迟 = 总工期延迟 |

### 4.2 管理启示

- **资源优先投入关键路径**：G-27 B5 必须配最强人力
- **非关键路径可延迟/削减**：L3 能力若人手不足，可延后到 M3 或交给社区
- **用浮动换确定性**：关键路径上的节点不做"镀金"，只做 MVP

---

## 5. 加速策略（缩短关键路径）

理论上只有以下方式能缩短关键路径：

### 5.1 技术突破（最有效但最难）
- **G-27 B5 找到更简单的 Embedder 接入方式** → 节省 1–2 月
- **Flutter 官方提供更稳定的 Embedding API** → 外部依赖

### 5.2 范围裁剪（最可行）
- **M2 混合渲染 demo 只验证 iOS + Flutter**（暂不验证 Android/Harmony）→ 节省 1 月
- **G-28 生态先做到 20 个（覆盖 95%），99% 留到 M3.7** → 不影响主叙事

### 5.3 并行化（有限）
- 关键路径本身**无法并行**（链式依赖）
- 但可在**关键路径节点内部**并行：如 G-27 B5 的 iOS/Android/Harmony 三端可并行开发

### 5.4 外部依赖
- **与 Flutter 社区/官方建立协作** → 影响 G-27 B5 难度
- **各平台 SDK 维护者贡献 Backend** → 影响 G-28 生态速度

---

## 6. 次关键路径（Near-critical Paths）

以下路径浮动小，若延迟会成为新的关键路径：

### 6.1 全终端路径
```
G-25 车机/TV/手表 → 六端真机验证（M2.4）
```
- 浮动 ≈ 1 月
- 风险：TV 焦点引擎（UIFocusSystem）适配复杂

### 6.2 AI 闭环路径
```
G-23 AI Agent → Style Safety 约束 → 自修复验证（M2.6）
```
- 浮动 ≈ 2 月
- 风险：LLM 能力边界

### 6.3 性能达标路径
```
performance + memory 深度优化 → benchmark 达标（M3.3）
```
- 浮动 ≈ 1 月
- 风险：跨端性能一致性

**管理建议**：把这三条保持在**浮动范围内**，避免它们变成新的关键路径。

## 9. 一句话总结

> **18 个月是架构性下限，不是管理目标。** 唯一能缩短它的方式是 G-27 B5 的技术突破或范围裁剪——其他一切优化都只是让非关键路径更饱满。

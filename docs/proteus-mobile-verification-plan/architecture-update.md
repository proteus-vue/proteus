# 架构更新（G-53）

## 新增原则

- **#13.57** 设备供给可编排：同一测试在本地 / 池化 / 云端跑出可比对结果
- **#13.58** 覆盖率可度量：验证充分性必须是**可计算数字**，不是感觉
- **#13.59** 不可用即 SKIP：验证基础设施自身的缺失不表现为被测代码的失败

## 成熟度模型更新

```
L0 文档自检         ← G-50
L1 IR 模拟          ← G-51
L2 真运行时         ← G-51 + G-52 设备矩阵
L3 设备供给编排     ← ★ G-53（本份：本地/池化/云统一调度 + 覆盖率门槛）
L4 开放生态         ← G-50（依赖 G-49 L3）
L5 开发者门户       ← G-50
L6 治理与分佣       ← G-50
```

G-53 将「设备供给」推至 L3，与 L2 的"能跑真机"区分开：**L2 解决"能不能跑"，L3 解决"跑哪些、花多少钱、够不够"**。

## 三维验证空间（最终形态）

```
执行环境 (G-51)：文档 / 模拟 / 真机
设备形态 (G-52)：屏幕 / 系统 / 输入 / 环境
设备供给 (G-53)：本地 / 池化 / 云        ← 本份新增
```

三者正交，任一维度的后端可独立替换。

| **G-50** | 发布前门槛接入覆盖率 gate |

**无冲突**：G-53 全部为扩展，未重写任何既有 SPI。

## 第 15 次泛化

> **「不绑定设备供给方式」**

前 14 次泛化分别解耦了渲染后端、宿主形态、容器形态、测试方法、基座形态、资源容器、组合方式、小程序运行时、隔离层级、开发者平台、验证执行环境、跨设备形态。**第 15 次解耦"设备从哪来"**。

模式一致：定义语义 + 后端实现 + conformance + 降级链。

## 已知缺口

| 缺口 | 说明 |
|------|------|
| **"95% 断言不需真机"未实证** | 需统计 G-46~52 各 plan 的 L1/L2 用例分布，本份仅估算 |
| **共享 Mac 并发上限未实测** | 8 个模拟器同时跑的资源压力需压测 |
| **云真机 Provider 未实现** | 本份只给契约，各平台适配待实施 |
| **serve-sim 非官方维护** | Apple Xcode 27 Device Hub 成熟后应优先切换 |
| **出海份额清单缺失** | 本份基于中国市场，其他地区需另建 |
| **Apple EULA 边界** | 对外提供云模拟器服务需法务确认（§05） |

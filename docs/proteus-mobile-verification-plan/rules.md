# G-53 铁律

## G-53.1 — 平台不可用必须返回 SKIP

未装 Xcode、缺 endpoint、额度耗尽 —— 一律 `SKIP` + reason。

**严禁**：抛异常、返回 FAIL、静默通过。

> 理由：验证基础设施自身不可用，不应表现为"被测代码有问题"。这是 G-46 RSC-01「缺失即降级，永不崩溃」在验证层的贯彻。

## G-53.2 — 能力缺失必须返回 DEGRADED 并列出缺失项

档位能力不满足 suite 需求时，返回 `DEGRADED` + `missing[]`。

**严禁**：静默按 PASS 处理（"跑过了 = 通过了"是致命错觉）。

## G-53.3 — 覆盖率不得虚报

- 加权份额**取上限 1**（防重叠类相加 >100%）
- SKIP **不计入** PASS 分子
- 空输入返回 `pass: false`

**严禁**：任何会让"没测 = 通过"的计算方式。

## G-53.4 — 报告必须携带 skipped 列表

覆盖率数字之外，必须列出**哪些设备没测、为什么**。

**严禁**：只报一个覆盖率数字（黑盒指标无法指导补测）。

## G-53.5 — 编排器自动选档，禁止人工硬编码档位

suite 声明**能力需求**（needsRender/needsEngine/needsHardware/needsRealRom），编排器据此选档。

**严禁**：在测试代码里写死 `tier = 'cloud-device'`——那会让零成本断言白白花钱上云。

## G-53.6 — 云真机额度耗尽不得阻断 CI

`QUOTA_EXCEEDED` → 降级或 SKIP + 标注覆盖率下降。

**严禁**：让 CI 因外部计费问题随机变红。

## G-53.7 — 模拟器档不得宣称硬件能力

`TIER_CAPABILITY` 中模拟器档的 `hardware` / `realRom` **恒为 false**。

**严禁**：为了"看起来覆盖更全"而把模拟器标成能测硬件。

## G-53.8 — 份额数据是运营数据，不得写死进代码

市场份额按季度变化，必须作为**可配置的 profile 数据源**。

**严禁**：把 `share: 0.20` 这类数字硬编码进架构常量。

## 反模式

- **AP-26** 穷举机型 —— 应等价类 + 代表采样（G-53 §等价类）
- **AP-27** 额度耗尽 → FAIL —— 应 SKIP + 覆盖率标注
- **AP-28** 覆盖率只报数字不列 skipped —— 黑盒指标
- **AP-29** 测试代码硬编码档位 —— 违反 G-53.5
- **AP-30** 把模拟器当真机宣称 —— 违反 G-53.7
